# Multi-Scale Erosion

作成日時: 2026-09-09 02:49
更新日時: 2026-09-09 03:53

## 出典と実装範囲

Schott ほか、[Terrain Amplification using Multi-scale Erosion](https://h-schott.github.io/p/mserosion/)
（ACM TOG / SIGGRAPH 2024、DOI: 10.1145/3658200）の Sections 3–5 を基準に実装する。
本文は [著者が公開した版](https://www.researchgate.net/publication/382403597_Terrain_Amplification_using_Multi_Scale_Erosion)で確認した。
terrain-editor の侵食実装、著者の公開コードは使わない。

対象は多段解像度の侵食本体と Section 5 の高さ復元・多段 breaching。
硬さの空間分布、安息角のノイズ、手動で指定した復元点は未実装。

## 処理と論文との対応

- 入力を開始解像度へ面積平均し、段階ごとに河川侵食 → 斜面安定化 → 堆積を実行する。
  次の段階へは bicubic 補間で倍に拡大する。最後は指定した最終解像度。
- 流出先への重みは Eq. (1)、集水面積は Eq. (2) の反復近似。高さは m、面積は m²。
  流出重みの分母を別パスに分けるが、数式は変えない。
- 河川侵食は Eq. (5) の傾斜・集水面積の上限を使用する。係数は、指定した最大侵食深さを
  反復回数と最大 stream power で割って導く。細かい段階の深さは「細部の強さ」を掛ける。
- 斜面安定化は Section 4.3 の隣接セル数に基づく固定量の移動。振動を抑えるため、
  1 回の移動量をセル幅の 1% 以下に制限する。
- 堆積は Section 4.4 の生成・輸送・堆積を分離した更新。流入は上流から下流への重みで集める。
  土砂の生成と侵食による除去量は連動させず、質量保存モデルとはしない。
  アプリでは土砂の内部量を地形の m に直す「堆積の高さ」を追加した（既定 0.001）。
  これは論文のパラメータではなく、実寸地形で堆積厚を調整するための換算。
  浮遊土砂の収支から差し引く量は換算前、地形へ足す量だけ換算後とする。

論文の代表値から流れの集中 1.3、傾斜指数 2、集水指数 0.8、傾斜上限 1、
土砂供給 0.1、堆積率 0.1 を採用する。面積上限は実寸に合わせて 4096 m² とする。
開始 / 最終解像度、反復数、
深さ、一定の安息角、移動量はアプリ用の既定値であり、論文の図の再現用プリセットではない。

## ノードと GPU

保存名は `multiScaleErosion`。Base / Mask 入力、Result 出力。
Mask は最終結果を元の高さへ混ぜる適用範囲で、論文の硬さマップではない。
白で適用、黒で元の高さを保つ。Base が無い場合は他の加工ノードと同じ中立平面。

列内の Multi-Scale Erosion が使う最大解像度の RGBA32_FLOAT テクスチャを 2 枚持ち、
各ノードは左上の領域を使う。異なる解像度のノードが続いても、同じコマンドリスト内で
作業テクスチャを解放・再作成しない。
各パスで読み元と書き先を交換し、UAV バリアで順序を保証する。
流量と土砂を含む反復は専用コンピュートキュー上で行い、CPU へ読み戻さない。
最終出力は合成解像度へ補間して高さを置き換え、法線を作り直す。

開始解像度より細かな入力の凹凸は再構成される。素材の細かな凹凸を保ちたいときは、
このノードの後に Surface を接続する。侵食・斜面・堆積をすべて無効にしたときは、
排水路補正も無効なら、再サンプリングも行わず入力をそのまま通す。

## 高さ復元と排水路補正

侵食 → 高さ復元 → 多段 breaching → Mask で適用 → 法線再生成の順。

- **高さ復元（Section 5.1）**: 最終地形で流出重みと集水面積を再計算し、集水面積が
  閾値未満の尾根・山頂を制約点にする。面積はセル数で指定する（既定 2）。
  制約点で「入力の高さ − 侵食後の高さ」を固定し、8 近傍の平均で誤差を拡散する。
  既定 500 回。高さ自体をぼかさないため侵食の細部が残る。
  最後に復元強度（既定 1、0 で無効）を掛けて加える。入力高さは同じ位置で線形補間する。
  集水は高さを固定した 32 回の反復近似で、全域の流量の完全収束は求めない。
- **排水路補正（Section 5.2）**: 外周を出口として priority flood で経路木を作り、
  逆順の走査で窪地から外周まで掘る。これは論文中の基本演算 B を担う独立実装で、
  Barnes らの公開実装の移植ではない。経路の同値判定はセル番号で固定する。
  各段で B を再計算し、掘削差分だけを有限支持の分離箱カーネルでならして差し引く。
  半径は既定 16 セルから半分ずつ下げ、最後の 1 セルでは B をそのまま適用する。
  盛り土をせず、水平な流路を許す非増加経路で全セルが外周へつながる。
  厳密に正の勾配を要求する別の水理ソルバでは、水平部の流向解決が別途必要。
- 排水の性質を検証する対象は最終解析グリッド。合成解像度への再サンプリング、
  Mask での部分適用、後続ノードの加工後まで排水を保証するものではない。
  意図的な湖を残す場合は「排水路補正」を無効にする。
- 新しい 5 設定はプロジェクトに保存する。キーがない既存プロジェクトでは
  高さ復元 1・閾値 2・反復 500・排水路補正有効・半径 16 を使用する。

高さ復元は GPU、排水路探索は CPU。GPU の結果を readback buffer へ記録し、
フレーム / compute のフェンス完了後、次の評価で回収する。CPU 処理中は短い待ちが入る。
結果はスタックの改版とノード位置ごとに再利用し、変更時・リサイズ時は破棄する。
GPU が参照するバッファは遅延解放する。非同期評価は後処理と後続ノードが終わるまで
前回の完成結果を表示し、書き出しと Path の経路探索も同じ完了条件を待つ。

## 検証

- Debug / Release ビルド、CTest、DXC の 12 エントリ（cs_6_6）が成功。
- 実ハイトマップを読み込み、UI 込みのスクリーンショットを確認。
  最終 Debug 実行では D3D12 / GPU ベースバリデーションの警告・エラーなし。
- 2048²、単一段階、河川侵食のみ・最大深さ 12 m の書き出しで、
  最大削り量は約 4.599 m（12 m 以下）。高さの増加は float 丸めの約 0.000036 m 以下。
- 全処理無効と黒い Mask は、侵食前の EXR とビット単位で一致。
- 平面は一様な高さを維持し、書き出したハイトに NaN / Inf は無い。
- 全 22 パラメータが保存され、再読み込み後の EXR は保存前とビット単位で一致。
- CPU 回帰テスト: 閉じた盆地、複数の窪地、奇数の半径で外周への非増加経路を確認。
  掘削のみ、有限値、補正済み地形・平面・排水済み斜面の不変性、不正入力の拒否を確認。
- `mse-default.tgproj` の両処理無効の EXR は、追加前の結果とビット単位で一致。
  高さ復元のみ / 排水路のみ / 両方を比較し、排水路による高さの増加は 0。
- 2048² で識別した明確な局所山頂 283 点は、復元後の入力との高さ誤差が
  最大 0.000036 m 以下。多段侵食ノード 2 個の直列接続も最後まで書き出せた。
- 確認用プロジェクト、画像、ログ、EXR は `data/mse-*` に置く。

## 山脈で谷筋が出なかった問題の修正

旧既定値では、一辺 2048 m・開始 64² の 1 セルが 1024 m² なのに、集水上限は
250 m² だった。降水だけで上限へ達するため、粗い段階の侵食が集水量で変わらず、
尾根と谷の差が失われていた。また 64² への縮小で入力の細部を失う一方、
最大深さ 12 m・細部倍率 0.5 では細かな谷を再形成する効果が弱かった。

新しい既定値は開始 128²・最終 1024²、集水上限 4096 m²、最大深さ 80 m、
細部倍率 0.7、侵食 1200 回、斜面 100 回、堆積 100 回。
`data/mse-default.tgproj` と同じ入力・視点で旧設定と比較し、支流状の谷筋が増えることを確認した。
元の確認用プロジェクトは `data/mse-default-before-fix.tgproj` に保存した。

集水上限は絶対面積なので、地形サイズを大きくしたときはセル面積に合わせて調整する。
これは論文の式を変更した修正ではなく、実寸に合わなかった既定値の修正である。
