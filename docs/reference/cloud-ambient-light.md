# cloud-ambient-light — 雲と環境光の関係（課題と方針）

作成日時: 2026-09-19 11:23
更新日時: 2026-09-19 11:32

雲が環境光（IBL）をどう遮るかについての、現状の課題・採った方針・残っている課題をまとめる。
**今後も改善を続ける前提の覚え書き**で、実装が進んだら「現在の実装」と「残っている課題」を更新する。

## 課題

大気モードの環境マップは、**世界の原点（高さ 0）から 1 回だけ**作っている
（`shaders/AtmosphereEnvironment.hlsl` が `IntegrateCloud(float3(0,0,0), ...)` で全方位の空と雲を積分する）。
できた 1 組の irradiance / prefiltered キューブを、地形（`MeshPbr.hlsl`）、配置モデル（`ModelPreview.hlsl`）、
雪煙（`SnowPlume.hlsl`）の**すべての画素に同じように掛ける**。位置による違いは一切無い。

このため、原点が雲の下にあると次のことが起きる。

- 雲海の上に突き出た山頂も、雲の下の暗く灰色の環境光で照らされる。青空の回り込みが無くなる。
- 逆に、原点の真上だけ雲が切れていると、雲の下の谷まで晴天の環境光で明るくなる。
- 直接光は `CloudShadow` が地点ごとに雲を見ているので、直接光と環境光で雲の効き方が食い違う。

本来ほしいのは「**その地点から見上げた半球が、どれだけ雲に覆われているか**」で決まる環境光。

## 検討した方法

| 方法 | 内容 | 判断 |
|---|---|---|
| a. 地点ごとに半球を積分 | 直接光の `CloudShadow` と同じ作法で、画素ごとに空へ向けて雲を積分する | 画素ごとの半球積分は重すぎる。不採用 |
| b. 高さ別の環境マップを複数 | 高さを変えて環境マップ一式を何組も作り、高さで引き分ける | 環境の生成（キューブ化・irradiance・prefilter）が雲の編集のたびに何倍にもなる。不採用 |
| c. 雲なし / 雲ありの 2 つを高さで混ぜる | 雲を抜いた空の環境をもう 1 つ持ち、地点の高さで補間する | **採用** |

c を選んだ理由。

- 雲を掛ける前の空は、同じコンピュートがすでに `m_skyView` に書いている。雲なしの環境は安く作れる。
- 雲なしの環境は雲の編集では変わらない。作り直すのは空（太陽・大気の濃さなど）が変わったときだけで済む。
- シェーダ側は irradiance を 2 回引いて補間するだけ。
- 雲海の上の山頂、という一番目立つ破綻が直る。

## 方針（c の中身）

- **雲ありの環境**: これまでどおり（原点から撮る）。
- **雲なしの環境**: `clouds = 0` にした同じ設定から作る。まず **irradiance（拡散）だけ**を作る。
  雪や岩は粗いので、鏡面（prefiltered）は雲ありの 1 つのままにして様子を見る。
- **混ぜる重み**: 地点の高さが雲底より下なら雲あり、雲頂より上なら雲なし、雲の中は滑らかに補間する。
  雲層の高さは、天候層（`localCloud == 4`）なら `weatherBottom` / `weatherThickness`、それ以外は
  `cloudBottom` / `cloudThickness` を使う。
- **調整のパラメータ**（大気の設定に置く）:
  - 遮蔽の強さ（0 で常に雲なしの環境、1 で上の規則どおり）
  - 遷移の幅（雲層の厚さに対する倍率）
  - 高さのオフセット（m。切り替わる高さを上下にずらす）
- 雲が無効のときは重みを 0 にし、これまでどおり 1 つの環境だけを使う（2 つは同じ絵になるので引く意味が無い）。

## 現在の実装

2026-09-19 に方針 c の第 1 段階（拡散だけ）を入れた。

- **雲なしの環境**: `Atmosphere` が `m_clearEnvironment` を持つ。`clouds = 0` にした同じ設定で
  `Environment::BuildFromAtmosphere(..., irradianceOnly = true)` を呼び、キューブと irradiance だけを作る
  （プリフィルタは作らない）。作り直すのは空が変わったとき（`Atmosphere::Update` の `skyChanged`）と、
  雲が初めて有効になったときだけ。雲の編集やアニメーションでは作り直さない。
- **混ぜる値**: `Atmosphere::CurrentAmbientBlend()` が、雲なしの irradiance の SRV と、重みが 0→1 に変わる
  高さの範囲（`low` / `high`）、遮蔽の強さを返す。雲が無効・大気モードでない・雲なしの環境が未生成なら
  SRV が無効値になり、シェーダはこれまでどおり 1 つの環境だけを引く。
- **シェーダ**: `AtmosphereCommon.hlsli` の `SampleAmbientIrradiance()`。重みは
  `lerp(1, smoothstep(low, high, 高さ), 遮蔽の強さ)`。地形（`MeshPbr.hlsl`）、配置モデル
  （`ModelPreview.hlsl` のシーン描画）、雪煙（`SnowPlume.hlsl`）が同じ関数を使う。
- **パラメータ**: `CloudAmbientSettings`（`Atmosphere.h`）。`AtmosphereSettings` に入れていないのは、値を
  動かすたびに環境マップの作り直しが走るのを避けるため。UI は「プレビュー設定 > 雲と環境光」、保存は
  大気の設定の `cloudAmbientOcclusion` / `cloudAmbientTransition` / `cloudAmbientHeightOffset`。

| パラメータ | 既定値 | 説明 |
|---|---|---|
| 遮蔽の強さ | 1.00 | 0 で高さに関わらず雲なしの環境、1 で雲底より下は雲ありの環境 |
| 遷移の幅 | 1.00 | 入れ替わる高さの幅。雲層の厚さに対する倍率（1 で雲底〜雲頂） |
| 高さのオフセット | 0 m | 入れ替わる高さを上下にずらす |

確認: `data/Scenes/everest`（雲海から峰が突き出たシーン）で、雲ありの環境だけの絵と撮り比べた
（`data/Test/snow-plume-qa/vp-20-ambient-compare.png`。上が変更前、下が変更後）。雲海より上の山が
雲の下の灰色がかった明るい環境光ではなく、青空の環境光で照らされ、日陰側が青く締まる。
**曇天の下の環境光は、晴天の青空より明るいことがある**ので、変更後は日陰が暗く見える。下の課題 1
（雲海からの照り返し）が無いぶん、暗さが目立つ。

## 残っている課題

今回の方針では直らない、または後回しにしたもの。優先度の高い順。

1. **雲頂より上での、雲海からの照り返しが無い。** 雲なしの環境の下半球は地面の色のまま。厳密には
   明るい白になる。第 1 段階を入れたら、雲海の上の日陰が暗く見えるようになり、これが一番目立つ。
   `cloudLighting`（雲の平均輝度）を下半球に足せば近似できる。
2. **水平方向の違いを見ていない。** 雲の切れ間の下が明るい、厚い雲の下が暗い、という差が出ない。
   直接光の雲影が使っている光学的深さのキャッシュ（`m_opticalDepth`）を真上方向に引いて重みに掛ければ、
   安く近似できる見込み。
3. **鏡面（prefiltered）は雲ありの 1 つのまま。** 濡れた面や氷の映り込みは、雲の上でも雲の下の空を映す。
   拡散の結果を見てから、鏡面も 2 つにするか決める。
4. **雲ありの環境を撮る位置が高さ 0 で固定。** 雲底が高さ 0 より下にあるシーン（標高の高い地形）では、
   「雲あり」のつもりの環境が雲の中や上から撮られる。雲底のすぐ下から撮るようにしたい。
5. **天候層の球殻の曲がり（`weatherCurvature`）を見ていない。** 重みは平らな層として高さだけで決める。
   地形の範囲では差は小さいはず。
6. **単独の雲（楕円体・プリミティブ）では、高さだけの規則が合わない。** 原点の上に 1 つだけ雲があると、
   雲ありの環境はその雲に大きく覆われ、雲底より低い地形全体が暗くなる。2 の水平方向の対応が入れば
   ここも改善する。
7. **雲の向こう側の雪煙**は別件（Snow Plume が合成の残した雲の透過率を読む）。[nodes.md](nodes.md) の Snow Plume を参照。
