## なぜ Mask Fluvial では足りないか

**「川筋を重力方向へ流す」ところは、すでに Mask Fluvial に入っている。**
窪みを埋めてから MFD（下り勾配のある 8 近傍へ `勾配^集中度` で配分）で
流量を累積しているので、あれは「重力方向にどこまでも流した結果」そのもの。
だから流す処理を足しても絵は変わらない。

河川に足りないのは次の 3 つ。

| 足りないもの | なぜ要るか |
| --- | --- |
| **水面の高さ** | 川は「下流へ単調に下がる面」。Liquid は水位が定数なので使えない |
| **河床を掘る** | 素の地形に水路は無い。掘らないと水面が斜面に貼り付いた帯にしかならない |
| **幅** | 流量から決まる（`幅 ≒ k・√Q`）。マスクの明るさは幅ではない |

このうち**本体は水面の高さ**。ここが河川と「濡れた筋」を分ける。
いまの `data/sample.tgproj` の `River` サーフェスは後者（Mask Fluvial を
そのままマテリアルのマスクにしたもの）で、水面が無いので斜面を水が
這い上がって見える。

もう 1 つ、Mask Fluvial の**窪み埋めは固定 8 回**（`CsPitFill`）なので、
8 セルより大きい盆地は埋まりきらない。盆地に入った流量はそこで消え、
出口から下流の川はほぼ 0 から再出発する。川筋マスクなら「盆地で途切れる」で
済むが、River では湖の下流で川が消えることになるので、ここも直す必要がある。

## 考え方

**River = Liquid の水位を、川筋に沿って下流へ単調に下がる面にしたもの。**

見えるのは常に一番上の面だけなので、1 枚のハイトフィールドでは
「河床を掘って水を張る」は**「見える Height を水面高へ置き換える」**に潰れる。
Liquid がまさにその考え方で、`水位 − 下地の高さ` がそのまま深さになる
（[compositing.md の「リキッド」](../design/compositing.md)）。

掘る処理が要るのは、水面そのものではなく**岸の形と水深**のため。
掘らないと深さが 0 になり、水の色も岸の落ち込みも出ない。

### 水面の単調化 = 窪み埋め

「水面を下流へ単調に下げる」を式にすると
`surface = max(地形高, min(近傍の surface) + 最小勾配 × 距離)` を
端（出口）から内側へ伝播させる反復で、これは **Planchon–Darboux 法の
窪み埋めそのもの**。つまり Mask Fluvial の窪み埋めを O(解像度) 回まわして
勾配 ε を付けたものが、そのまま川の水面高になる。

- 埋めた面は流向計算にも水面高にも使える。**1 回の反復で両方が出る。**
- 盆地は最小勾配で出口の高さまで埋まるので、**湖が自然にできる**。
  Lake ノードを別に作らなくてよい。**この副作用が一番おいしい。**
- 盆地の出口から下流へも流量が続くので、湖の下流で川が消えない。
- 湖面（ε 勾配の平坦面）では MFD の流れが扇状に広がる。分岐した流れは出るが、
  三角州の形になるのは堆積が伴う場合なので、そこまでは期待しない。

## ピン

Sediment / Snow と同じ「加工」ノード（`IsHeightOperationKind`）。
下地になれず、Base に何も繋がっていなければ素通りする。

```
River   Base ──┐                      ┌── Result  地形（河床を掘って水を張った状態）
        Seed ──┤    解析グリッド 512   ├── Water   水面の被覆
               │                      ├── Bank    河原（岩・砂利を置く帯）
               └──────────────────────┴── Depth   水深
```

| ピン | 型 | 内容 |
| --- | --- | --- |
| `Base` | Material（入力） | 下地。ここまで合成した Height から川筋を作る |
| `Seed` | Mask（入力、省略可） | 川の出どころを絞る。繋がなければ全面から |
| `Result` | Material（出力） | 河床を掘り、水を張った地形 |
| `Water` | Mask（出力） | 水面の被覆。水のマテリアルを貼る |
| `Bank` | Mask（出力） | **河原。岩・砂利を置く帯**（下の節） |
| `Depth` | Mask（出力） | 水深（0〜1）。水の色の濃さ、濁りに使う |

Sediment / Crumbling / Snow と同じく **`Result` を繋がず、マスクだけ使ってもよい**
（`maskOnly` の自動差し込みに乗る）。地形を変えずに川筋の分布だけ取れる。

## パラメータ

単位は**すべて実寸（m）**。Heightmap ノードの `標高差` が基準になる。
既定の平面（一辺 1024 m）を 512 グリッドで切ると **1 セル 2 m**。
下の既定値はこの前提で決めてある。

### 川筋

| 名前 | 既定 | 意味 |
| --- | --- | --- |
| 川のしきい値 | 0.002 | 川とみなす流量。**全セル数に対する割合**（Mask Fluvial と同じ単位） |
| 最大ディテール | 8.0 m | 流向を読む前にならす大きさ |
| 集中度 | 4.00 | 下流への配分の集中度。大きいほど主流へ集まる |
| 解像度 | 512 | 川筋を計算するグリッド。**合成解像度とは別** |

### 掘る

| 名前 | 既定 | 意味 |
| --- | --- | --- |
| 主流の幅 | 60.0 m | **流量が最大のセル**での幅。幅の基準はここ |
| 最小幅 | 3.0 m | しきい値ぎりぎりの細い沢でも、これより細くしない |
| 幅の伸び | 0.50 | 流量に対する幅の指数。**0.5 が水理幾何の標準**、0 で一定幅 |
| 河床の深さ | 3.0 m | 水面から河床まで |
| 岸の幅 | 8.0 m | 水際から岸の上端までの距離（**掘る形**の話） |
| 岸の硬さ | 0.35 | 0 でなだらかな土手、1 で切り立った崖 |

```
幅 = max(最小幅, 主流の幅 × (Q / Qmax)^幅の伸び)
```

**幅の基準は主流側に置く。** 初版は「しきい値の流量での幅 × (Q/Qしきい値)^指数」を
`最大幅` で止める形だったが、しきい値 0.0005 は約 131 セルの集水面積で、
主流はその数百倍を持つ。指数 0.5 なら 100 倍で 10 倍幅になるので、
**支流の大半まで上限に張り付いて**幅の差が消える。
`Qmax` を基準にすれば「主流はこの幅、源流はこの幅」を直接指定でき、
しきい値を動かしても幅が暴れない。`Qmax` は Mask Fluvial と同じ
`InterlockedMax`（`CsMaxReduce`）で集める。

### 水面

| 名前 | 既定 | 意味 |
| --- | --- | --- |
| 水を張る | 入 | 切ると乾いた河床のまま残る（涸れ川・旧河道） |
| 最小勾配 | 0.0002 | 水面が下流へ下がる最小の傾き。大きくすると平坦な谷底が上流側から浸かる |

**最小勾配 0 は流向計算には使えない。** 平坦面では MFD の重みが全部 0 になり、
流量がそこで止まる。ユーザー値が 0 でも、窪み埋めには小さな ε
（Mask Fluvial の `kPitEpsilon` 相当）を別に入れる。水面高としては ε の
分だけ傾くが、1 セル当たり 1e-5 なので見えない。

### 河原（Bank マスク）

| 名前 | 既定 | 意味 |
| --- | --- | --- |
| 河原の広がり | 15.0 m | 水際から外側へ、河原とみなす距離。**`幅の伸び` で一緒に伸びる** |
| 河原の比高 | 2.0 m | 水面からこの高さまでを河原とする（増水時に浸かる帯） |
| 河原のぼかし | 0.30 | 縁のなだらかさ |

**`岸の幅` と `河原の広がり` は別物。** 前者は地形をどう掘るか、後者は
マスクをどこまで出すか。掘った岸より外側まで河原を伸ばしたいことがあるので、
同じ値にはしない。

## パイプライン

既存の資産をかなり流用できる。窪み埋めだけは作り直す。

1. **解析グリッドへ落とす + ローパス** — `CsSampleHeight` / `CsBlurH` / `CsBlurV` をそのまま。
2. **窪み埋め = 水面高（Planchon–Darboux）** ← **新規。**
   `surface` を端は地形高、内側は +∞ で初期化し、
   `surface = max(地形高, min(近傍 surface + 最小勾配 × 距離))` をヤコビ反復。
   情報は 1 反復に 1 セル進むので、累積と同じく **2 × 解像度 回**。
   端のセルは出口として動かさない（`CsPitFill` と同じ）。
   出力 `surface` は**どこでも地形高以上**で、盆地の中だけ地形より高い（= 湖）。
3. **MFD 重み + 流量累積** — `surface` の上で `CsWeights` / `CsAccumInit` /
   `CsAccumIter` をそのまま。**`Seed` は雨の量。** `CsAccumIter` は毎反復で
   雨の 1 を足し直しているので、初期化だけでなく**反復中の定数にも**掛けること。
4. **川を抜き、幅を決める** — `CsMaxReduce` で `Qmax` を取り、
   `Q ≥ しきい値` のセルを中心線とし、上の式でセルごとの幅を出す。
5. **中心線からの距離場 — Jump Flooding**（512 なら 9 パス）。
   ヤコビで距離を広げると O(解像度) 掛かるので、ここは JFA を使うこと。
   - **伝播する値は距離ではなく `幅(種)/2 − 距離` の最大。** 単純な最近傍だと、
     太い本流と細い支流の合流点で支流のセルが最近傍になり、本流の縁が欠ける。
     JFA は非ユークリッド計量では近似になるが、この用途には足りる。
   - **種の座標を運ぶ。** 各セルは「自分を覆う中心線セル」の座標を持つので、
     そこから**その中心線セルの `surface`** を引ける。川の断面を水平にするには
     ローカルの `surface` ではなく**中心線の `surface`** を水面高にすること。
     ローカル値を使うと岸側が高くなる。
   - 水際からの距離 `dw = 距離 − 幅(種)/2`（内側は負）も一緒に出す。
6. **水面の判定** — 水になるのは次の**論理和**。
   - 川: `dw < 0`。水面高は中心線の `surface`。
   - 湖: `surface − 地形高 > ε`。水面高はローカルの `surface`（湖面は平坦なので
     川の判定と矛盾しない）。
   **距離場だけでは湖は出ない**（湖は幅より広い）。初版はここが抜けていた。
7. **河床を掘る** — **中心線の周りだけ。** `河床 = 水面高 − 河床の深さ` へ下げ、
   `岸の幅` / `岸の硬さ` で外側の地形へ繋ぐ。**湖底は掘らない**
   （湖の深さは `surface − 地形高` そのもの）。
8. **合成解像度へ書き戻し + `RebuildNormalsFromHeight()`。** 川の中と外で扱いが違う。
   - 水の外（掘った岸を含む）: 堆積と同じく**差分で足し戻す**（`CsApply` の
     `delta + buried` の形。掘った所は `delta < 0` なので細部はそのまま残る）。
   - 水の中: 水面高で**置き換える**。細部は残さない（水面は平ら）。
   - `水を張る` が切のときは、水の中も河床の差分で足し戻す。
9. **マスクを焼く** — `Water` / `Bank` / `Depth`。**解析グリッドの R32 の値から計算する**
   （次の項）。

### 書き戻し先は R16

合成 Height は `kHeightFormat = R16_FLOAT` で、標高差 604 m のとき中腹の量子化は
約 0.3 m。最小勾配 0.001 の水面は 1 セル（2 m）で 0.002 m しか下がらないので、
書き戻した Height では**約 300 m ごとの階段**になる。

- 湖は水平なので影響なし。
- **川の水面は、法線を Height から作り直すと段ごとに縞が出る**（実装して確認した。
  はっきり見える）。水面の法線は R32 の水面高の勾配から作り直し、水の被覆で
  混ぜる（`CsWaterNormal`）。Height 自体の階段は残るので、ごく低い角度から
  見ると段が見えることがある。
- **`Depth` と `Bank` の比高は R16 の結果からではなく、R32 の `surface` と
  解析グリッドの地形高から出す。** R16 から差を取ると 0.3 m 単位で飛ぶ。

## 河原（Bank）マスクの作り方

**距離場と水面高が 5 と 2 で既に出ているので、ほぼタダで作れる。**

水際からの距離 `dw`（水面の内側は負）と、水面からの比高
`h = 地形高 − 水面高` の 2 つを掛け合わせる。どちらも解析グリッドの R32 の値。

```
距離の帯 = smoothstep(0, ぼかし, dw)
         × (1 - smoothstep(河原の広がり - ぼかし, 河原の広がり, dw))
比高の帯 = 1 - smoothstep(河原の比高, 河原の比高 + ぼかし, h)

Bank = 距離の帯 × 比高の帯
```

- **比高で切るのが効く。** 距離だけだと、川が谷底を流れているときに
  谷壁を駆け上がってしまう。「増水時に浸かる高さまで」が河原の定義に近い。
- **河原の広がりは流量で伸びる**（`幅の伸び` を共有）。
  源流の細い沢に 15m の河原ができるのはおかしい。
- 湖の岸にも同じ式で河原が出る（湖のセルは `dw` を「湖面の縁からの距離」で
  持たせる。JFA の種に湖の縁も加えれば済む）。

### 水中の礫

`Depth` を Mask Levels で反転すれば「浅瀬」のマスクになる。
瀬の石を置くならこちら。ノードを増やす必要はない。

## 既存ノードとの繋ぎ方

```
Heightmap → River ─ Result ─→ Surface(水) ─→ Surface(砂利) ─→ Output
              ├─ Water ────────┘                  │
              ├─ Bank ─────────────────────────────┘
              └─ Bank ──→ Crumbling(Emission) → 河原に本物の岩を積む
```

- **水の Surface には Height / Normal を書かせない**（チャンネルを BaseColor /
  Surface だけにする）。River 自体は加工ノードなのでハイトブレンドを通らないが、
  その先の Surface（水）は普通のレイヤーとしてブレンドを通る。Height を書かせると
  Surface 自身のハイト（定数でも 0.5 の平面）で水面が置き換わり、Normal を
  書かせると素材の法線が乗る。水面の形と法線は River だけが決める。
- **`Bank` → `Crumbling` の Emission が本命。** マスクで砂利の色を塗るだけでなく、
  Crumbling が**岩片の形そのもの**を河原へ積んでくれる。`Unique` 出力で
  岩 1 個ずつ色を変えられるのもそのまま効く。
  `最小サイズ` / `最大サイズ` を 0.3〜1.5m くらいに落とすと河原の石になる。
- **急な岸だけに転石を置く**なら `Bank × Mask Slope`（Mask Blend の乗算）。
- **水の質感**は [compositing.md](../design/compositing.md) の推奨値
  （ベースカラー `(0.01, 0.03, 0.035)`、ラフネス 0.05〜0.1、メタリック 0）。
  `Depth` を濁りに掛けると浅瀬が明るくなる。

## 実装メモ

既存の加工ノードに揃えるときに落としやすい所。

- **`HashHeightState` に River のパラメータを混ぜる。** マスク op のキャッシュは
  `layer.sediment` / `crumbling` / `snow` をハッシュに入れて「その時点までの
  Height」を識別している。River を足さないと、River を動かしても
  `Water` / `Bank` / `Depth` が焼き直されない。
- **出力 3 本は 1 つの `MaskOpKind::River` を `channel` で見分ける**（Crumbling の
  `Mask` / `Unique` と同じ）。op 1 つが op テクスチャ 1 枚に対応する作りなので、
  出力ピンごとに別の op になる。河原の形のパラメータは op へ写す。
- **`maskOnly` の差し込み**（`NodeGraph.cpp` の「Mask だけを繋いだ堆積 / 崩落 /
  積雪」の処理）に River も足す。3 本のどれか 1 本でも繋がっていれば差し込む。
- **作業テクスチャは R32_FLOAT。** Fluvial / Sediment / Snow と同じ。
  `surface` の勾配は 1 セル 1e-5 まで落ちるので R16 では持てない。
- 作業テクスチャは Fluvial の 8 枚に `surface`（ピンポンで 2 枚）と JFA
  （種座標 + 値、ピンポンで 2 枚）を足した組になる。Fluvial と共有できるものは
  共有する。
- `IsPreviewableNodeKind()` に入れて、ノードを選んだら `Water` を
  プレビューできるようにする（Mask Fluvial と同じ扱い）。

## コスト

**いまのノードで一番重くなる。**

| 処理 | 512 グリッドでのディスパッチ数 |
| --- | --- |
| 窪み埋め = 水面（ヤコビ） | 約 1024 |
| 流量累積（ヤコビ） | 約 1024 |
| 距離場（JFA） | 9 |
| 掘る / 張る / マスク | 10 未満 |

合わせて **約 2100**。Sediment（既定 300〜640）の 3〜5 倍。
初版は「累積 1024 + 単調化 1024」で見積もっていたが、単調化を窪み埋めに
統合しても、8 回だった窪み埋めが 1024 回になるので合計は変わらない。
マスク op の入力ハッシュキャッシュには乗るので、色やラフネスを触っても
走らないが、River のパラメータを動かすたびに待つことになる。

解像度を 256 に落とせば 4 分の 1 になる。川筋の形は粗いグリッドでも決まるので、
**調整中は 256、仕上げで 512** が現実的な使い方。

Mask Fluvial の窪み埋めも同じカーネルに乗せ換えれば盆地で途切れなくなるが、
あちらは 8 回で済んでいる軽さも価値なので、切り替えは別途判断する。

## この方式では出ないもの

- **蛇行（meander）。** MFD は地形の谷底をなぞるだけなので、平野を蛇行して
  流れる川にはならない。欲しくなったら Curve ベースの別ノードが要る
  （terrain-editor の候補リストでも `River Path Mask` → 蛇行と
  段階を分けてある）。
- **内側湾曲の砂州（point bar）。** 蛇行しないので、**河原は左右対称になる。**
  崩したければ `Bank × Mask Noise` を掛ける。
- **河岸段丘。** 過去の水位を覚えていないと作れない。
- **滝。** 窪み埋めは max で持ち上げるだけなので、崖の落ち込みは水面にも残る。
  出ないのは**ハイトフィールドが垂直な水面を持てない**からで、
  崖の上下は水面として繋がるが、落ちる水そのものは描けない。
- **三角州。** 湖面で流れが扇状に広がるところまでは出るが、
  堆積が無いので州の形にはならない。

## 段階

一気に作らず 2 つに割る。**1 だけでも既存の川の見た目はかなり良くなる。**

### 段階 1 — `River`（水面まで通す）— **実装済み（2026-09-03）**

窪み埋め = 水面、累積、JFA、掘る、張る、3 本のマスクまで通した。
窪み埋めを O(解像度) にした時点で水面高は手に入るので、
「掘るだけ、水は張らない」を先に作る意味は薄い。初版はそう分けていたが、
水面を後回しにすると `Depth` の意味が途中で変わる。

JFA の伝播値は最初から `幅/2 − 距離` にした。R16 の階段は水の法線に縞として
出たので、水面の法線を R32 から作り直すパスを足した。
