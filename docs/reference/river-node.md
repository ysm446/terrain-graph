## なぜ Mask Fluvial では足りないか

**「川筋を重力方向へ流す」ところは、すでに Mask Fluvial に入っている。**
窪みを埋めてから MFD（下り勾配のある 8 近傍へ `勾配^集中度` で配分）で
流量を累積しているので、あれは「重力方向にどこまでも流した結果」そのもの。
だから流す処理を足しても絵は変わらない。

河川に足りないのは次の 3 つ。

| 足りないもの | なぜ要るか |
| --- | --- |
| **水面の高さ** | 川は「下流へ単調に下がる面」。Liquid は水位が定数なので使えない |
| **河床を掘る** | 素の地形に水路は無い。掘らないと水面が斜面に貼り付いた帯にしかならない |
| **幅** | 流量から決まる（`幅 ≒ k・√Q`）。マスクの明るさは幅ではない |

このうち**本体は水面の高さ**。ここが河川と「濡れた筋」を分ける。
いまの `data/sample.tgproj` の `River` サーフェスは後者（Mask Fluvial を
そのままマテリアルのマスクにしたもの）で、水面が無いので斜面を水が
這い上がって見える。

## 考え方

**River = Liquid の水位を、川筋に沿って下流へ単調に下がる面にしたもの。**

見えるのは常に一番上の面だけなので、1 枚のハイトフィールドでは
「河床を掘って水を張る」は**「見える Height を水面高へ置き換える」**に潰れる。
Liquid がまさにその考え方で、`水位 − 下地の高さ` がそのまま深さになる
（[compositing.md の「リキッド」](../design/compositing.md)）。

掘る処理が要るのは、水面そのものではなく**岸の形と水深**のため。
掘らないと深さが 0 になり、水の色も岸の落ち込みも出ない。

### 単調化が湖を作る

水面を下流へ単調にすると、**下流より低い区間は水面で埋まる**。
盆地に自然と湖ができるので、Lake ノードを別に作らなくてよい。
分岐や三角州も MFD ならそのまま出る。**この副作用が一番おいしい。**

## ピン

Sediment / Snow と同じ「加工」ノード（`IsHeightOperationKind`）。
下地になれず、Base に何も繋がっていなければ素通りする。

```
River   Base ──┐                      ┌── Result  地形（河床を掘って水を張った状態）
        Seed ──┤    解析グリッド 512   ├── Water   水面の被覆
               │                      ├── Bank    河原（岩・砂利を置く帯）
               └──────────────────────┴── Depth   水深
```

| ピン | 型 | 内容 |
| --- | --- | --- |
| `Base` | Material（入力） | 下地。ここまで合成した Height から川筋を作る |
| `Seed` | Mask（入力、省略可） | 川の出どころを絞る。繋がなければ全面から |
| `Result` | Material（出力） | 河床を掘り、水を張った地形 |
| `Water` | Mask（出力） | 水面の被覆。水のマテリアルを貼る |
| `Bank` | Mask（出力） | **河原。岩・砂利を置く帯**（下の節） |
| `Depth` | Mask（出力） | 水深（0〜1）。水の色の濃さ、濁りに使う |

Sediment / Crumbling / Snow と同じく **`Result` を繋がず、マスクだけ使ってもよい**
（`maskOnly` の自動差し込みに乗る）。地形を変えずに川筋の分布だけ取れる。

## パラメータ

単位は**すべて実寸（m）**。Heightmap ノードの `標高差` が基準になる。

### 川筋

| 名前 | 既定 | 意味 |
| --- | --- | --- |
| 川のしきい値 | 0.0005 | 川とみなす流量。**全セル数に対する割合**（Mask Fluvial と同じ単位） |
| 最大ディテール | 8.0 m | 流向を読む前にならす大きさ |
| 集中度 | 4.00 | 下流への配分の集中度。大きいほど主流へ集まる |
| 解像度 | 512 | 川筋を計算するグリッド。**合成解像度とは別** |

### 掘る

| 名前 | 既定 | 意味 |
| --- | --- | --- |
| 川幅 | 12.0 m | しきい値ちょうどの流量での幅 |
| 幅の伸び | 0.50 | 流量に対する幅の指数。**0.5 が水理幾何の標準**、0 で一定幅 |
| 最大幅 | 120.0 m | 下流で太くなりすぎないように止める |
| 河床の深さ | 3.0 m | 水面から河床まで |
| 岸の幅 | 8.0 m | 水際から岸の上端までの距離（**掘る形**の話） |
| 岸の硬さ | 0.35 | 0 でなだらかな土手、1 で切り立った崖 |

### 水面

| 名前 | 既定 | 意味 |
| --- | --- | --- |
| 水を張る | 入 | 切ると乾いた河床のまま残る（涸れ川・旧河道） |
| 最小勾配 | 0.0010 | 水面が下流へ下がる最小の傾き。0 にすると水平な湖が長く伸びる |

### 河原（Bank マスク）

| 名前 | 既定 | 意味 |
| --- | --- | --- |
| 河原の広がり | 15.0 m | 水際から外側へ、河原とみなす距離。**`幅の伸び` で一緒に伸びる** |
| 河原の比高 | 2.0 m | 水面からこの高さまでを河原とする（増水時に浸かる帯） |
| 河原のぼかし | 0.30 | 縁のなだらかさ |

**`岸の幅` と `河原の広がり` は別物。** 前者は地形をどう掘るか、後者は
マスクをどこまで出すか。掘った岸より外側まで河原を伸ばしたいことがあるので、
同じ値にはしない。

## パイプライン

既存の資産をかなり流用できる。

1. **窪み埋め + MFD 累積** — `CompositeFluvial.hlsl` のパスをそのまま再利用
   （`CsPitFill` / `CsWeights` / `CsAccumIter`）。`Seed` は初期流量に掛ける。
2. **流量から川を抜き、幅を決める** — `幅 = 川幅 ×(Q / Qしきい値)^幅の伸び`、`最大幅` で止める。
3. **水面高を下流へ単調化** ← **新規。** 上流へ向かって
   `surface[上] = max(surface[上], surface[下] + 最小勾配 × 距離)` をヤコビ反復。
   長距離の伝播なので反復回数は O(解像度)。
4. **中心線からの距離場** — **Jump Flooding**（512 なら 9 パス）。
   幅の内外判定、岸の落ち込み、河原マスクが全部ここから出る。
   ヤコビで距離を広げると O(解像度) 掛かるので、ここは JFA を使うこと。
5. **河床を `水面高 − 河床の深さ` へ引き下げ、岸を `岸の硬さ` でなだらかに繋ぐ。**
6. **水を張る** — 川の中の Height を水面高へ置き換える。
   Liquid と同じく**ハイトブレンドを通さない**（水位を動かしても下地を変形させない）。
7. **合成解像度へ書き戻し + `RebuildNormalsFromHeight()`。**
   堆積と同じく差分で足し戻す。ただし水面は「足す」ではなく「置き換える」なので、
   川の中と外で扱いを分けること。

## 河原（Bank）マスクの作り方

**距離場と水面高が 4 と 3 で既に出ているので、ほぼタダで作れる。**

水際からの距離 `dw`（水面の内側は負）と、水面からの比高
`h = 地形高 − 水面高` の 2 つを掛け合わせる。

```
距離の帯 = smoothstep(0, ぼかし, dw)
         × (1 - smoothstep(河原の広がり - ぼかし, 河原の広がり, dw))
比高の帯 = 1 - smoothstep(河原の比高, 河原の比高 + ぼかし, h)

Bank = 距離の帯 × 比高の帯
```

- **比高で切るのが効く。** 距離だけだと、川が谷底を流れているときに
  谷壁を駆け上がってしまう。「増水時に浸かる高さまで」が河原の定義に近い。
- **河原の広がりは流量で伸びる**（`幅の伸び` を共有）。
  源流の細い沢に 15m の河原ができるのはおかしい。

### 水中の礫

`Depth` を Mask Levels で反転すれば「浅瀬」のマスクになる。
瀬の石を置くならこちら。ノードを増やす必要はない。

## 既存ノードとの繋ぎ方

```
Heightmap → River ─ Result ─→ Surface(水) ─→ Surface(砂利) ─→ Output
              ├─ Water ────────┘                  │
              ├─ Bank ─────────────────────────────┘
              └─ Bank ──→ Crumbling(Emission) → 河原に本物の岩を積む
```

- **`Bank` → `Crumbling` の Emission が本命。** マスクで砂利の色を塗るだけでなく、
  Crumbling が**岩片の形そのもの**を河原へ積んでくれる。`Unique` 出力で
  岩 1 個ずつ色を変えられるのもそのまま効く。
  `最小サイズ` / `最大サイズ` を 0.3〜1.5m くらいに落とすと河原の石になる。
- **急な岸だけに転石を置く**なら `Bank × Mask Slope`（Mask Blend の乗算）。
- **水の質感**は [compositing.md](../design/compositing.md) の推奨値
  （ベースカラー `(0.01, 0.03, 0.035)`、ラフネス 0.05〜0.1、メタリック 0）。
  `Depth` を濁りに掛けると浅瀬が明るくなる。

## コスト

**いまのノードで一番重くなる。**

| 処理 | 512 グリッドでのディスパッチ数 |
| --- | --- |
| 流量累積（ヤコビ） | 約 1024 |
| 水面の単調化（ヤコビ） | 約 1024 |
| 距離場（JFA） | 9 |
| 掘る / 張る / マスク | 10 未満 |

合わせて **2000〜3000**。Sediment（既定 300〜640）の 3〜5 倍。
マスク op の入力ハッシュキャッシュには乗るので、色やラフネスを触っても
走らないが、River のパラメータを動かすたびに待つことになる。

解像度を 256 に落とせば 4 分の 1 になる。川筋の形は粗いグリッドでも決まるので、
**調整中は 256、仕上げで 512** が現実的な使い方。

## この方式では出ないもの

- **蛇行（meander）。** MFD は地形の谷底をなぞるだけなので、平野を蛇行して
  流れる川にはならない。欲しくなったら Curve ベースの別ノードが要る
  （terrain-editor の候補リストでも `River Network` → `Meandering Rivers` と
  段階を分けてある）。
- **内側湾曲の砂州（point bar）。** 蛇行しないので、**河原は左右対称になる。**
  崩したければ `Bank × Mask Noise` を掛ける。
- **河岸段丘。** 過去の水位を覚えていないと作れない。
- **滝。** 水面を単調にする過程で段差がならされるので、崖を落ちる水にはならない。

## 段階

一気に作らず 2 つに割る。**1 だけでも既存の川の見た目はかなり良くなる。**

### 段階 1 — `River`（掘るだけ、水は張らない）

流量から幅を決めて河床を掘り、`Bank` と `Depth` を出す。
水面の単調化を入れないので軽く（約 1050 ディスパッチ）、リスクも小さい。
このとき `Depth` は「河床の深さ」であって本物の水深ではない。

### 段階 2 — 水面の単調化

`水を張る` と `最小勾配` を足す。ここで湖も出てくる。
`Depth` の意味が本物の水深に変わるだけで、繋ぎ方は変えずに済む。

### 段階 3（やるかどうか未定）— 粒径

流量から `Grain` 出力（上流ほど 1、下流ほど 0）を出し、
河原の石のサイズやマテリアルを上下流で変える。
出力ピンが 5 本になるので、必要になってから足す。
