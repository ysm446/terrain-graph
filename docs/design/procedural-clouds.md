# 手続き雲の形状構築（実験）

作成日時: 2026-09-11 11:24
更新日時: 2026-09-11 12:28

## 目的と範囲

既存の「雲塊」「雲層」を維持し、3D直線に沿った球の配置と楕円体を合成して、雲の輪郭を組み立てる実験。Houdiniの[Cloud modeling](https://www.sidefx.com/docs/houdini/model/cloud.html)で説明される「形状生成→合成→ノイズ」の役割分担を参考にする。流体シミュレーションやVDB読み込みは行わない。

## 接続

```text
雲ライン → 雲の球配置 ─┐
                       ├→ 雲形状マージ → 雲ノイズ → 雲出力
雲楕円体 ─────────────┘
```

追加メニューの「（実験）」付き5ノードを使用する。最後の雲出力は既存ノード。大気散乱モードで描画する。
`Line`は3D直線、`Shape`は基本形状の集合、`Volume`は密度フィールド。地形用Path・Mask・Materialとは接続できない。既存の雲塊や雲層のVolumeを形状マージへ接続することもできない。

| ノード / 保存名 | 操作 |
| --- | --- |
| 雲ライン / `cloudLine` | 始点・終点XYZ（m）。初期値は(0,200,0)→(0,1600,0)の縦線 |
| 雲の球配置 / `cloudSpheres` | 球の数1〜32、始点・終点半径、XZ方向のばらつき、半径のばらつき、シード |
| 雲楕円体 / `cloudEllipsoid` | 中心XYZと各軸の半径。回転は未対応 |
| 雲形状マージ / `cloudMerge` | 2入力の形状を統合。つなぎの滑らかさ（m）を指定 |
| 雲ノイズ / `cloudNoise` | ノイズの種類、模様の大きさ、輪郭の変位、細部の削り、境界の柔らかさ、密度、Indirect Light、Ambient Light、シード |

マージは片側だけでも有効。同一ノードが複数の枝から到達する場合は1回だけ取り込む。異なる球配置ノードは同じラインを共有できる。球が1個なら始点と始点半径を使う。マージを含む1フィールドは最大32個の球・楕円体。超過時は表示を停止し、雲ノイズのプロパティに理由を表示する。黙って末尾の形状を捨てない。

ラインは今回、始点・終点の数値編集のみ。選択中のラインは始終点と線、球配置は元ラインと各球の3大円、楕円体・マージは元形状のワイヤーをビューポートに表示する。未接続の形状も対象。ガイドは雲に隠れず表示し、現在プロパティに表示している1ノードに連動する。直接ドラッグするハンドル、曲線、分岐付きライン、個々の球の手動編集、アニメーションは未対応。複数の直線から作った形状同士はマージできる。

## フィールドと描画

CPUで球・楕円体の一覧をコンパイルし、最大32個の中心・半径を描画定数へ渡す。巨大な3D密度テクスチャは作らず、GPUの共通`CloudDensity`でワールド座標から評価する。`localCloud=3`を実験経路とし、従来の0/1/2の計算は維持する。

楕円体の符号付き距離の近似から形状を作る。合成は安定化したlog-sum-expのsmooth minimum。滑らかさ0は通常のunion。入れ子のマージは最大の滑らかさをフィールド全体へ適用する。各マージ階層が個別のSDF演算を保持する方式ではない。

形状全体に同じ座標のノイズを掛ける。ノイズの種類は Perlin（従来）/ Perlin fBM / Perlin-Worley。従来は64³ノイズのAチャンネルの低周波Perlin、fBMはR、Perlin-WorleyはGで輪郭変位・Bで細部の削りを評価する。2スケールの輪郭変位と、より細かい侵食に使う。既存のノイズテクスチャを利用し、追加のGPUリソースは作らない。密度は内側へ向かってsmoothstepで増え、重なり部分の密度を単純加算しない。

包囲箱は各形状・各軸ごとに計算する。最小半径を`rMin`、正規化半径を`k0`とすると、外側の距離近似は`d >= rMin*(k0-1)`。unionと変位の最大膨張`M = smoothness*log(N)+displacement`に対し、各半径を`1+M/rMin`倍した範囲の和で包囲する。内向きの細部の削り・境界幅は余白に加えず、薄い楕円体の長軸比をフィールド全体へ掛けない。

密度評価で同じ距離下界を計算し、`min(rMin*(k0-1))-M`から0.01mの誤差余裕を引いた正の距離以内は空白として飛ばす。主視線と光学的厚さの両方に適用し、元のサンプル格子の整数歩だけ進めるため、雲内部の刻みは変えない。smooth minimumは最小距離を基準に指数和を蓄積し、`log`を形状ごとではなく密度評価につき1回へ削減する。主視線は境界幅と模様の大きさに応じた刻み（下限5m、最大2048サンプル）、光学的厚さは最大512サンプル。既存の半解像度合成を利用できる。

雲層用の光学的厚さキャッシュを実験形状にも利用し、環境マップの生成前にも更新する。背景・自己遮蔽・地形の雲影・ゴッドレイ・環境光は同じ形状を参照する。キャッシュは64×32×64の近似なので細かな陰影が滑らかになったり格子が見える場合がある。巨大な包囲箱や細い形状、全解像度描画は重くなる。

雲だけがkm単位で地面が小さい場合にも逆投影の精度が落ちないよう、この経路では雲の包囲寸法もカメラのクリップ範囲へ反映する。地形のシャドウマップ範囲は変更しない。

## 保存と互換性

新ノードは名前で保存し、設定は各ノードの`proceduralCloud`節へ記録する。既存プロジェクト形式の版は維持。読み込み時にUIと同じ範囲へ値を制限する。Undo/Redoは既存のグラフスナップショットを使用し、形状プロパティの変更では地形を再評価しない。

## 検証

Debug / Releaseビルド、既存テストと追加グラフテスト、DXC 7エントリを確認。追加テストは接続型、空入力、6種類の接続、再現性、32個上限、共有枝、循環拒否、単球、ライン削除を対象とする。

Releaseで縦長の雲＋楕円体、保存再読み込み、雲ノイズのUIを確認。従来の雲＋ゴッドレイのシーンは変更前と画素一致。画像とサンプルは`data/procedural-cloud-qa/`、開くファイルは`saved.tgproj`。`ui.png`がUI確認、`tower5.png`が描画確認。

Debug GPU検証は起動時の環境生成が数分完了せず中断したため未完了。プロパティのマウス直接操作、すべての極端な形状・設定の描画は未確認。参考画像にある高密度の細部と多重散乱品質を再現したものではなく、形状構築の実験段階。

今回のサンプル（球6個＋楕円体1個、全解像度）のReleaseベンチマークは30フレーム平均7.492 ms/frame、133.5 FPS。起動時のキャッシュ生成を含まない、この環境・シーンの測定値。`benchmark.log`に記録。


### マージの最適化と配置ガイド

Debug / Releaseビルド、グラフテスト、DXC 6エントリを確認。追加テストは未接続形状の評価、削除時のガイド消去、薄い楕円体の包囲高さ、内向き設定による不要な拡張の防止を対象とする。Releaseの`opt-gizmo.png`で球6個とラインの表示を目視。空白スキップだけを無効にした対照画像と`opt-final.png`は全画素一致した。

単独起動、同じ`saved.tgproj`、240フレームの平均は変更前25.070 ms/frame → 変更後4.215 ms/frame（約83%短縮）。起動時生成を除くアプリ計測で、GPU単独の時間ではない。過去の30フレーム測定値とは直接比較しない。ログは`opt-before-isolated.log` / `opt-after-isolated.log`。包囲範囲の縮小に伴い照明キャッシュの格子と積分開始位置は変わるため、最適化前との陰影の画素一致は保証しない。形状の密度式は維持する。編集時のキャッシュ・環境光の同期更新は残る。

更新版は`build/bin/Release/terrain_graph.exe`。Debug GPU実行検証は前回の制限どおり未完了。配置ガイドは表示のみで、操作は既存のプロパティで行う。


### ノイズの種類の選択

`proceduralCloud.noiseType`に`perlin` / `perlinFbm` / `perlinWorley`を保存する。省略・未知値は`perlin`として旧ファイルの形状を維持。描画定数では既存雲に合わせてfBM=0 / Worley=1、手続き雲専用の従来Perlin=2へ変換する。種類変更は雲の照明キャッシュと環境光にも反映する。

Debug / Releaseビルド、テスト、DXC 6エントリ、3種類のRelease描画、Perlin-Worleyの保存・再読み込み、`--screenshot-ui`で選択欄を確認。従来設定は`opt-final.png`と全画素一致。検証画像は`data/procedural-cloud-qa/noise-*.png`。Debug GPU実行検証と選択欄のマウス直接操作は未確認。

この追加の更新版は`build/cloud-opt/Release/terrain_graph.exe`。起動中の通常版がexeを使用しているため、出力先を分けてビルドした。
