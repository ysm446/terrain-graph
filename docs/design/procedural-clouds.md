# 手続き雲の形状構築（実験）

作成日時: 2026-09-11 11:24
更新日時: 2026-09-12 12:45

## 目的と範囲

既存の「雲塊」「雲層」を維持し、3D直線に沿った球の配置と楕円体を合成して、雲の輪郭を組み立てる実験。Houdiniの[Cloud modeling](https://www.sidefx.com/docs/houdini/model/cloud.html)で説明される「形状生成→合成→ノイズ」の役割分担を参考にする。流体シミュレーションやVDB読み込みは行わない。

## 接続

```text
雲ライン → 雲の球配置 ─┐
                       ├→ 雲形状マージ → 雲ノイズ → 雲出力
雲楕円体 ─────────────┘
```

追加メニューの「（実験）」付き6ノードを使用する。最後の雲出力は既存ノード。大気散乱モードで描画する。
`Line`は3D直線、`Shape`は基本形状の集合、`Volume`は密度フィールド。地形用Path・Mask・Materialとは接続できない。既存の雲塊や雲層のVolumeを形状マージへ接続することもできない。

| ノード / 保存名 | 操作 |
| --- | --- |
| Cloud Shape Generate / `cloudShapeGenerate` | 雲種、中心XYZ、サイズ、長さ／幅、球の間隔、乱れ、下側の切り取り、回転、半径のランダム化、二次形状、滑らかさ、シード。入力なしで単独の積雲を生成 |
| 雲ライン / `cloudLine` | 始点・終点XYZ（m）。初期値は(0,200,0)→(0,1600,0)の縦線 |
| 雲の球配置 / `cloudSpheres` | 球の数1〜256、始点・終点半径、XZ方向のばらつき、半径のばらつき、シード |
| 雲楕円体 / `cloudEllipsoid` | 中心XYZと各軸の半径。回転は未対応 |
| 雲形状マージ / `cloudMerge` | 2入力の形状を統合。つなぎの滑らかさ（m）を指定 |
| 雲形状複製 / `cloudReplicate` | 親1個あたりの球数1〜64、半径倍率、半径・位置のばらつき、複製後の滑らかさ、シード、元形状を残す |
| 雲ノイズ / `cloudNoise` | ノイズの種類、模様の大きさ、輪郭の変位、細部の削り、境界の柔らかさ、密度、Indirect Light、Ambient Light、シード |

マージは片側だけでも有効。同一ノードが複数の枝から到達する場合は1回だけ取り込む。異なる球配置ノードは同じラインを共有できる。球が1個なら始点と始点半径を使う。マージを含む1フィールドは最大256個の球・楕円体。超過時は表示を停止し、雲ノイズのプロパティに理由を表示する。黙って末尾の形状を捨てない。

ラインは今回、始点・終点の数値編集のみ。選択中のラインは始終点と線、球配置は元ラインと各球の3大円、楕円体・マージ・複製は出力形状のワイヤーをビューポートに表示する。未接続の形状も対象。ガイドは雲に隠れず表示し、現在プロパティに表示している1ノードに連動する。直接ドラッグするハンドル、曲線、分岐付きライン、個々の球の手動編集、アニメーションは未対応。複数の直線から作った形状同士はマージできる。

## フィールドと描画

CPUで球・楕円体の一覧をコンパイルし、最大256個の中心・半径を描画定数へ渡す。巨大な3D密度テクスチャは作らず、GPUの共通`CloudDensity`でワールド座標から評価する。`localCloud=3`を実験経路とし、従来の0/1/2の計算は維持する。

楕円体の符号付き距離の近似から形状を作る。合成は最も近い2距離だけを使う多項式smooth minimum（`d1-k*h^2/4`、`h=max(k-(d2-d1),0)/k`）。滑らかさ0は通常のunion。膨張は形状数に関係なく最大 `k/4`。入れ子のマージは最大の滑らかさをフィールド全体へ適用する。複製ノードは、入力で使われた滑らかさをそのノードの値へ置き換える。各マージ階層が個別のSDF演算を保持する方式ではない。

形状全体に同じ座標のノイズを掛ける。ノイズの種類は Perlin（従来）/ Perlin fBM / Perlin-Worley。従来は64³ノイズのAチャンネルの低周波Perlin、fBMはR、Perlin-WorleyはGで輪郭変位・Bで細部の削りを評価する。2スケールの輪郭変位と、より細かい侵食に使う。既存のノイズテクスチャを利用し、追加のGPUリソースは作らない。密度は内側へ向かってsmoothstepで増え、重なり部分の密度を単純加算しない。

包囲箱は各形状・各軸ごとに計算する。最小半径を`rMin`、正規化半径を`k0`とすると、外側の距離近似は`d >= rMin*(k0-1)`。unionと変位の最大膨張`M = smoothness/4+displacement`に対し、各半径を`1+M/rMin`倍した範囲の和で包囲する。内向きの細部の削り・境界幅は余白に加えず、薄い楕円体の長軸比をフィールド全体へ掛けない。

密度評価で同じ距離下界を計算し、`min(rMin*(k0-1))-M`から0.01mの誤差余裕を引いた正の距離以内は空白として飛ばす。主視線と光学的厚さの両方に適用し、元のサンプル格子の整数歩だけ進めるため、雲内部の刻みは変えない。smooth minimumは最小距離と2番目の距離だけを保持し、指数や対数を使わない。主視線は境界幅と模様の大きさに応じた刻み（下限5m、最大2048サンプル）、光学的厚さは最大512サンプル。既存の半解像度合成を利用できる。

雲層用の光学的厚さキャッシュを実験形状にも利用し、環境マップの生成前にも更新する。背景・自己遮蔽・地形の雲影・ゴッドレイ・環境光は同じ形状を参照する。キャッシュは64×32×64の近似なので細かな陰影が滑らかになったり格子が見える場合がある。巨大な包囲箱や細い形状、全解像度描画は重くなる。

雲だけがkm単位で地面が小さい場合にも逆投影の精度が落ちないよう、この経路では雲の包囲寸法もカメラのクリップ範囲へ反映する。地形のシャドウマップ範囲は変更しない。

## 保存と互換性

新ノードは名前で保存し、設定は各ノードの`proceduralCloud`節へ記録する。既存プロジェクト形式の版は維持。読み込み時にUIと同じ範囲へ値を制限する。Undo/Redoは既存のグラフスナップショットを使用し、形状プロパティの変更では地形を再評価しない。

### 雲形状複製と空間分割

`Shape → 雲形状複製 → Shape`。球配置・楕円体・マージの後、雲ノイズの前へ接続する。親1個あたりの球数は1〜64（既定12）、半径倍率0.05〜1（既定0.3）、半径のばらつき0〜0.9、位置のばらつき0〜1、シード0〜10000、元形状を残す（既定オン）。新しい小球に合わせ、複製後の滑らかさは独立した値（既定10m）を使う。合計256個を超えた場合は表示を停止して理由を表示する。複製を連結できる。

配置はFibonacci sphereの方向を親の各軸半径で伸縮し、親の表面上へ中心を置く。楕円体上の面積に対して一様な散布ではない。新しい球の半径は親の最小半径×倍率×ばらつき。位置の乱れは子球の半径に比例する。親の位置とシードから乱数を作り、保存時のノードIDの振り直しに影響されない。親の表面全体に配置するため、雲の下側にも膨らみが付く。元形状を残さない場合は小球だけの形状になり、間隔によって隙間ができる。

グラフ評価はノードごとの結果をキャッシュし、元ノードIDと生成番号で基本形状を識別する。元形状を残す複製結果と元形状を再マージしても元形状を二重に数えない。二つの別の複製ノードが作る子球は別形状として扱う。ギズモは複製後の形状をそのまま表示する。

17形状以上はCPUで中心位置の中央値による二分木（BVH）を構築する。葉は最大4形状、256形状で最大127ノード。形状配列を葉順に並べ、各ノードに中心のAABB、最小半径比、最大半径、葉の範囲と次の部分木への飛び先を持つ。既存の描画定数のフレーム転送を利用し、新しいGPUリソースやディスクリプタは追加しない。定数構造体は14512バイト。16形状以下は従来の順序と全数評価を維持する。

各ノードの距離下界は`distance(position, centerAABB) * min(rMin/rMax) - max(rMax)`。楕円体距離近似を下回るため、空白判定と遠方群の除外に利用できる。通常unionでは現在の最小値より遠い部分木を厳密に除外する。smooth minimumは最も近い2距離だけに依存するため、下界が`min(d2, d1+k)`より遠い部分木を厳密に除外できる（省略による誤差はない）。空白スキップの距離にも除外した部分木の下界を含める。主視線・照明キャッシュ・雲影で同じ経路を利用する。

滑らかさを大きくしたり球を密集させたりすると除外できる部分木が減る。全設定で高速化する保証はない。Cloud Shape Generateの雲種選択や、Houdini Replicateの全機能を再現したものではない。

Debug / Releaseビルド・テスト・DXC 6エントリを確認。複製テストは未接続・型・再現性・表面配置・元形状の保持/除外・再マージ・二段複製・上限超過・循環・削除を対象とする。BVHテストは葉の被覆と飛び先、細長い楕円体を含む距離下界、全数評価との1mm以内の差、離れた群での評価数削減を確認。ReleaseでUIとギズモを撮影し、91形状の複製結果について保存再読み込み前後とBVH有無で全画素一致。既存7形状のシーンも変更前と全画素一致。

同じシーン・120フレーム平均のアプリ計測は、91形状のシーンで全数評価31.188 → BVH20.470 ms/frame、離れた104形状で5.711 → 4.847 ms/frame。起動時生成を除く、この環境での測定でありGPU単独の時間ではない。比較では同じ実行ファイルにBVHだけを無効化したシェーダを指定した。

サンプルは`data/cloud-replicate-qa/saved.tgproj`、UI画像は`ui.png`、描画は`replicate.png`、比較画像・ログも同フォルダ。実行ファイルは`build/cloud-replicate/Release/terrain_graph.exe`。Debug GPU実行とプロパティのマウス直接操作は未確認。


## 形状の3Dベイク

球数の増加に伴う描画負荷を抑えるため、手続き雲（`localCloud == 3`）の合成形状を自動でGPUキャッシュへ焼き込む。既存のノード接続で利用でき、ベイク操作や追加ノードは不要。ノードと球の配置は引き続き編集でき、256形状の上限は維持する。

最終密度ではなく、ノイズを加える前の距離近似と空白距離の下界を `R32G32_FLOAT` に格納する。球の合成はベイク時にBVHを使って評価し、描画・自己遮蔽・環境・地形影は同じ格子を参照してから既存のノイズ変位と侵食を加える。これにより、ノイズの細部を格子の解像度に固定せず、描画中の球ごとの評価を除去する。キャッシュの確保やシェーダ取得が失敗した場合は従来の直接評価へ戻す。

### 格子と更新

- 既存の包囲箱の両端を格子点に含める。2D配列テクスチャのXYをハードウェア補間、Zを手動補間し、3Dの線形補間として扱う。
- 各軸8〜512点、総格子点数は192³以下。縦横比に合わせ、予算内で長軸の点数を最大化する。立方体は192³、細長い配置は長軸を最大512点まで増やす。
- キャッシュ1枚の画素データは最大54 MiB。アロケータの配置・アライメントは別。サイズ変更中は旧リソースがGPU同期完了まで残るため、一時的な使用量は増える。
- 球の数・中心・半径・接合幅、または包囲箱が変わると再ベイク。ノイズの種類・シード・スケール・侵食、照明・消散係数・サンプル数だけでは再ベイクしない。ノイズ変位幅の変更で包囲箱が変わる場合は再ベイクする。
- 光学的厚さのキャッシュとは独立。照明を直接計算する設定でも形状ベイクを利用する。シェーダ再読み込み時は両キャッシュを無効化する。
- `CloudShapeBake` のPIXマーカー、フレーム用アップロード領域、明示的なUAV→SRV遷移を使う。再確保・終了時の解放は `DeferRelease` を通す。
- `AtmosphereSettings` / `AtmosphericParameters` にSRVと格子サイズを16バイト追加し、全体は14,528バイト。実行時キャッシュはプロジェクトファイルへ保存せず、読み込み時に再生成する。

空白スキップには、補間した下界から格子セルの対角長・smooth unionの最大膨張・ノイズの最大変位を引く。単純に補間した距離で進むと細い形状を飛ばすおそれがあるため、保守的な余裕を持たせる。ベイク用シェーダでは遠方の早期returnを無効にし、格子全域の距離を生成する。

### 精度と制約

格子補間による近似なので、直接評価との画素一致は保証しない。広い範囲に極小の球を混在させると、格子より小さい凹凸が丸くなったり消えたりする可能性がある。ノイズそのものは従来通り描画時に評価する。さらに広い範囲や細かい形状への対応には、分割した格子や疎なボリュームが次の候補になる。

球が増えた場合の計算負荷は、主に形状編集時のベイクへ移る。毎フレーム球を動かす場合は毎フレームの再ベイクが必要となる。ノイズ評価・レイのステップ数・画面占有率による描画負荷は残る。

## 配置密度と平らな雲底

### 面積・体積による複製

新規の雲形状複製は「表面密度」を既定とする。「体積密度」へ切り替えると親の内部へ配置する。旧データで `distribution` が未指定の場合は「個数（従来）」として読み込み、以前の個数・半径・乱数・配置を維持する。

| 項目 | 値と意味 |
| --- | --- |
| 配置方式 | 個数（従来）／表面密度／体積密度。新規は表面密度 |
| 配置密度 | 0〜10,000、既定10。表面は個/km²、体積は個/km³ |
| 半径の倍率 | 既存通り親の最小半径に対する倍率。配置密度とは独立 |
| 合計形状数 | 元形状保持を含む実際の出力数。256個超過時は密度を下げる案内を表示 |

球数は各親の面積または体積に密度を掛けて四捨五入し、密度が正の場合は最低1個とする。密度0は追加なし。球の半径を2倍にすると、表面密度では概ね4倍、体積密度では概ね8倍の球数になる。例として半径500m、表面密度10個/km²は31個、半径1000mでは126個。体積密度10個/km³ではそれぞれ5個・42個。

楕円体の表面積は256方向の球面積分で近似し、表面への配置は面積要素の伸縮を補正した棄却法を使う。体積配置は球面方向と一様乱数の立方根を半径に使い、楕円体へ変換する。どちらも親ごとのシードで再現できる。配置後に半径の変動と位置のばらつきを加えるため、位置のばらつきを上げると中心が元形状からはみ出す場合がある。

密度は各親の面積・体積に対する値で、重なった親の内部や表面を除いた合成形状全体の測度ではない。また、球同士の非接触を保証するパッキングではない。表面はランダムな分布であり、球が近接する場合もある。半径倍率が同じなら、大きな親から生成した球の半径も大きくなる。

Houdiniの[Cloud Shape Replicate](https://www.sidefx.com/docs/houdini/nodes/sop/cloudshapereplicate.html)は表面／内部への配置とPoint Separationで密度を調整する。[Cloud Shape from Polygon](https://www.sidefx.com/docs/houdini/nodes/sop/cloudshapefrompolygon.html)のPacking Densityは、値を上げると小さい球を増やして元の形状へ近づける。この実装は既存の半径倍率を維持し、単位を明示した配置密度としている。Houdiniと同一のアルゴリズムではない。

### 密度フィールドで作る雲底

雲底は後段の「雲ノイズ」で設定する。球を底に敷き詰める代わりに、ノイズ適用後の密度フィールドを水平面で切り取り、必要なら下端をぼかす。

- 「雲底を平らにする」は既定オフ。以前のプロジェクトも未指定ならオフ。
- 「雲底の高さ」はワールドY、−20,000〜20,000m、既定0m。雲の内部を横切る高さに設定する。
- 「雲底のぼかし幅」は0〜300m、既定20m。雲底から上方向へ密度を `smoothstep` で立ち上げる。0は水平面による切断。
- 指定高さ以下の密度は0。空白スキップでは水平面までの距離を下界として使う。
- 本体・自己遮蔽・地形影・環境描画で同じ処理を使う。
- 元形状の包囲箱を変更しないので、雲底の高さ・ぼかし幅だけの変更では形状の3Dベイクを再実行しない。照明キャッシュは更新する。
- 元の密度がない隙間は埋めない。連続した底面が必要なら、上流で横長の楕円体などをマージして土台を作り、その内部をこの水平面で切る。形状選択時の球ギズモは切断前の配置を示す。

保存項目は雲形状複製の `distribution`（`count` / `surfaceDensity` / `volumeDensity`）、`packingDensity`、雲ノイズの `flattenBottom` / `bottomHeight` / `bottomFeather`。GPUでは既存のpaddingを高さ・ぼかし幅に使い、パラメータ全体のバイト数を維持する。

検証用データは `data/cloud-density-qa/`、実行ファイルは `build/cloud-density/Release/terrain_graph.exe`。表面密度のUIと雲底設定のUIをCLI撮影して目視確認した。球数と面積・体積の比例、表面／内部への配置、密度0、上限超過、旧個数指定、雲底設定のコンパイルとベイクの無効化条件をテストで確認した。

## 可変長の雲形状バッファ（2026-09-11 15:02）

## Cloud Animation

Cloud Noise → Cloud Animation → Cloud Output の Volume 接続で、入力の密度フィールドを水平に循環させる。Cloud Layer / Cloud (Legacy) の Volume にも接続できる。設定は中心X/Z、幅・奥行き（100〜100000m、既定10000m）、速度（0〜1000m/s、既定100）、方向（0〜360°、既定90）、再生（既定オン）。方向0°は+Z、90°は+X。高さは入力の雲を維持する。

指定したワールド範囲の入力を切り出し、移動分を引いた参照座標を各軸の範囲で折り返す。端を越えた部分が反対側から現れる。元から範囲をまたぐ形状は切り出されるため、形を丸ごと流したいときはノイズ変位も含めて余白を取る。個々の球の中心を瞬間移動させる方式ではない。斜め方向ではX/Zが独立に循環し、必ずしも一定秒数で全体が同じ状態に戻るわけではない。

再生オフは現在位置を保持。「開始位置へ戻す」は停止して移動量を0にする。保存対象は設定のみで、再読み込みは開始位置から。Animationを直列に接続した場合はCloud Outputに最も近い設定を使う。選択時には有効な出力につながるループ範囲を枠で表示する。

描画用範囲と形状ベイクの範囲を分離。球・BVH・形状ベイクは時間では更新しない。密度とノイズを同じ座標で参照して輪郭を維持し、空間スキップは循環の継ぎ目で制限する。照明キャッシュ・雲影はループ後の密度から更新するため、再生時にはその計算負荷がある。環境光・反射は既存の再生制御に従う。

Cloud Animation の「模様を変化」は既定オフ。オンでは「模様の速度比」（0〜1、既定0.75）を適用し、雲の移動に対するノイズの相対変位を積算する。1は模様維持、小さいほど変化が速い。オフでは相対変位を保持して変化を止め、切替時に模様を飛ばさない。再生停止は両方を停止し、開始位置へ戻す操作は両方の変位を初期化する。形状ベイクを変更せずノイズ座標だけを動かし、照明・影にも同じ密度を使う。設定のない旧データはオフで読み込む。

## Cloud Merge の膨張抑制（2026-09-12 11:05）

log-sum-expのsmooth minimumは、距離差が滑らかさk以内にある形状がN個あると輪郭が最大`k*log(N)`膨らみ、球を密に並べるCloud Line / Cloud Spheres / Cloud Map Generateでは全体が太って見えた。合成を最も近い2距離の多項式smooth minimum（`d1-k*h^2/4`、`h=max(k-(d2-d1),0)/k`）へ置き換え、膨張を形状数に関係なく最大`k/4`に固定した。入力順に依存せず、孤立した形状は膨らまない。BVHの除外は下界が`min(d2, d1+k)`を超える部分木を対象とし、誤差の閾値`k*log(N*k/0.001)`は不要になった。包囲箱と空白スキップの余白は`k*log(N)`から`k/4`へ縮小。既存プロジェクトの滑らかさ80mは同じ値のまま輪郭が細くなるため、必要に応じて値を上げ直す。


## Cloud Shape Generate（2026-09-12 12:20）

Cloud Shape Generate (Experimental) を追加。入力なしで単独の積雲を球の集合として生成し、Shape を Cloud Replicate / Cloud Merge / Cloud Noise へ接続できる。雲種（Humilis / Mediocris / Congestus）で土台の厚さと塔の高さ・本数を切り替え、中心XYZ・サイズ（基本半径）・長さ／幅の倍率・球の間隔・乱れ・下側の切り取り・回転・半径のランダム化・二次形状（繰り返し1〜3、押し出し、広がり）・つなぎの滑らかさ・シードを持つ。土台は楕円体内の乱した格子、塔は先端へ細くなる球列、二次形状は上半球方向へ積む子球。Houdini の Cloud Shape Generate を参考にした構成で、Bend と Fuse は未対応。保存識別子は `cloudShapeGenerate`、設定は `proceduralCloud` 節。 実装は `src/graph/CloudShapeGenerator.h`。生成手順は、(1) 基本半径×長さ／幅／雲種の高さ比率の楕円体内へ間隔×1.1の格子点を乱れ（±0.3格子）で揺らして配置し外縁を最大15%小さくする（隣接球は必ず重なる）、(2) 雲種の塔本数を面積比で決め、土台内側から半径0.8倍刻みで段ごとに揺らぎながら先端へ細くなる球列を立てる、(3) 二次形状で表面の球の上半球方向へ親と重なる距離に子球2個を積む、(4) 下側の切り取り平面より下の球を除き、かかる球は持ち上げる、(5) 上方向まわりに回転して中心へ移動。作業予算超過時は表示を停止して理由をUIに出す。
