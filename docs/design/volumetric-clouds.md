# ボリューム雲の仕様と方向性

作成日時: 2026-09-10 15:13
更新日時: 2026-09-12 23:10

本書はボリューム雲の現行仕様と、今後の開発判断の入口をまとめる。
現行仕様は 2026-09-11 のノイズ選択追加までを含む。今後の項目は検討候補であり、実装済み機能や確定した実装予定とは区別する。
変更の経緯・個別検証は [雲ノード](cloud-nodes.md)、大気と照明の詳細は [大気散乱スカイ](atmospheric-sky.md) を参照。

## ゴッドレイ

プレビュー設定の「ゴッドレイ」で有効・濃さ（0〜0.0002 /m、既定0.00004）・表示距離（100〜20000 m、既定5000）を指定する。既定はオフ。`preview.atmosphere` の `godRays` / `godRayDensity` / `godRayDistance` に保存し、未指定ファイルは既定値で読む。

大気散乱モードで太陽が地平線より上の場合に、一様な媒質を48点で積分する。雲なしでも有効で、カメラからシーン深度または表示距離までを対象とする。雲がある場合は従来の合成順を維持するため、雲底より下に限定する。Beer-Lambert の区間透過率と、既存の正規化HG位相関数（g=0.65）による単散乱。照明には大気透過後の太陽照度と既存の `CloudShadow` と地形のシャドウマップを使用する。地形の遮蔽はライティングの「影」に連動し、雲がないときの雲透過率は1。既存のライト行列・2048²深度・定数バイアスを共有し、3×3 PCFで比較する。空中には面法線がないため傾斜バイアスは使用しない。マップのUV・深度範囲外は遮蔽なしとして扱う。シャドウマップは描画後にpixelとcomputeの両方が読める状態へ遷移する。雲と媒質は高さで分離し、カメラが雲底の上下どちらにあるかで前後順を切り替える。シーン深度と表示距離で積分を打ち切り、HDR合成後に既存の露出・トーンマップを適用する。

雲用の半解像度ターゲット・深度再構成・PIXマーカーを共有する。無効時は追加の積分を行わない。雲層の照明キャッシュが有効ならそれを再利用する。直接計算・雲塊では多重レイマーチになるため負荷が増える。

制限: シャドウマップの範囲外の遮蔽、複数の雲Volume、雲内部の霧、多重散乱、時間方向の再投影は扱わない。雲がある場合は雲底で媒質を区切る近似であり、物理大気全体の再積分ではない。環境マップや素材の書き出しには作用しない。

検証: Debug / Release ビルド、既存テスト一式、`PsMain` / `CsCloudHalf` のDXC単体コンパイル成功。Releaseでオン・オフ画像、設定の保存・再読み込み、`--screenshot-ui` による追加項目の表示を確認（`data/godray-qa/ui4.png`）。Debug GPU検証は起動時の環境生成が数分完了せず打ち切ったため未完了。追加項目のマウスによる直接操作は未確認。

地形遮蔽の検証: Debug / Release ビルド、既存テスト、DXC成功。雲なし地形で有効・無効・影なしのRelease画像を比較し、稜線からの光の筋と影設定への連動を確認。UI撮影済み（`data/godray-terrain-qa/ui.png`）。Debug GPU検証は環境生成が数分完了せず未完了。

## 天候層（Cloud Weather Layer）

Cloud Weather Layer (Experimental) を追加。RDR2 / Nubis 方式の天候マップ駆動の雲層で、Coverage / Type の Mask 入力と Volume 出力を持つ。雲量（0〜1）と雲種（0: 層雲、0.5: 積雲、1: 積乱雲）をスライダーで指定し、マスクを接続すると場所ごとに掛ける。雲種は3本の高さプロファイル（層雲 0〜0.2、積雲 0〜0.5、積乱雲 0〜1.0 の正規化高さ）を連続的に補間し、塊ごとに頂上の高さを低周波ノイズで変える。積乱雲の広がり（かなとこ雲）、雲底のほつれ、中心XZ・範囲幅／奥行き・雲底高度・最大厚さ・端のフェード、ノイズの種類・模様の大きさ・細部の削り・密度・Indirect / Ambient Light・シード、再生・風速・風向を持つ。雲量は低周波の場（平均が指定値）で地域差を付け、形状ノイズは2オクターブで繰り返しを崩す。描画は `localCloud=4` の新経路で、雲層の照明キャッシュ・雲影・ゴッドレイ・環境光は共通。照明キャッシュの XZ 格子は天候層で 192（他は従来の 64）、カメラのクリップ範囲は層の包囲箱へ広げる。保存名は `cloudWeatherLayer`、設定は `cloudWeather` 節。

密度式（分布改善後）: 雲量の場 `broad` は風向に沿って `1/(1+3×streets)` に引き伸ばした座標で2オクターブの fBM を取り、雲種に応じてスケール `1-0.45×type`、コントラスト `1+2.5×type` を掛ける。`coverage' = saturate(coverage × mask × 2 × broad × (0.9+0.2×type)) × (1+anvil)`、`shape = remap(0.65×PW(uvw) + 0.35×PW(2.3uvw), 0.4..1)`、`density = remap(shape × profile(h/top), 1-coverage', 1)`、下部ほど強い細部の削りと範囲端のフェードを掛ける。`top = lerp(0.5,1,broad)` で塊ごとの頂上高さを変える。

照明: Cloud Weather Layer の照明に Nubis の in-scatter 確率を追加。雲底からの正規化高さ（雲種の最大高さで正規化）と局所密度から `depthProbability = 0.05 + pow(saturate(density×2), remap(h,0.3,0.85,0.5,2))`、`verticalProbability = pow(remap(h,0.07,0.14,0.1,1),0.8)` を求め、高次散乱と天空光へ `lerp(1, depth×vertical, 0.75)` を掛ける。単散乱は変えない。雲底と薄い縁が暗くなり、厚い塊の上面は明るいまま。天候層（`localCloud=4`）のみに適用し、他の雲の見た目は変えない。

LOD: Cloud Weather Layer の細部と距離 LOD。「細部の大きさ」（既定400m、20〜5000m、保存名 `detailScale`）で細部ノイズの周期を形状ノイズから独立させた（従来は模様の大きさ÷3.1＝約1290m）。主視線のレイマーチを距離適応にし、刻み幅は `max(細部の大きさ×0.08, 距離×0.004×64/サンプル数)`（近景約32m、10kmで40m、30kmで120m、最大2048サンプル）。12〜30km より遠くでは細部ノイズの参照を省き、平均値相当の薄い削りへ置き換える。照明キャッシュの格子数は下位16bitをXZ、上位16bitをYに分け、天候層は192×64×192（他は64×32×64）。他の雲経路の刻みは変えない。

照明キャッシュ: Cloud Weather Layer の風による陰影の揺らぎ対策。定点でも風で雲が動くと陰影が泳いでいた原因は、世界に固定した照明キャッシュ格子（30km で 156m）を雲が横切るたびに三線形補間の形が変わることだった。対策として、格子を風のオフセットの端数分（1ボクセル未満）だけずらして雲と一緒に動かす（`CloudCacheShift`、ベイクとサンプリングの両方に適用）。あわせて格子数を範囲に応じて決め、ボクセルを約80mに保つ（XZ 64〜256、8の倍数、Y 64。30km で 256）。他の雲経路は従来の 64×32×64。

照明調整: Cloud Weather Layer の照明調整。太陽を背にした視点で厚い雲頂が薄い縁より暗く見える逆転を修正。原因は4次で打ち切った前方寄りの位相では逆散乱の反射が不足し、天空光の平坦な明るさが支配していたこと。対策: (1) 高次散乱の残りを等方項 `sunlight × 0.3 × Indirect Light × exp(−sunDepth×0.5)` で補う、(2) 高次散乱の太陽光の減衰係数を 0.5^order → 0.8^order にして陰の側を暗くする、(3) 天空光の比重を 0.6 に下げる、(4) in-scatter の密度指数の高さ依存を 0.5〜2.0 → 0.5〜1.0 に緩め、密度は3倍で評価して雲頂の表面層を暗くしない。天候層のみに適用。

遠景: Cloud Weather Layer の遠景対応。(1) 層を地球（半径 6360 km）と同心の球殻として扱い、原点からの水平距離 d に対して層を d²/(2R) 沈める（100 km で約 790 m）。密度評価と in-scatter の高さは沈みを足した高さで計算し、包囲箱は範囲の対角端での沈み分だけ下へ広げる。地形は平らのまま。(2) 「遠景の開始距離」（既定 20 km、0 で無効、保存名 `farDistance`）より先の雲を 1/4 解像度の別パス（`CsCloudFar`）で描き、手前の積分をその距離で打ち切って後ろに合成する。半解像度モードとも併用できる。`AtmosphereSettings` は 304 バイト（weatherBottom / weatherThickness / weatherFar）。

## 手続き雲の形状構築（実験）

既存の雲塊・雲層とは別に、3D直線沿いの球と楕円体をマージして描く実験経路を追加。直線・球配置・楕円体・マージ・ノイズの5ノード。既存Volume同士の合成とは異なる。詳細は [手続き雲](procedural-clouds.md)。

## 1. 目的

山腹にかかる雲、稜線の間を流れる雲、広域にばらつく雲層を、地形を見ながら非破壊で配置・調整できるようにする。
目指すのは地形オーサリングに使えるリアルタイムの体積表現で、温度・湿度・流体から雲を生成する気象シミュレーションではない。

判断では、地形との位置関係、自然な輪郭と陰影、編集時の応答を重視する。
形状の改善を照明だけで補ったり、明るさの調整のために密度や雲影まで変えたりしないよう、操作の役割を分ける。

## 2. 現行のノードと接続

| ノード | 入出力 | 用途 |
| --- | --- | --- |
| 雲塊 (`cloud`) | 入力なし → Volume | 局所的な雲の位置・寸法・形状を直接編集する |
| 雲層 (`cloudLayer`) | Distribution: Mask → Volume | 指定範囲に雲の塊を分布させる |
| 雲出力 (`cloudOutput`) | Volume → 表示 | 地形出力と独立して、表示する雲を選ぶ |

同時に出力できる Volume は 1 つ。雲層内部には多数の塊があるが、複数の Volume ノードを合成する機能はまだない。
Volume ピンは手続き的な密度の設定を運ぶもので、汎用の体積テクスチャではない。
Material / Mask / Path とは直接接続できない。雲層の Distribution は専用の Mask 入力。

表示には大気散乱モードが必要。雲出力の未接続・無効状態では雲を表示しない。
雲ノードの選択を変えても地形の出力は変わらず、雲出力へ接続した雲を表示する。
雲出力がある場合はノード設定を優先し、ない既存プロジェクトでは従来のライティング内の雲設定を使う。

## 3. 配置と形状

位置と寸法はワールド座標の m。中心高度は地形原点を基準とし、海抜標高や地表からの相対高度ではない。
雲底の基準は `中心高度 − 厚さ / 2`。地形表面への自動吸着や地形変更への自動追従はしない。

| 操作 | 役割 |
| --- | --- |
| 中心 X/Z・中心高度、横幅・奥行き・厚さ | 雲の存在範囲を決める |
| 雲量（雲層） | 塊の広がり・輪郭を調整する。0 で消える |
| Distribution（雲層） | 広域の配置を制御する。黒は雲なし、白は未接続相当 |
| ノイズの種類 | Perlin fBM（従来・既定）と Perlin-Worley を選ぶ |
| 模様の大きさ | 雲層では配置1セルあたりの長さ（m）。表面ノイズのスケールにも使う |
| 繰り返しセル数（雲層） | 横・奥行き共通で1〜32、既定10。配置の周期を決める。範囲内の個数ではなく、高さ方向のセルはない |
| 形の崩し・細部の崩し・縁の柔らかさ | 輪郭の欠けや表面のほぐれ方を調整する |
| シード | 配置やノイズの乱数を変える |
| 平らな雲底・雲底の平らさ | 丸い底から、浅い起伏を残した平らな底へ調整する |
| 消散係数 | 雲の光の通しにくさを変える。本体・自己遮蔽・地形影に影響する |

雲塊は楕円体を基本にノイズで削る。雲層はセルごとの塊の集合を基本とし、
大きさ・縦横比・回転・高さを独立に変え、異なる高さの膨らみと座標の変形を組み合わせる。
これは同じ丸い塊が並ぶ見た目を避けるための形状近似である。
セル内の回転は自動生成されるが、雲ノード全体の回転を編集する操作は未対応。

Distribution は主に雲の配置を決める。ノイズを変更するだけで、塊自体の基本形が任意の形になるわけではない。
大まかな配置には滑らかなマスクを使い、輪郭と細部は形状側で調整する。
雲層の配置周期は「模様の大きさ × 繰り返しセル数」。広い範囲では繰り返しが見える場合がある。
表面ノイズは独自の周期を持つため、セル数は最終的な密度全体が完全に一致する周期を指定するものではない。

雲底の平らさは 0〜1。平らな雲底が有効なとき、0 は丸い底、1 は平らな底に対応する。
平らな底にもノイズによる浅い起伏と密度の立ち上がりを残し、単純な切断面にはしない。

### ノイズの選択

雲塊・雲層の「形と配置 → ノイズの種類」で選択する。雲出力を使わない旧形式の大気設定にも同じ選択を持つ。
Perlin fBM は従来の密度式を維持する。Perlin-Worley は形状に Perlin と反転 Worley の合成、細部の侵食に高周波 Worley を使う。
楕円体やセル配置は共通のため、ノイズ切替だけで熱泡の積み重ねや高さ依存の形状になるわけではない。同じ崩し量でも雲の体積や輪郭は変わる。

64³ の周期テクスチャを RGBA16F（2 MiB、従来は R16F の 0.5 MiB）で生成し、R に従来ノイズ、G に Perlin-Worley、B に細部 Worley を格納する。
Worley は周期 4・8・16・32 の特徴点との距離から合成し、ノイズ生成時だけ計算する。レイマーチ中はテクスチャを読む。
種類の切替では再生成せず、参照チャンネルを切り替える。雲層の大域的な座標変形は従来の R を使う。
本体・地形影・光学的厚さ・環境マップは共通の密度関数を使い、種類の変更は環境マップにも再生中から反映する。

プロジェクトではノードの `cloud.noiseType` と旧形式の `atmosphere.cloudNoiseType` に `perlinFbm` / `perlinWorley` を保存する。
項目がない旧プロジェクトと未知の値は Perlin fBM に戻す。

## 4. 照明と明るさ

雲は太陽光の単散乱、高次散乱の近似、上下半球からの天空照明を合成する。
本体・自己遮蔽・地形への雲影は共通の密度を使う。雲影は地形への直接光を減衰させる。

| パラメータ | 現行の意味 | 既定値 |
| --- | --- | --- |
| Indirect Light | 太陽光の高次散乱（第 2〜4 オクターブ）の倍率。0〜5 | 1 |
| Ambient Light | 雲が受ける上下半球の天空照明の倍率。0〜5 | 1 |
| スカイライト強度 | 地形と雲が共有する天空照明の強度。雲には Ambient Light をさらに乗算 | 既存のライティング設定に従う |

Indirect Light の 0 は高次の太陽光散乱を無効にするが、単散乱と天空照明は残る。
Ambient Light の 0 は雲の天空照明を無効にする。スカイライト強度が 0 なら Ambient Light を上げても天空照明は増えない。
両項目の 1 は、それぞれの項目を追加する前の明るさを維持する基準値。

これらの倍率は雲密度・視線透過率・地形への直射影を変えない。
雲を含む環境マップには反映されるため、その雲からの環境光・反射は変化しうる。
trueSKY の画面は操作の参考であり、内部式やパラメータ値の互換性は意図しない。
独立した Direct Light スライダーは現行仕様に含まれない。

多重散乱と天空照明は近似で、パストレーシングとの比較やエネルギー保存の検証は未実施。
実地形の局所的な照り返し、谷の GI、地形から雲内部へ落ちる影は未対応。

## 5. 動きと保存

| 動かし方 | 挙動 |
| --- | --- |
| 雲全体を移動 | 配置範囲と雲を一緒に移動する |
| 範囲内で模様を流す | 配置範囲を固定して模様を流す |
| 流れながら変化 | 配置範囲を動かし、表面ノイズとの相対移動で形を変える |

風速は m/s、風向は 0 度が +Z、90 度が +X。
模様の速度比は 0〜1、既定 0.75。雲層では塊の移動と表面ノイズの移動を分離する。
比率変更は移動量の積算に反映し、その瞬間に模様の位相を飛ばさない。
停止後の再生は続きから進み、「開始位置へ戻す」で移動量をリセットする。

ノード設定・接続・再生設定はプロジェクトに保存するが、経過時間と移動量は保存しない。
読み込み時は指定した位置から始まる。編集は既存グラフのアンドゥの対象で、雲の編集だけでは地形を再評価しない。
旧ファイルの Indirect Light / Ambient Light 未指定値は 1。
平らな雲底が未指定の旧ノードはオフ、雲底の平らさが未指定なら 1 として互換性を保つ。

## 6. 描画とキャッシュ

雲の存在範囲を視線と交差判定し、その区間をレイマーチする。地形深度で積分を止め、HDR で合成して既存の露出・トーンマップへ渡す。

| データ・処理 | 対象と更新 |
| --- | --- |
| 周期密度ノイズ | 64³ 相当の RGBA16F 2D 配列、2 MiB。シード変更時に再生成 |
| Distribution | 雲層の 512×512 マスクをキャッシュ。移動だけでは再評価しない |
| セル形状 | 最大32×32セルを3枚のRGBA32F（48 KiB）に保持。選択したセル数で参照座標を折り返す。シード変更・シェーダ再読み込み時に更新 |
| 光学的厚さ | 雲層の 64×32×64 格子、RGBA16F、1 MiB。太陽・上下方向を近似し、本体と地形影で共有 |
| 半解像度の雲 | 毎フレーム、縦横半分で散乱光・透過率・終端距離を計算。雲塊・雲層・従来雲に適用 |
| 環境光・反射 | ローカル雲は再生中に固定。停止・編集終了から 0.3 秒後に更新。空・シード・出力元・ノイズ種類の変更は即時更新 |

光学的厚さは停止中に再利用し、形状・分布・移動等の変更時に更新する。
Indirect Light / Ambient Light の変更だけでは光学的厚さを再計算しない。
照明キャッシュは雲層用で、雲塊と従来雲には適用しない。

半解像度の結果は 4 点補間する。空と地形の分類が違うか、終端距離の差が
`max(1 m, 終端距離の 1%)` を超える場合は、その画素を全解像度で再評価する。
地形と空の解像度は維持するが、雲の細部は少し柔らかくなる。時間方向の再投影は行っていない。
`--cloud-full-resolution` で全解像度の比較ができ、`--cloud-reference` で雲層の照明キャッシュを無効にできる。
プレビュー設定の「ボリューム雲」で、描画解像度（半解像度／全解像度）、レイマーチ品質（32／64／128）、陰影の品質（キャッシュ／直接計算）を指定し、プロジェクトに保存する。
陰影の品質は雲層の内部陰影と地形への雲影に適用する。雲塊は対象外。起動引数は保存設定より優先する比較用の指定として維持する。

### セル数と品質設定（2026-09-11）

ノードの `cloud.cellCount` に1〜32の整数を保存し、旧プロジェクトは10として読む。
品質設定は `preview.atmosphere` の `samples`、`fullResolutionClouds`、`cloudLightingCache` に保存する。
既定は64サンプル・半解像度・キャッシュ使用。「新規」で既定に戻る。
配置の移流はセル数に応じた周期、表面は従来の10セル相当の共通周期でそれぞれ折り返し、任意のセル数でも折り返し時の不連続を避ける。
セル数変更は本体・光学的厚さ・環境に反映し、セルテクスチャの再確保は不要。

Debug / Release のビルド、グラフテスト、DXC 11エントリを確認。Release で1・10・17・32セルと全解像度・128サンプル・直接計算を描画した。
10セルは変更前と全画素一致。セル数と品質設定の保存・再読み込みを確認。
`--screenshot-ui` で全体を撮影。追加項目とツールチップの直接操作・目視は未確認（前回のComputer Useで対象アプリの使用が承認されなかった）。Debug GPU実行と長時間移流の動画確認は未実施。

環境マップは地形原点から見た近似で、局所反射の視差は再現しない。
ローカル雲の再生中の反射は雲に追従せず、従来雲は最大 1 Hz 更新という違いがある。
環境マップ等の同期生成による待ちは残っている。

## 7. 性能の基準と検証上の制約

セル事前計算と半解像度描画の比較では、同一の停止シーンの GPU 処理表示が 3.94 → 1.39 ms になった。
これは雲単独ではなく、UI 等を含むフレームのグラフィックスキューの処理時間。
Present の待ち、CPU、別キューの評価、フレーム外の事前計算は含まない。
FPS の逆数やアプリ全体の平均フレーム時間とは区別する。

検証環境は NVIDIA RTX PRO 5000 Blackwell、Release、ビューポート約 1416×696。
GPU・画面サイズ・雲の占有面積・厚さ・視点・再生状態で負荷は変わるため、固定の達成値とはしない。
詳細な比較条件とアプリ全体の計測値は [雲ノードの軽量化](cloud-nodes.md#描画の軽量化) に記録している。

最新の軽量化はビルド・既存テスト・DXC・Release の描画比較を確認済み。
Debug の GPU ベース検証は起動が約 5 分で完了せず打ち切っており、この変更の Debug 実行確認は未完了。
過去の変更で完了した Debug 検証と混同しない。

### ノイズ選択の検証（2026-09-11）

- Debug / Release のビルドとグラフテスト、共有密度関数を使う DXC 12 エントリの単体コンパイルが成功。
- 雲塊・雲層それぞれの Perlin fBM / Perlin-Worley と旧形式の Perlin-Worley を Release で撮影し、目視確認。
- 雲塊の Perlin fBM は変更前の画像と全画素一致。Perlin-Worley の雲層は保存・再読み込み後も全画素一致。
- `--screenshot-ui` の画像は確認済み。ただしノイズ選択欄はスクロール範囲外で、直接操作の追加確認は Computer Use が対象アプリの使用を承認せず未実施。
- Debug の GPU ベース検証はシェーダ・パイプライン準備に時間がかかり、描画完了まで確認できていない。Release の成功と区別する。

- 画像とログはローカルの `data/cloud-noise-qa/`、確認用実行ファイルは `build/cloud-noise/Release/terrain_graph.exe`。ユーザーが起動中の実行ファイルとの競合を避け、Release の出力先を分けた。

## 8. 現行仕様の懸念点・要確認事項

以下は「怪しい部分」を残すための一覧。コードから分かる性質と、実際に描画不具合として確認できたことは分ける。
初版作成時には追加の描画実験や修正は行っていない。ノイズ選択追加時の確認は下記に記録する。

| 優先 | 箇所・状態 | 懸念と根拠 | 確認・改善の入口 |
| --- | --- | --- | --- |
| 高 | 半解像度の深度判定／コード上の制約 | 判定に使うのは地形までの距離で、雲自身の前面深度ではない。空に浮く薄い雲や雲同士の境界は、深度差による全解像度への切替で保護されない | 空背景の細い断片を全解像度と比較。静止画に加えてゆっくりカメラを動かし、消失・にじみ・ちらつきを確認 |
| 高 | 半解像度の代表点／未再現の懸念 | 2×2 の左上 1 点を採るため、サンプル間に収まる細い雲を拾えない可能性がある。時間方向の蓄積もない | 遠景・細い輪郭・カメラ移動の連番比較。必要なら代表点や復元方法を検討 |
| 高 | 再生オン・風速 0／コード上の条件不一致 | `Atmosphere::Update` の移動条件は `animateClouds && windSpeed > 0`、環境更新の停止判定は `!animateClouds`。再生オンのまま風速 0 だと動かないのに停止後の更新条件を満たさず、形状や明るさの編集が環境に反映されない可能性がある | 再生オン・風速 0 で Ambient Light や形状を変更し、再生オフ後と反射を比較。停止扱いの定義をそろえるか決める |
| 高 | 最新変更の Debug 検証／未完了 | 起動完了まで確認できていない。ログに警告がないだけでは、GPU リソースの使用が正しいとは結論できない | 検証用シェーダ処理・PSO 作成等のどこで時間がかかるか切り分け、完走を確認 |
| 中 | 全解像度への戻し判定／コード上の性質 | 補間の重みが 0 の近傍も深度判定するため、結果に寄与しない点が原因で再レイマーチする場合がある。境界の多い地形では速度改善が小さくなりうる | 再評価する画素の割合を可視化・計測。必要な点だけ判定する場合の画像差と速度を比較 |
| 中 | 距離差の閾値／調整値 | 1 m または終端距離の 1% は品質保証から導いた値ではない。遠距離では大きな差を許し、近距離や急斜面では再評価が増える可能性がある | 近景・遠景・稜線・地形と雲の接触を比較し、閾値の妥当性を検証 |
| 中 | 固定解像度の光学的厚さ／既知の近似 | 64×32×64 を広い雲層に割り当てるため、領域を広げるほどワールド空間での精度が落ちる。密度の細部より陰影が粗くなる場合がある | 薄い雲・狭い穴・太陽高度の低い場面で `--cloud-reference` と比較 |
| 中 | 形状パラメータの結合／現行仕様 | 模様の大きさが雲層のセル間隔にも関係し、雲量は塊の広がりも変える。配置の密度だけ、表面の模様だけを独立に調整しにくい | 狙った外観を作る操作を確認し、必要なら塊間隔・寸法・表面周期を分離する |
| 中 | 10 セル周期と移流／既知の制約・一部未検証 | 広域では配置の反復が見えうる。周期折返しは式として整合させているが、最新の形状の巻き戻し境界を動画で確認していない | 広角の遠景と長時間・高速移流で、反復と境界の飛びを確認 |
| 中 | 明るさの近似／未検証 | 高次散乱の係数と倍率 0〜5 は外観調整用。白飛びや陰影の平坦化を起こさない範囲が、全ての太陽高度・密度で保証されているわけではない | 同じ露出で順光・逆光・下面、Indirect / Ambient の 0・1・上限を比較。物理精度を主張する場合は参照解と比較 |
| 中 | 環境と本体の不一致／既知の制約 | 再生中の環境光・反射固定、地形原点からの環境生成、局所 GI 未対応により、目の前の雲と照明が一致しない場面がある | 光沢のある地形や雲内視点で影響を確認。表現上の許容範囲と更新方式を決める |
| 中 | 性能評価／測定範囲の制約 | 高性能 GPU の限定シーンでの結果。統計の GPU 時間は同期的なフレーム外更新を含まず、編集の引っ掛かりを見落としうる | パス別 GPU 時間に加え、連続編集の応答、環境更新の待ち、異なる解像度・GPU を測る |

「半解像度でも地形境界は補完する」は、あらゆる雲の細部を保存する保証ではない。
また、「Indirect Light / Ambient Light が 1 なら従来どおり」は各倍率の追加前との比較であり、
形状式や解像度を変更した後も過去の画像全体を再現するという意味ではない。

## 9. 今後の方向性（検討候補）

まず現在の形状と高速化を安定させ、その後に編集対象を拡張する。以下は優先順位の提案で、実装着手の確約ではない。

| 優先 | 候補 | 判断基準 |
| --- | --- | --- |
| 1 | 半解像度合成とキャッシュの品質・安定性を検証 | 雲内、稜線、薄い断片、カメラ移動、再生、リサイズで欠けやちらつきを確認。Debug 検証の未完了を解消 |
| 1 | 雲パス別の GPU 計測 | 本体・光学的厚さ・合成・環境更新のどこが重いかを分け、実測から次の最適化を選ぶ |
| 2 | 大きな形と配置の制御を改善 | 単純な丸い塊の反復を減らす。分布、塊の寸法、輪郭の崩しを必要に応じて独立に調整できるようにする |
| 2 | 品質と速度を選ぶ操作 | 全解像度と半解像度の差を評価し、通常の UI と保存設定が必要か判断する |
| 2 | 空領域のスキップ・距離に応じたサンプル配分 | 追加データの生成費用も含めて比較し、薄い雲を飛ばさずに負荷を減らせるか検証する |
| 3 | 環境更新の非同期化・時間分割 | 編集時の待ちと再生中の反射の遅れを減らす。未完成結果の混在や明滅を防ぐ |
| 3 | 複数 Volume の合成・Path 配置・操作ハンドル | 山腹の雲と広域の雲層を同時に作る必要性に応じて設計する。重なりの密度・照明・負荷も定義する |
| 後続 | 時間方向の再投影 | 残像、カメラ移動、雲の変形、編集時の履歴破棄を解決できる場合に検討する |

新しい形状方式は分布ノイズの種類だけで評価せず、大小の塊、連結した部分、穴、薄い断片が混在するかを見る。
明るさは順光の上面だけでなく、側面・下面・逆光を同じ露出で比較し、立体感を残す。
複数 Volume は単に最終画像を重ねる仕様にせず、重なった密度と透過率の扱いから検討する。

気象シミュレーション、複数の雲種、体積データの書き出し、厳密な局所 GI は当面の対象外。
他エンジンへの体積出力が必要になった段階で、出力形式と再現性を別途設計する。

## 10. 変更時の確認項目と実装入口

形状・照明の変更は、雲塊と雲層、従来雲への影響を区別して確認する。
停止と再生、順光と逆光、雲の上・下・内部、地形との交差を含め、同じカメラ・露出・設定で比較する。
分布は未接続・白・黒・滑らかなグレー、雲量は 0 と濃い設定も確認する。
キャッシュの変更ではシード編集・出力切替・ホットリロード・リサイズを確認し、保存往復と旧ファイルの読み込みも守る。

| 実装 | 役割 |
| --- | --- |
| `src/graph/NodeGraph.h` | ノード種と雲の設定 |
| `src/renderer/Atmosphere.h` / `.cpp` | 共有定数、更新判定、GPU リソースと描画 |
| `shaders/AtmosphereCommon.hlsli` | 共通の密度・交差・散乱・透過率 |
| `shaders/AtmosphereCloudCells.hlsl` | セル形状の事前計算 |
| `shaders/AtmosphereOpticalDepth.hlsl` | 雲層の光学的厚さキャッシュ |
| `shaders/AtmosphereComposite.hlsl` | 半解像度の雲計算と画面合成 |
| `shaders/AtmosphereCloudLighting.hlsl` / `AtmosphereEnvironment.hlsl` | 天空照明と環境生成 |

C++ と HLSL の共有定数は現行 176 bytes。変更時は双方の配置を合わせる。
過去の資料にある 160 bytes 等は当時の履歴であり、現在の配置ではない。
