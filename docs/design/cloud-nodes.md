# 雲ノード（第1段階）

作成日時: 2026-09-10 02:06
更新日時: 2026-09-10 03:07

## 目的と操作

山腹にかかる雲の位置と形を直接作れるようにする。グラフの右クリックから
「雲塊」「雲出力」を追加し、Volume ピンを接続する。
雲出力は1つ、接続する雲塊も1つ。未接続・無効なら雲は出ない。
複数の雲塊ノードを置いて、雲出力の接続先を差し替えて比較できる。
雲塊のコピー・削除・設定編集は既存グラフのアンドゥと保存の対象。

表示には大気散乱モードが必要。雲ノードのプロパティの「大気散乱へ切替」でも切り替えられる。
太陽・空・環境光の設定はライティングと共有する。
雲を選んでも地形の出力は変わらず、雲出力へ接続した雲を常に表示する。

## ノードと単位

- 雲塊 (`cloud`): 入力なし、Volume 出力1つ。中心 X/Y/Z、横幅・厚さ・奥行き、
  消散係数、模様の大きさ、形の崩し、細部の崩し、縁の柔らかさ、シード、有効状態。
- 雲出力 (`cloudOutput`): Volume 入力1つ。地形の Output とは独立。
- `ValueType::Volume` は Material / Mask / Path と接続できない。
  第1段階では体積テクスチャではなく、手続き的な密度の設定を運ぶ。
- 中心位置と全幅はワールド座標の m。Y は地形原点基準で海抜標高ではない。
  中心高度の上下に厚さの半分ずつを取る。地形表面へ自動吸着しない。
- 新規追加時は現在の平面サイズ S・変位量 H から横幅 0.3S、奥行き 0.2S、
  厚さ 0.4H、中心高度 0.2H を設定する。以降は地形寸法へ自動追従しない。

## 描画

既存のレイマーチ・自己遮蔽・雲影・天空照明を共有する。
楕円体の内側だけを密度領域とし、粗いノイズで形を削り、別スケールのノイズで縁をほぐす。
全軸にワールド単位のノイズ周期を使い、高さ方向の模様を厚さから独立させる。
雲本体と遮蔽・影は同じ楕円体の交差区間と密度を使う。
地形深度で視線の積分を止めるため、山に隠れた雲が山の手前へ重ならない。
追加の GPU リソースは作らず、既存の周期密度テクスチャを共有する。

局所領域と3D密度を編集する考え方は
[UE Local Fog Volumes](https://dev.epicgames.com/documentation/en-us/unreal-engine/local-fog-volumes-in-unreal-engine)と
[Unity Local Volumetric Fog](https://docs.unity.cn/Packages/com.unity.render-pipelines.high-definition%4013.0/manual/Local-Volumetric-Fog.html)を参考にした。
各エンジンの描画方式やパラメータ互換性を再現するものではない。

## 動きと更新負荷

雲塊の「動き」で再生、風速（m/s）、風向（0 度は +Z、90 度は +X）を設定する。
「雲全体を移動」は配置範囲ごと平行移動し、「範囲内で模様を流す」は範囲を固定して密度模様を流す。
「流れながら変化」は範囲を風速どおり動かし、模様をワールドで「模様の速度比」を掛けた速度で動かす（既定 0.75）。
相対的に異なるノイズ領域を読み、形を歪ませずに移動とともに輪郭が変わる。
追加ノイズ生成・テクスチャ読み取り・レイマーチステップはなく、CPU で読み取り座標のオフセットだけを更新する。
雲本体と影は共通の密度関数を使う。長時間再生は基準と細部（3.1 倍）に共通の 10 周期で折り返す。
新規雲の動かし方はこのモード。既存ファイルの translate / flow、設定がない旧ファイルの全体移動は維持する。
保存値は `motionMode: "drift"`。比率の既定 0.75 は穏やかな変化のための見た目上の選択で、気象モデルの値ではない。
「模様の速度比」は 0〜1。1 は現在の形を保ち、0 は模様を空間に固定する。
相対移動量を毎フレーム積算するため、再生中に比率を変えても現在の位相は飛ばない。
`noiseSpeedRatio` として保存し、未指定の既存ファイルは 0.75。読み込み値は 0〜1 に制限する。
再生を外すと一時停止し、再び有効にすると続きから進む。「開始位置へ戻す」は停止して移動量をゼロにする。
動かし方や出力する雲の切替でも移動量をリセットする。
再生設定は保存するが、経過時間・移動量は保存せず、読み込み時は指定した中心位置から始める。

雲のプロパティ編集は地形評価用の revision を更新しない。位置や寸法の変更では密度テクスチャを再生成しない。
雲本体と地形への雲影は毎フレーム更新し、再生中は環境光・反射を最後の計算結果に固定する。
停止中の編集は最後の変更から 0.3 秒後に環境マップを更新する。空・シード・出力元の切替は即時更新する。
これは同期的な環境マップ生成による操作中の待ちを避ける近似であり、再生中の反射は雲の移動に追従しない。

## 保存と従来の雲

ノードの `cloud` オブジェクトへ設定を保存。ピン・接続・座標は既存グラフ形式を使う。
雲出力があるとノード設定を優先し、ライティングの従来雲の編集欄を隠す。
雲出力がない既存プロジェクトでは従来の雲設定を使う。雲出力を削除すると従来設定へ戻る。
描画用の寸法を従来の `preview.atmosphere` へ上書きしない。
雲出力が複数ある不正なファイルは先頭の雲出力を採用する。

## 今回の範囲

回転、複数の雲の合成、マスク分布、Path に沿う配置、ビューポートの操作ハンドル、
体積データのエクスポートは未対応。
反射と環境光は既存の地形原点からの近似。地形が雲の内部へ落とす影は未対応。
この段階は局所的な雲形状を編集する試作で、気象シミュレーションではない。

## 検証

- Debug / Release ビルド成功。既存テストと追加の雲グラフテストを通過。
- 追加テスト: 型違いの接続拒否、設定伝達、未接続、ノード削除、出力重複拒否、地形出力の独立。
- 実行時 DXC で描画・環境光・雲影の共有シェーダをコンパイル。Debug の GPU 検証ログに警告・エラーなし。
- `--screenshot-ui --select-node 100` で雲塊のプロパティと Volume 接続を目視確認。
- 空木岳に厚い雲塊と薄い雲を配置して目視確認。元のプロジェクトは変更せず QA コピーを使用。
- 保存・再読み込みで雲の全設定が一致し、読み込み後の表示も確認。
- 旧雲の有効設定を残したまま雲出力を未接続にした画像は、雲なし画像と全画素一致。
- 検証資料は `data/cloud-node-qa/`。山腹の例は `mountain-wisp.tgproj` / `mountain-wisp.png`。
- 対話操作によるドラッグ・コピー・アンドゥの目視確認は未実施。既存のグラフ編集機構を利用する。
