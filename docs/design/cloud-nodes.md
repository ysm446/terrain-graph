# 雲ノード（第1段階）

作成日時: 2026-09-10 02:06
更新日時: 2026-09-10 12:26

## 描画の軽量化

雲層の周期セル 10×10 個について、シードだけで決まる位置・半径・高さ・回転・ローブを
10×10×3 の RGBA32F テクスチャへ事前計算する。シード変更とシェーダ再読み込み時に更新し、
風による移動では再生成しない。比較画像では事前計算だけの差は最大 1/255（RGB 各成分）。

画面上の雲は縦横半分（端数切り上げ）の解像度でレイマーチし、散乱光 RGB と透過率を
RGBA32F、終端までの距離を R32F に保存する。全解像度の合成で 4 点補間するが、
空と地形の分類が違うか、距離差が max(1 m, 終端距離の 1%) を超える場合は
当該画素を全解像度で再評価する。地形と空の描画解像度はそのまま。
雲塊・雲層・従来の雲に適用し、時間方向の履歴は使わない。
細い雲や輪郭の細部は少し柔らかくなる。リソース確保や compute pipeline の取得失敗時は
全解像度へフォールバックする。

比較用の `--cloud-full-resolution` は半解像度描画のみを無効化する。
セルの事前計算は有効なまま。設定ファイルへ保存する項目ではない。

NVIDIA RTX PRO 5000 Blackwell、Release、表示スケール 100%、ビューポート約 1416×696、
VSync 無効。12 km の雲層を 120 フレーム暖機後、240 フレーム計測した
アプリ全体の平均フレーム時間（GPU 単独の時間ではない）は以下。

| シーン | 変更前 | セル事前計算のみ | 半解像度も有効 |
| --- | ---: | ---: | ---: |
| 停止中 | 4.149 ms | 2.602 ms | 1.336 ms |
| 再生中 | 4.461 ms | 2.951 ms | 1.599 ms |

再生中の位置は実時間で進むため完全一致ではない。
停止シーンの統計画面での GPU 処理表示は変更前 3.94 ms、変更後 1.39 ms。
値は当該シーンと環境の参考値で、雲パス単独の測定値ではない。
雲塊・低い視点・地形との交差も Release の画像で確認した。
Debug は GPU ベース検証を有効にした起動が約 5 分で完了せず打ち切った。
ログに警告・エラーはなかったが、Debug 実行の検証完了とは扱わない。
比較画像とログは `data/cloud-performance-qa/`（Git 管理外）。

## 目的と操作

山腹にかかる雲の位置と形を直接作れるようにする。グラフの右クリックから
「雲塊」「雲出力」を追加し、Volume ピンを接続する。
雲出力は1つ、接続する雲塊も1つ。未接続・無効なら雲は出ない。
複数の雲塊ノードを置いて、雲出力の接続先を差し替えて比較できる。
雲塊のコピー・削除・設定編集は既存グラフのアンドゥと保存の対象。

表示には大気散乱モードが必要。雲ノードのプロパティの「大気散乱へ切替」でも切り替えられる。
太陽・空・環境光の設定はライティングと共有する。
雲を選んでも地形の出力は変わらず、雲出力へ接続した雲を常に表示する。

## ノードと単位

- 雲塊 (`cloud`): 入力なし、Volume 出力1つ。中心 X/Y/Z、横幅・厚さ・奥行き、
  消散係数、模様の大きさ、形の崩し、細部の崩し、縁の柔らかさ、シード、有効状態。
- 雲出力 (`cloudOutput`): Volume 入力1つ。地形の Output とは独立。
- `ValueType::Volume` は Material / Mask / Path と接続できない。
  第1段階では体積テクスチャではなく、手続き的な密度の設定を運ぶ。
- 中心位置と全幅はワールド座標の m。Y は地形原点基準で海抜標高ではない。
  中心高度の上下に厚さの半分ずつを取る。地形表面へ自動吸着しない。
- 新規追加時は現在の平面サイズ S・変位量 H から横幅 0.3S、奥行き 0.2S、
  厚さ 0.4H、中心高度 0.2H を設定する。以降は地形寸法へ自動追従しない。

## 描画

既存のレイマーチ・自己遮蔽・雲影・天空照明を共有する。
楕円体の内側だけを密度領域とし、粗いノイズで形を削り、別スケールのノイズで縁をほぐす。
全軸にワールド単位のノイズ周期を使い、高さ方向の模様を厚さから独立させる。
雲本体と遮蔽・影は同じ楕円体の交差区間と密度を使う。
地形深度で視線の積分を止めるため、山に隠れた雲が山の手前へ重ならない。
追加の GPU リソースは作らず、既存の周期密度テクスチャを共有する。

局所領域と3D密度を編集する考え方は
[UE Local Fog Volumes](https://dev.epicgames.com/documentation/en-us/unreal-engine/local-fog-volumes-in-unreal-engine)と
[Unity Local Volumetric Fog](https://docs.unity.cn/Packages/com.unity.render-pipelines.high-definition%4013.0/manual/Local-Volumetric-Fog.html)を参考にした。
各エンジンの描画方式やパラメータ互換性を再現するものではない。

## 動きと更新負荷

雲塊の「動き」で再生、風速（m/s）、風向（0 度は +Z、90 度は +X）を設定する。
「雲全体を移動」は配置範囲ごと平行移動し、「範囲内で模様を流す」は範囲を固定して密度模様を流す。
「流れながら変化」は範囲を風速どおり動かし、模様をワールドで「模様の速度比」を掛けた速度で動かす（既定 0.75）。
相対的に異なるノイズ領域を読み、形を歪ませずに移動とともに輪郭が変わる。
追加ノイズ生成・テクスチャ読み取り・レイマーチステップはなく、CPU で読み取り座標のオフセットだけを更新する。
雲本体と影は共通の密度関数を使う。長時間再生は基準と細部（3.1 倍）に共通の 10 周期で折り返す。
新規雲の動かし方はこのモード。既存ファイルの translate / flow、設定がない旧ファイルの全体移動は維持する。
保存値は `motionMode: "drift"`。比率の既定 0.75 は穏やかな変化のための見た目上の選択で、気象モデルの値ではない。
「模様の速度比」は 0〜1。1 は現在の形を保ち、0 は模様を空間に固定する。
相対移動量を毎フレーム積算するため、再生中に比率を変えても現在の位相は飛ばない。
`noiseSpeedRatio` として保存し、未指定の既存ファイルは 0.75。読み込み値は 0〜1 に制限する。
再生を外すと一時停止し、再び有効にすると続きから進む。「開始位置へ戻す」は停止して移動量をゼロにする。
動かし方や出力する雲の切替でも移動量をリセットする。
再生設定は保存するが、経過時間・移動量は保存せず、読み込み時は指定した中心位置から始める。

雲のプロパティ編集は地形評価用の revision を更新しない。位置や寸法の変更では密度テクスチャを再生成しない。
雲本体と地形への雲影は毎フレーム更新し、再生中は環境光・反射を最後の計算結果に固定する。
停止中の編集は最後の変更から 0.3 秒後に環境マップを更新する。空・シード・出力元の切替は即時更新する。
これは同期的な環境マップ生成による操作中の待ちを避ける近似であり、再生中の反射は雲の移動に追従しない。

## 保存と従来の雲

ノードの `cloud` オブジェクトへ設定を保存。ピン・接続・座標は既存グラフ形式を使う。
雲出力があるとノード設定を優先し、ライティングの従来雲の編集欄を隠す。
雲出力がない既存プロジェクトでは従来の雲設定を使う。雲出力を削除すると従来設定へ戻る。
描画用の寸法を従来の `preview.atmosphere` へ上書きしない。
雲出力が複数ある不正なファイルは先頭の雲出力を採用する。

## 今回の範囲

回転、複数の雲の合成、マスク分布、Path に沿う配置、ビューポートの操作ハンドル、
体積データのエクスポートは未対応。
反射と環境光は既存の地形原点からの近似。地形が雲の内部へ落とす影は未対応。
この段階は局所的な雲形状を編集する試作で、気象シミュレーションではない。

## 雲層と分布マスク

### 塊の配置と表面ノイズ

雲層は楕円体（平らな雲底では半楕円体）の集合として密度を作る。
模様の大きさをセル間隔とし、隣接 3×3 セルの塊を評価する。シードから位置・半径・縦横比・高さを変える。
セル境界でも隣の塊を評価するため、境界で途切れない。半径は 1 セル未満。
雲量で半径と輪郭を調整し、0 で消える。マスクは輪郭を縮めて分布を制御し、内部を一律に薄めない。
密度のある内部を作ってから、形状ノイズと細部ノイズで表面を削る。雲塊の密度式は維持する。
本体・影・光学的厚さキャッシュ・環境マップは同じ密度式を参照する。
配置は 10 セル周期で、既存の移流オフセットの巻き戻し周期と一致する。大きな範囲では繰り返しが見える場合がある。
高周波な分布マスクは輪郭にも細かく作用するため、大まかな雲の配置には滑らかなマスクを使う。
既存の雲層も新方式になる。保存形式・設定項目・C++ 定数配置の変更はない。

検証資料は `data/cloud-clusters-qa/`。Release で雲量 0 / 0.3 / 0.6 / 0.9、横・上、厚さ 600 / 1800 m、
平らな雲底のオン・オフ、白・黒の入力マスクを描画。関連 5 シェーダの DXC と既存テストを通過。
12 km、停止中の同一プロジェクトの 30 フレーム計測では、直前のノイズ密度方式 2.021 ms → 新方式 3.269 ms。
測定はこの場面のみ。塊の評価を追加した分だけ負荷が増える。C++ は変更していない。
Debug 描画も完了し、検証ログに警告・エラーなし。雲量 0 の画像は変更前と一致。
アニメーションの目視とグレーの分布マスクの比較は未実施。

### 分布と操作

`cloudLayer`（雲層）は Mask の Distribution 入力と Volume 出力を持ち、雲出力へ接続する。
雲塊と同じ設定を共有し、雲量 `coverage` を追加。既定は横幅・奥行き 12 km、中心高度 500 m、厚さ 600 m、模様 1500 m。
範囲は直方体。横幅・奥行きは各 20 km まで指定できる。中心高度と厚さで上下端を決める。
Distribution は白が雲、黒が空、未接続は全面。雲量で塊の広がり、マスクで局所的な塊の輪郭を調整する。
画像・ノイズ・レベル・高さなど、既存の Mask 出力を接続できる。全マスク UV を雲層の XZ 範囲へ割り当てる。
地形と一致させる場合は雲層中心 X/Z を 0、横幅・奥行きを地形の平面サイズに合わせる。自動追従はしない。
既定の動きは範囲内の模様の移流。全体移動では範囲と分布マスクも一緒に動く。

分布は専用 MaterialEvaluator の 512×512 出力でキャッシュする。通常のプレビュー選択から独立し、風や雲量の変更で再評価しない。
評価結果はプレビューの灰色範囲ではなく 0〜1 の色出力として取得する。グラフの地形 revision・接続ピン・ペイント revision が変わると更新する。
独立した補助フェンスを複数同時に扱えない現行 Device に合わせ、分布の評価はグラフィックスキューで同期記録する。
重い侵食などを分布元に使うと編集時の負荷が大きい。中間処理の作業解像度は各ノード設定を使う。
雲がないマスク領域はノイズ評価前に除外する。密度評価あたり分布テクスチャの読み取りが 1 回増える。
視線と影は同じ直方体との交差・同じ分布を使う。広い濃雲の多重レイマーチは依然高負荷で、空領域のスキップや低解像度描画は今後の課題。
分布未評価時は雲を隠し、初回完成後に環境マップを更新する。再生中の環境光・反射は既存と同じく固定。

同時に出力する Volume は引き続き 1 つ。複数の雲層や雲塊との合成、配置ハンドルは未対応。
検証資料は `data/cloud-layer-qa/`。12 km の描画、分布マスク・UI・保存を確認済み。
Debug / Release ビルドとグラフテストを通過。実行時 DXC と Debug 検証ログに警告・エラーなし。
黒マスクは雲無効と、白マスクは未接続と、各画像が全画素一致。
最適化前の Release の UI 撮影では 12 km の例が約 15 FPS（表示値）であり、その後、以下の照明キャッシュを追加した。

## 雲層の照明キャッシュ

視線上の各サンプルで繰り返していた太陽・上方・下方の光学的厚さを、64×32×64 の格子へ事前計算する。
RGBA16F の 2D 配列テクスチャ（1 MiB）を使い、描画時は隣接スライスを補間する。地形上の雲の影にも太陽方向の値を共有する。
密度ノイズ・視線方向のサンプル数は維持するが、照明と影は空間補間による近似となる。小さい影や薄い境界は柔らかくなる場合がある。

停止中は設定・分布マスクの評価 revision が変わるまで再利用する。再生中は移動後の位置とノイズから更新する。
シェーダのホットリロードでも無効化する。更新は描画前の GPU compute で記録し、CPU の GPU 完了待機を追加しない。
環境光生成は従来の計算を維持し、再生中は従来どおり固定。雲塊・旧方式の雲は対象外。

Release、VSync 無効、起動後 120 フレームの準備後に 240 フレームを計測した 12 km の検証シーンでは、
停止中 24.431 → 2.906 ms/frame、再生中 24.241 → 3.129 ms/frame。
20 km の濃い雲の別シーンでは 120 フレーム計測で 64.894 → 2.721 ms/frame。
いずれもアプリ全体のフレーム時間であり、GPU パス単体の時間ではない。シーン・画面解像度・GPU に依存する。
比較用ログ・画像は `data/cloud-speed-qa/`。12 km の停止画像は目視で確認し、RGB 平均絶対差は各チャンネル 0.31/255 未満。
Debug / Release ビルド、グラフテスト、実行時 DXC と Debug 起動を確認。

## 平らな雲底

雲塊・雲層の「形と配置」に「平らな雲底」を追加。新規ノードはオン。
保存キーは `flatBottom`（bool）。未指定の既存ノードはオフで従来形状を維持する。
雲底の基準高度は `中心高度 − 厚さ / 2`。オフへの切替で従来の密度計算に戻る。

雲塊は下側が丸い楕円体から、底面を雲底に置く半楕円体へ切り替える。
底から厚さの 12% まではノイズの高さ座標を固定し、底が細かく上下するのを抑える。
雲底は一律の水平面ではなく、既存の形状・細部ノイズに応じて基準面から厚さの 2〜21% の範囲で持ち上げる。
そこから厚さの 8% で密度を滑らかに立ち上げ、浅い起伏とほぐれた縁を残す。
初期の一律 4% の立ち上がりは切断面のように平らすぎたため置き換えた。
雲層にも同じ下部ノイズ固定・雲底の立ち上がりを使い、上端の減衰と分布マスクは維持する。
これらの割合は形状調整用の近似であり、温度・湿度から凝結高度を計算する気象モデルではない。

平らな雲塊は従来の楕円体交差に収まらないため、外接直方体との交差区間を使う。
本体・自己遮蔽・地形影・環境マップは共通の交差と密度を参照する。
密度評価 1 回のノイズ読み取り回数と GPU テクスチャは追加しない。
視線のサンプル数は従来どおり交差区間長で決まり、外接直方体への変更で増える場合がある。
AtmosphericParameters / AtmosphereSettings は 160 bytes に揃え、雲底設定と明示的なパディングを末尾に追加した。
シェーダと C++ 定数配置を同時に変更しているため、旧実行ファイルは新しいビルドへ切り替える必要がある。

### 平らな雲底の検証

- Debug / Release ビルド、既存テスト、関連 5 シェーダの DXC 単体コンパイルを通過。
