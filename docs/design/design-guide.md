# design-guide — UI の設計ガイド

作成日時: 2026-08-31 14:36
更新日時: 2026-09-06 20:00

`src/ui/` と各パネルの見た目・レイアウト・配色・部品のルール。

**UI を変更するときは必ずこのドキュメントに従う。** ここに無い見た目を足したくなったら、
まず既存の部品で表現できないかを検討し、どうしても必要なら実装と同時にここを更新する。

関連: [rendering.md](rendering.md)（ビューポートの中身） /
[compositing.md](compositing.md)（レイヤーとマスクの意味）

---

## 0. 基本原則

1. **既存のヘルパーを使う。** 設定値 1 行を描くのに `ImGui::SliderFloat` を直接呼ばない。
   [src/ui/UiStyle.h](../../src/ui/UiStyle.h) の `Property*` を使う。
   ヘルパーがラベルの体裁・幅・既定値マーカー・ツールチップ・範囲の丸めをまとめて面倒を見る。
2. **幅を親いっぱいに伸ばさない。** ウィジェットは用途ごとに決まった幅を使い、
   `SetNextItemWidth` を必ず指定する。パネルを広げたときに間延びさせない。
3. **色を直書きしない。** 配色は `ApplyTheme()` に集約する。
   パネル側で `PushStyleColor` を積まない。例外はビューポートに重ねる
   ブラシカーソルのように、テーマとは無関係な意味を持つ描画だけ。
4. **数値には必ず既定値がある。** 既定値は設定構造体の初期値
   （`MaterialLayer{}.roughness` など）を渡す。数値リテラルを直接書かない。
5. **ユーザーに見える文字列は日本語。** 識別子・ログ・シェーダ名・チャンネル名
   （`BaseColor` / `Normal` / `Surface` / `Height`）は英語のまま。

## 1. 画面レイアウト

ImGui は docking ブランチを使う。全体は 1 つのドックスペースで、
**パネルはすべてドックへ収める。**

絶対座標でパネルを置かない。ウィンドウの大きさが変わったときや、
別の大きさで保存された ini を読んだときに、画面外へはみ出して操作できなくなる。

```
+----------------------------------------------------------------------+
| メニューバー  ファイル / 表示                                          |
+-----------------------------------------------+----------------------+
| ビューポート                                   | グラフ (タブ前面)     |
| [表示モード]                                   | プレビュー設定        |
|                                               | ライティング     |
|                                               +----------------------+
|                                               | 一覧                 |
|                                               | ・ベース             |
|                                               +----------------------+
|                                               | プロパティ            |
|                                               | 基本 / ハイト / マスク |
+---------------------------+-------------------+----------------------+
| テクスチャ                 | マテリアル | 天球  |                      |
+---------------------------+-------------------+----------------------+
| ステータスバー  直近の通知 .......... プロジェクト / 数 / 解像度 / FPS |
+----------------------------------------------------------------------+
```

- **中央**: ビューポート（合成結果を貼ったプレビュー）
- **中央の下**: アセットの帯。左にテクスチャ、右にマテリアルと天球（タブ）。
- **右**: グラフ / プレビュー設定 / ライティング（タブ）。既定の前面はグラフ。
  縦に積むと 1 枚あたりが短くなり、どれもスクロールしないと全体が見えないため。

**カラムは右の 1 本だけにする。** 左右に分けると 1 本あたりが狭くなる。

**右カラムは細くする。** 中身は「パラメータ名：ウィジェット」の行と
上下に割った区画だけで、横幅を要求しない。余った幅はビューポートへ回す
（素材の見え方を確かめるのがこのツールの主目的）。

**アセットの一覧は帯へ置き、右カラムに入れない。** どれもサムネイルの格子なので、
縦長の右カラムより横に広い帯のほうが枡が多く入る。
帯の左右を **テクスチャ | マテリアル・天球** に割るのは、
**テクスチャのサムネイルをマテリアルのマップ欄へドラッグして割り当てる**ため。
掴む側と落とす側が同時に見えている必要がある（同じ枠のタブに置くと、
マテリアルを表に出した時点で一覧が隠れ、ドラッグの起点が無くなる）。
**マテリアルのサムネイルも同じくドラッグ元**で、Surface のプロパティの
マテリアル行と、グラフの Surface ノードのサムネイルへ落として割り当てる
（ペイロードは `TG_MATERIAL`。受け口はどちらも同じ ID を受けるだけ）。

**パネルの中は横ではなく縦に割る。** レイヤーは上が一覧、下がプロパティ。
プロパティは「ラベル：値」の行なので幅を要求し、横に割るとカラム全体を
広く取らないと成立しない。一覧と編集が同時に見えていれば、
レイヤーを選び直しながら値を調整できる。

**区画の境界はドラッグで動かせるようにする**（`ui::HorizontalSplitter()`）。

- 大きさは `settings.json` に覚えさせる。**起動のたびに戻ると、毎回引き直すことになる。**
- 保存は**掴んでいた手を離したときだけ**。ドラッグ中に毎フレーム書かない。
- 値は**拡大率を掛ける前**で持つ。表示スケールを変えても見た目の大きさが保たれる。
- 上限と下限を必ず入れる。引き切って片方が潰れると、戻す手掛かりが無くなる。
- 掴める幅は線より広く取る（`kSplitterGrabWidth`）。線と同じ太さだと狙って掴めない。
- 余白は `Dummy` ではなくカーソルの直接指定で空ける。
  `Dummy` を挟むと `ItemSpacing` が余分に入り、境界の位置が想定からずれる。
- **動作はテストで押さえる**（`tests/UiInteractionTests.cpp`）。
  ドラッグはスクリーンショットに写らない。

**アセットの帯は右カラムの下へ回り込ませない。** 右カラムを切り出した後の
中央ノードを割ることで、帯をビューポートの真下だけに伸ばす。

新しい常設パネルは、この 5 つの枠のどこかに入れる。フローティングウィンドウは
**メニューから開く、その場で完結する作業**だけに留める
（設定、情報、テクスチャの書き出し）。
常時見ておきたいものはドックへ入れる。

### 設定ウィンドウ

`ウィンドウ > 設定`。**プロジェクトに保存しない、アプリ側の設定だけ**を置く
（UI の拡大率と文字サイズ、ウィンドウの大きさ、垂直同期・FPS 上限・ホットリロード・背景色）。
たまにしか触らないものにドックの面積を割かないため、ドックへは収めない。

- 中身は常設パネルと同じ `Property*` の行で書く。専用の見た目を作らない。
- 変えたらその場で `settings.json` へ書く。「適用」ボタンは置かない。
- **設定の写しをアプリ側に持たない。** UI も使う場所も `m_settings.Ui()` /
  `m_settings.Display()` を直接読み書きする。写しを経由すると
  「UI では変わったのに設定へ書き戻し忘れて、次回の起動で戻る」という壊れ方をする。
  実際に FPS 上限でそうなった。**書き戻す場所が無ければ、忘れようがない。**
- **値が少数の離散値なら、スライダーではなく選択にする**（FPS 上限、拡大率）。
  スライダーだと「60 に合わせたつもりが 59」のような外れ方をする。

### プレビューの窓（マテリアル / テクスチャ / 天球）

一覧のサムネイルを**ダブルクリック**すると開く、そのアセット 1 つぶんの窓
（`ウィンドウ` メニューからも開く）。ドックへは収めない。**3 つとも同じ形にする。**

- **中身は上下 2 区画。上がプレビュー、下がプロパティ。**
  スクロールするのは下だけなので、値を送ってもプレビューは出たままになる。
  窓そのものは `NoScrollbar | NoScrollWithMouse`。
- **上の区画は幅に合わせた正方形**（`PreviewPaneSize()`）。窓を広げれば絵も大きくなり、
  区画に余白が残らない。**手で動かす境界は置かない**（幅で決まるので動かす意味が無い）。
  - 窓が横長で幅ぶんの高さが取れないときだけ、残りの高さで頭打ちにして
    絵を横中央へ寄せる。下のプロパティが 1 画面ぶんは残るようにする。
- **映すのは一覧で選んでいるもの。** 窓に別の選択を持たせない。
  持たせると「一覧で選んだもの」と「窓の中身」が食い違う状態が生まれる。
  ダブルクリックは選択と表示を同時に動かす（開いた窓には必ず押したものが出る）。
- **設定はこの窓だけが持つ。** 一覧にも同じ行を置くと、片方にだけ足したときに食い違う。

### マテリアルプレビューの窓

`ウィンドウ > マテリアルプレビュー`、または**マテリアル一覧のサムネイルを
ダブルクリック**。回せる球と、そのマテリアルのプロパティを縦に並べる。
一覧のサムネイル（84px）では、素材の粗さや法線の効きまでは読めないため。

- **映すのは一覧で選んでいるマテリアル。** 窓に別の選択を持たせない。
  持たせると「一覧で選んだもの」と「窓の中身」が食い違う状態が生まれる。
  ダブルクリックは選択と表示を同時に動かす（開いた窓には必ず押したものが出る）。
- **マテリアルの設定（基本 / マップ）はこの窓だけが持つ**（`DrawMaterialProperties`）。
  一覧にも同じ行を置くと、片方にだけ足したときに食い違う。
  値の調整は球を見ながらやるほうが早いので、置き場所はこちらに寄せる。
- **照らし方はビューポートと同じ**（適用中の天球の IBL + 太陽 + 露出 + トーンマップ）。
  素材が本番の環境でどう見えるかを確かめる窓なので、専用のライトは置かない。
  一覧のサムネイルが固定 2 灯なのは、**見比べる**ためで目的が違う。
- 操作はビューポートと揃える。**ドラッグで回し（符号も `Camera::Orbit` と同じ）、
  ホイールで寄る。** 球の区画はスクロールしないので、ホイールをズームへ回せる。
  表示だけの設定（球へ並べるタイル数、視点を戻す）は下の区画の先頭に置き、
  マテリアルの設定（基本 / マップ）とは区切り線で分ける。
  **表示だけの設定はプロジェクトに保存しない。**
- ホイールの行き先は**マウスが乗っている区画**で決まる
  （球ならズーム、プロパティならスクロール）。下の「ホイールの割り当て」。

### テクスチャプレビューの窓

`ウィンドウ > テクスチャプレビュー`、または**テクスチャ一覧のサムネイルを
ダブルクリック**。拡大した中身と、そのテクスチャの詳細（チャンネル / 名前 /
解像度 / ミップ / 形式 / 参照 / 場所）を縦に並べる。
**マテリアルプレビューの窓と同じ作法**で作る。

- 映すのは一覧で選んでいるテクスチャ。窓に別の選択を持たせない。
- 拡大表示は正方形で幅いっぱい、上限（`Scaled(480)`）で頭打ち。
- **チャンネルの切り替えはこの窓に置く。** ORD のように 1 枚へ複数のマップを
  詰めたテクスチャは、RGB のまま見ても意味が読めない。
- 名前の変更もここ。画像ファイルの名前は変わらないことをツールチップに書く。

### 天球プレビューの窓

`ウィンドウ > 天球プレビュー`、または**天球一覧のサムネイルをダブルクリック**。
**面を反転した球（天球メッシュ）を外から見た絵**と、その天球の設定
（名前 / ソース / 環境光の強さ、HDRI か手続き的な空）を並べる。
手前の面は抜けていて、向こう側の内壁に環境が貼られている。

- **映すのは適用中の天球**（＝一覧で選んだもの＝ビューポートの環境）。
  「選ぶ」と「適用する」を分けない方針（上の「天球（環境）の置き場」）のまま。
- **適用中の環境キューブをそのまま引いて毎フレーム描く**（`renderer::SkySphere`）。
  HDRI を読み直さないので、ドラッグに追従できる。露出とトーンマップは
  ビューポートに合わせる（一覧のサムネイルが固定露出なのは、見比べるためで目的が違う）。
- **メッシュは持たず、レイと単位球の交点を解析的に解く**（見え方は無限に細かい
  球メッシュと同じ）。**遠近を付ける**のが一覧のサムネイル（平行投影の円板）との違いで、
  中央が大きく縁ほど詰まるため、平たい魚眼ではなく球として読める。
- 操作はマテリアルの球と揃える。**ドラッグで回し、ホイールで寄る。**
  **掴んだ面がドラッグに付いてくる**ように、上下左右とも符号を反転させる。
  見えているのは球の**内壁**（向こう側の面）なので、素直に回すと引いた向きと
  逆へ動いて見える。マテリアルの球（外側の面を見る）とは逆の符号になる。

### ホイールの割り当て

**ホイールを取り上げてよいのは、その区画がそもそもスクロールしないときだけ。**
スクロールする区画の中の部品でホイールを横取りすると、
**ズームとスクロールが同時に起きて**、狙った場所へ行けなくなる。

- ビューポートは `ImGuiWindowFlags_NoScrollWithMouse | NoScrollbar` を立てたうえで、
  画像の上（`IsItemHovered()`）のホイールをカメラのズームにしている。
  窓がスクロールしないので競合しない。
- **スクロールさせたいものと 3D の部品は、区画で分ける。**
  マテリアルプレビューの窓は上下に割ってあり、球の区画は
  `NoScrollWithMouse`（ズーム）、プロパティの区画は普通にスクロールする。
  区画で分けずに同居させると、ホイールをどちらにも渡せない。
- どれもホバー基準で決める。**フォーカス（アクティブな窓）では決めない。**
  マウスの下にあるものが動くほうが、目と手が一致する。

### 情報ウィンドウ

`ウィンドウ > 情報`。バージョン、FPS、描画サイズ、合成・履歴・GPU リソースの
状態を確認するときだけ開く補助ウィンドウ。常設ドックの面積を使わないため、
初期状態では閉じておき、右カラムには収めない。

### 書き出しウィンドウ

`ファイル > テクスチャを書き出す…`。**設定を決めるだけで、実行はここでやらない。**
書き出しは指定解像度での再合成と読み戻しを伴うので、要求だけ積んで
フレームの外で処理する（プロジェクトの保存・読み込みと同じ作法）。

- 中身は常設パネルと同じ `Property*` の行で書く。専用の見た目を作らない。
- **押す前に、書き出されるファイル名を全部並べて見せる。**
  枚数と名前が分かっていないと、既存のファイルを上書きするのか判断できない。
- 出力先か名前が空、マップが 1 つも選ばれていないときは「書き出す」を伏せる。
  押せてしまうと、何も起きない理由を探すことになる。

### ステータスバー

画面下端に 1 行。**メニューバーと同じ仕組み**（`BeginViewportSideBar` + `BeginMenuBar`）で、
ドックスペースより**前に**呼んで作業領域を狭める。後だとドックがバーの下へはみ出す。

- **左**: いまのモード（ペイント中など）と、**直近の通知**。
  通知はログをそのまま受ける（`SetLogSink`）ので、警告やエラーを見逃さない。
  情報は 6 秒で消え、警告とエラーは次の通知まで残す。長い文はホバーで全文を出す。
- **右**: いま何を持っているか（プロジェクト名 / レイヤー・マテリアル・テクスチャの数 /
  合成解像度 / FPS）。編集できる値は置かない。**表示専用の要約だけ。**
- 通知が長いときは右の要約を出さない。重ねて読めなくするより、消えるほうがよい。

### メニューバー

- `ファイル` — 新規 / 開く… / 最近使ったプロジェクト / 保存 / 名前を付けて保存… / 終了。
  **プロジェクト全体にかかる操作だけを置く。**
  マテリアル単体の書き出しはマテリアルパネルに置く（対象が選択中のものなので）。
  **「新規」はプロジェクトが持つ設定をすべて既定へ戻す**（レイヤー・アセットに加えて、
  形状・変位量・カメラ・ライト・露出・被写界深度などのプレビュー設定も）。
  戻す項目は `PreviewRenderer::ResetSettings()` と `io::ReadPreview` で揃える。
  片方に足し忘れると「新規にしたのに前の値が残る」という壊れ方をする。
- `編集` — 元に戻す / やり直す。**対象はレイヤーとマテリアルだけ**で、
  テクスチャの読み込みと削除、ペイントの筆致、プレビュー設定は含めない。
  何が戻るのか分かるよう、メニューにその旨を添える。
- `ウィンドウ` — レイアウトのリセット、アセットの帯の切り替え（Ctrl+B）、
  情報・設定ウィンドウ。**アセットの帯は畳める。** 出さないとドックノードが空になり、
  ビューポートがその高さをもらう。状態は `settings.json` に覚えさせる
  （区画の大きさと同じ扱い）。畳んでいる間はマテリアルのドラッグができないので、
  Surface のマテリアルはコンボから選ぶ。
  **ビューポートに関わる切り替えはメニューに置かない**（ビューポート左上の
  「表示」ボタンに置く。下の「ビューポートに重ねる操作」を参照）。
  ImGui のデモのような開発専用の項目も置かない。
- **メニューでは要求を積むだけにする。** 読み書きは GPU 待機を伴うので、
  次のフレームの頭（フレームの外）で `ProcessPendingFileWork()` が処理する。
- **履歴（最近使ったプロジェクト）はアプリ側の状態**。プロジェクトにも ini にも入れず、
  `%LOCALAPPDATA%/terrain-graph/recent.json` に置く。
  項目はファイル名、右の列に置き場所を出す（同名のプロジェクトを見分けるため）。
- **ショートカットはメニュー項目に必ず併記する**（`ImGui::MenuItem` の第 2 引数）。
  割り当ては `Ctrl + N / O / S / Shift + S`（新規 / 開く / 保存 / 名前を付けて保存）と
  `Ctrl + Z / Y`（元に戻す / やり直す。`Ctrl + Shift + Z` でもやり直せる）。
  処理は `HandleShortcuts()` がメニューと**同じ入口**（`Request*`）を呼ぶ。
  片方だけ直すと動きが食い違うので、入口を分けない。

### 既定のドックレイアウト

`Application::BuildDefaultLayout()` が `DockBuilder` で組む。分割は**比率**で書く。

| 分割 | 比率 | 収めるパネル |
| --- | --- | --- |
| 右 | 0.26（全体比） | グラフ / プレビュー設定 / ライティング（タブ。グラフが前面） |
| 下 | 0.28（中央の残り高さ比） | アセットの帯 |
| 帯の右 | 0.45（帯の幅比） | マテリアル / 天球（タブ） |
| 帯の左 | 残り | テクスチャ |
| 中央 | 残り | ビューポート |

**分割の順序に意味がある。** 右 → 下 → 帯の左右 の順で切る。
下を先に切ると帯が右カラムの下まで伸びてしまう。

**同じ枠で前面にしたいパネルは、その枠へ最後にドックする。**
タブの並びは submit した順で決まるので、ドックの順を変えても並びは変わらない。

- **分割の前に `DockBuilderSetNodeSize()` を呼ぶ。** 呼ばないと分割比が当てにならない。
- **パネルを増減したり配置を変えたらドックスペース ID の版を上げる**
  （`MaterialMixerDockSpace_v12`）。
  上げないと、新しいパネルが ini に無いまま浮いて出てくる。
- 組むのは **ini にドックの配置が無いときだけ**。判定は
  `DockBuilderGetNode()` が null かどうかで、**`DockSpaceOverViewport()` がノードを作る前**に行う。
  そうしないと必ず非 null になり、判定が意味を失う。
- `ウィンドウ > レイアウトをリセット` でいつでも組み直せる。
  ini に別の大きさの配置が残っていて釣り合いが崩れたときの逃げ道になる。
- パネルを追加したら `DockBuilderDockWindow()` に**ウィンドウ名を正確に**足す。
  名前が食い違うと、そのパネルだけドックに入らず浮いたままになる。
- **タブが重なる枠では、ini に配置が無いときの前面は submit 順や
  `DockBuilder` のドック順では決まらない。** 前面にしたいパネルの `Begin` 直前で
  `SetNextWindowFocus()` を呼ぶ（既定レイアウトを組んだ直後の数フレームだけ）。
  既定は「レイヤー」。**1 つの枠にまとめたので、前面にできるのは 1 枚だけ。**
  複数のパネルが要求すると、後から描いたほうが勝って既定が定まらない。

## 2. 寸法と DPI

### ウィンドウ

**クライアント領域（描画される中身）は実ピクセルで `1920x1080 × UI の拡大率` に固定する。**
既定（拡大率 100%）では 1920x1080。
`Window::Create` の引数はクライアント領域のサイズで、枠のぶんは
`AdjustWindowRectExForDpi` が足す。録画やスクリーンショットの解像度を
モニタ設定に左右させないため。

- **作業領域に入りきらなくても縮めない。** 縮めると解像度を固定した意味が無くなる。
  はみ出すときは位置だけ作業領域の中へ寄せ、警告をログへ出す
  （タイトルバーが画面外へ出ると窓を掴めなくなるため）。
- 手で広げたりスナップしたりしたあとは、
  **`設定 > ウィンドウ > 既定の大きさに戻す`**（`Window::ResizeClient`）で 1920x1080 に戻す。
  最大化やスナップも解除する。

### UI の拡大率

**既定では UI を 1920x1080 の面へ 1:1 で載せる**（拡大率 100%）。
クライアント領域を実ピクセルで固定した以上、モニタの DPI で UI まで拡大すると、
固定したはずの作業面積がモニタ設定によって変わってしまう。

ただし高 DPI では文字が小さくなるため、**`設定 > UI` で使う人が選べる**。
「スケール追従」を入れると Windows の表示スケールに合わせ、切ると拡大率を直接選ぶ。
設定は `%LOCALAPPDATA%/terrain-graph/settings.json` に残る。

- 拡大率の変更は `ImGuiLayer::SetUiScale()` に集約する。
  スタイル（余白・部品幅）は `ui::ApplyTheme()` が掛け直し、フォントは
  **ImGui 1.92 の `style.FontScaleDpi`** が動的に拡縮する（アトラスの作り直しは不要）。
- **ウィンドウの大きさも拡大率に合わせる**（`1920x1080 × 拡大率`。150% なら 2880x1620）。
  こうすると**作業面積は論理サイズで 1920x1080 のまま**で、文字と部品だけが大きくなる。
  UI だけ拡大するとパネルが窮屈になるので、大きさは必ず揃える。
- ドックの分割幅は ini にピクセルで残るため、拡大率を変えた直後は釣り合いが崩れる。
  `ウィンドウ > レイアウトをリセット` で組み直す。

**DPI 認識自体は有効なままにする**（`ImGuiLayer::EnableDpiAwareness()` を
ウィンドウ生成より前に呼ぶ）。無効にすると OS がウィンドウごとビットマップ拡大し、
描画解像度が落ちてぼやける。

寸法定数はすべて `ui::Scaled()`（DPI だけ）か `ui::TextScaled()`（DPI と文字サイズ）を
通して使う。**文字が入る寸法は `TextScaled()`**、余白・線幅・サムネイルのように
文字と関係ない寸法は `Scaled()`。混ぜると、文字を大きくしたときに
ラベルが途中で切れたり、ボタンから文字がはみ出したりする。

### フォント

Yu Gothic Medium → Meiryo → MS ゴシック の順で読み込む。
日本語が出せるフォントを優先する。

**大きさは `設定 > UI > 文字サイズ` で使う人が選ぶ**（既定 17px、11〜28px）。
拡大率と違って余白や部品幅は動かないので、**文字だけ**を大きく / 小さくできる。

- 変更は `ImGuiLayer::SetFontSize()` に集約し、**ImGui 1.92 の `style.FontSizeBase`**
  へ入れる（`FontScaleDpi` が拡大率、その積が実際に描かれる大きさ）。
  拡大率と同じく動的ラスタライズなので、アトラスの作り直しも GPU 待機も要らない。
- `ui::ApplyTheme()` はスタイルを既定から作り直すため、**呼んだあとは必ず
  `FontSizeBase` と `FontScaleDpi` を入れ直す**（`ImGuiLayer::ApplyScaleToStyle()`）。
- ラベルは短く保つ。長いラベルは文字を大きくするとラベル列に収まらない。

**サイズを変えてよいのは一覧のサムネイルに添える名前だけ**
（`kCaptionFontSize` = 12、`ui::GridCaption()` が使う。`FontScale()` を掛けて
本文と同じ比で拡縮する）。本文（既定 17）よりはっきり小さくして、サムネイルの添え物だと分かるようにする。
小さいほど 1 行に入る字数が増えるので、長い素材名の省略も減る。
それ以外で文字サイズを変えない。ImGui 1.92 は同じフォントを別サイズで
積めるため（`PushFont(nullptr, size)`）、第 2 フォントは読み込まない。

### 部品の幅（固定値。種類を勝手に増やさない）

[src/ui/UiStyle.h](../../src/ui/UiStyle.h) の定数。96 DPI・文字 17px 基準。
「通し方」の列が、`Scaled()`（DPI のみ）と `TextScaled()`（DPI × 文字サイズ）の別。

| 定数 | 値 | 通し方 | 用途 |
| --- | --- | --- | --- |
| `kLabelColumnWidth` | 108 | TextScaled | プロパティ行のラベル列 |
| `kSliderMinWidth` / `kSliderMaxWidth` | 76 / 176 | TextScaled | スライダー。残り幅をこの範囲へ丸める |
| `kComboMaxWidth` | 190 | TextScaled | コンボの上限 |
| `kTextInputWidth` | 190 | TextScaled | 文字列入力 |
| `kButtonWidth` | 68 | TextScaled | 通常のボタン（追加 / 複製 / 削除 など） |
| `kWideButtonWidth` | 148 | TextScaled | 単独で置くボタン（視点をリセット など） |
| `kSplitterGrabWidth` | 8 | Scaled | 列の境界を掴める幅。線より広く取る |
| `kCaptionFontSize` | 12 | FontScale | 一覧のサムネイルに添える名前（唯一の例外サイズ） |
| `kNodeThumbnail` | 64 | Scaled | グラフのノードに出すサムネイル（マスクの結果 / マテリアル） |

## 3. プロパティ行（最重要）

**すべての設定値は「パラメータ名：ウィジェット」の 2 列テーブルの 1 行として描く。**
左列がラベル（末尾に全角コロン）、右列がウィジェットと既定値マーカー。

```cpp
if (ui::BeginPropertyTable("layerBasicRows")) {
    changed |= ui::PropertyFloat("ラフネス", &layer.roughness, 0.0f, 1.0f,
                                 kDefaultLayer.roughness, nullptr, "%.2f");
    ui::EndPropertyTable();
}
```

- テーブル ID は `<パネルか節の名前>Rows`。**節ごとに別のテーブルにする。**
  行の ID はラベル文字列から作るので、同じラベルを同じテーブルに 2 回置くと衝突する
  （「種類」がハイトとマスクの両方に出るなど）。
- 値は描く前に必ず範囲へ丸める（ヘルパーが内部で `std::clamp` している）。
  プロジェクト読み込み直後の範囲外値を UI 側で吸収するため。

### 行ヘルパーの使い分け

| ヘルパー | 用途 |
| --- | --- |
| `PropertyFloat` | 実数。スライダー + 既定値マーカー。既定。対数軸は `ImGuiSliderFlags_Logarithmic` |
| `PropertyInt` | 整数 |
| `PropertyBool` | チェックボックス |
| `PropertyColor` | RGB カラー。**表示色（sRGB）をそのまま持つ値**に使う（背景色など） |
| `PropertyColorLinear` | RGB カラー。**リニアで持つ色**に使う（アルベド、ライト、空）。下の「色空間」を参照 |
| `PropertyCombo` | 列挙。ラベルは配列で渡す |
| `PropertyTextInput` | 文字列入力（名前、パス） |
| `PropertyValue` | 表示専用の値 |
| `PropertyLabel` + `PropertyEnd` | 既製の行で表せないウィジェットを自分で置く |
| `PropertyLabelEmpty` + `PropertyEnd` | 値列にボタンだけを置く |

数値入力欄は別に置かない。**スライダーは Ctrl + クリックで値を直接入力できる。**
狭いパネルに入力欄まで並べると、スライダーが摘めない幅まで縮む。

- **直接入力は Enter で確定するまで値を書き戻さない**（`PropertyFloat` / `PropertyInt`）。
  ImGui は打つたびに値を適用するので、そのままだと「1」「12」「120」と途中の値で
  合成が走り、打っている最中に画面が切り替わる。スライダーには写しを渡し、入力中の
  値は ImGui の状態置き場に控え、入力が終わったフレームで 1 回だけ返す。Esc は取り消し。
  ドラッグとキーボードでの変更はその場で返す（`tests/UiInteractionTests.cpp` で押さえる）。

- **直接入力できることはツールチップに必ず出す**（`PropertyFloat` / `PropertyInt` が
  自動で「Ctrl + クリックで直接入力」を添える）。気づけない機能は無いのと同じ。
- **きりのいい値を狙う行には刻み（`snapStep`）を渡す。**
  ドラッグ中だけその刻みへ吸着し、直接入力した値は丸めない。
  「UV スケールを 2.00 に」のような操作をドラッグだけで済ませるため。

| 行 | 刻み |
| --- | --- |
| UV スケール（レイヤー / プレビュー） | 0.25 |
| ノイズの周波数 | 1（タイルするよう整数へ丸めて評価するため、表示も整数にする） |
| ノイズのオフセット | 0.5 |
| 焦点距離 | 1 mm |

刻みを増やすときは、その値が**何の単位で意味を持つか**で決める。
0〜1 の比率（ラフネスなど）は刻まない。中間の値そのものに意味があるため。

### 既定値マーカー

数値・色・列挙・真偽の行は、右端に小さな丸を置く（`ResetDot`）。

| 状態 | 色 |
| --- | --- |
| 既定値から変えてある | アクセント `#96A3AD`（ホバーで `ImGuiCol_Text`） |
| 既定値のまま | `#454545`（ホバーで `#747474`） |

- **2 つの状態は明度ではっきり離す。** もとは既定値のままの色に
  `ImGuiCol_TextDisabled`（`#747474`）を使っていたが、アクセントと明度が近く
  見分けられなかった。マーカー専用の色を `UiStyle.cpp` に持つ
  （`kResetDot` / `kResetDotHovered`）。`ImGuiCol_TextDisabled` は
  補助テキストでも使うので、そちらを暗くして解決しない。
- **既定値のままでもホバーで少し持ち上げる。** 押せることが分かるようにするため。
  ただしアクセントには寄せない（変更済みと紛らわしくなる）。
- 押すと既定値へ戻る。ツールチップに既定値そのものを出す。
- **これが「既定値から変えてあるか」の唯一の視覚表現。**
  ラベルの色を変えるといった二重の表現は入れない。

### ツールチップ

- ラベルに付ける。`Property*` の `tooltip` 引数へ渡すだけ。
- 表示は `ImGuiHoveredFlags_DelayShort`（即座には出さない）。
  折り返し幅は `GetFontSize() * 22`。
- **書き方**: 「そのパラメータが何をするか」＋「大きくすると／小さくするとどうなるか」。
  1〜2 文。単位や標準値があれば書く。
- **画面に出す文字列へ markdown を書かない。** ツールチップもヒントも
  `TextUnformatted` / `TextV` に素通しするので、`**強調**` は
  アスタリスクごとそのまま表示される。強調したいことは語順で示す
  （大事な一文を先頭に置く）。コメントとドキュメントの `**` は今までどおり。

**例外: 値が見切れる部品には、ウィジェット側にも付ける。**
テクスチャを選ぶコンボは幅が `kComboMaxWidth` で頭打ちなので、
`T_Dusty_Gravel_Grou...` のように名前が切れて見分けられない。
ラベルのツールチップ（そのスロットが何か）とは役割が別なので、両方置いてよい。

- 出すのは**いま割り当ててあるもの**。遅延はラベル側と揃える。
- **ドラッグ&ドロップの受け口より後に置くこと。**
  `SetTooltip` は内部でウィンドウを作るため、先に呼ぶと
  `BeginDragDropTarget()` が見る「直前のアイテム」が変わり、ドロップを受けられなくなる。
- ドラッグ中は出さない（`ImGui::GetDragDropPayload() != nullptr` で判定）。
  ImGui 自身がドラッグのプレビューを出すので、重ねると読めない。

### 節と補助テキスト

- 節の見出しは `ui::SectionHeader()`（`SeparatorText`）。プロパティテーブルの**外**で呼ぶ。
- 操作の説明や注意は `ui::HintText()`。テーブルの外に 1 行で置く。
  行ごとの説明はツールチップへ回し、`HintText` は節全体にかかるものだけにする。

---

### 色空間

**描画に使う色はリニアで持ち、人に見せるときだけ sRGB へ直す。**

- レンダラはリニアで計算し、テクスチャは sRGB の SRV 経由でハードウェアが
  リニア化する。**定数の色も同じリニア空間で持つ**（そうしないと、
  同じ「0.5」がテクスチャ由来か定数由来かで倍以上ずれる）。
- ImGui のカラーピッカーはガンマを知らず、渡した値をそのまま表示色として描く。
  **リニア値を直接渡すと、スウォッチの見た目と描画結果が食い違う**
  （リニア 0.5 は画面上では sRGB 0.735 相当の明るい灰色になる）。
- そのため、リニアで持つ色は `PropertyColorLinear` を使う。
  値はリニアのまま読み書きし、ピッカーへ渡す直前に sRGB へ直す。
- **一覧に出す色見本も同じ。** `ColorSwatch` などへ渡すときは
  `LinearToSrgb`（`core/ColorSpace.h`）を通す。
- 変換式は `core/ColorSpace.h` と `shaders/Common.hlsli` で必ず一致させる。
  片方だけ 2.2 乗などの近似にすると、選んだ色と描画結果がずれる。

判断に迷ったら「その値は最終的にシェーダの計算に入るか」で決める。
入るならリニア（`PropertyColorLinear`）、画面へそのまま出すだけなら表示色
（`PropertyColor`）。背景色はバックバッファへそのまま書くので後者。

## 4. 配色

グレー基調。**彩度はほぼ持たせず、明度だけで面の階層を作る。**
実装は [src/ui/UiStyle.cpp](../../src/ui/UiStyle.cpp) の `ApplyTheme()`。

| 用途 | 色 | ImGui の色 |
| --- | --- | --- |
| ウィンドウ背景 | `#1E1E1E` | `WindowBg` |
| パネル・ポップアップ | `#232323` | `ChildBg` / `PopupBg` |
| タイトル・メニューバー・タブの帯 | `#181818` | `TitleBg` / `MenuBarBg` |
| タブ（非選択 / ホバー / 選択） | `#2B2B2B` / `#363636` / `#3E3E3E` | `Tab` / `TabHovered` / `TabSelected` |
| 選択中タブの上辺 | `#666666` | `TabSelectedOverline` |
| 入力欄・ボタン | `#2B2B2B` | `FrameBg` / `Button` |
| 同（ホバー / 押下） | `#363636` / `#414141` | `*Hovered` / `*Active` |
| 見出し・選択 | `#323232` | `Header` |
| 枠線 | `#343434` | `Border` |
| 区切り線 | `#383838` | `Separator` |
| つまみ | `#606060` / `#828282` | `SliderGrab` / `*Active` |
| 文字 | `#CDCDCD` | `Text` |
| 補助文字 | `#747474` | `TextDisabled` |
| アクセント | `#96A3AD` | `CheckMark` / `DragDropTarget` など |

**アクセントは 1 色だけ。** わずかに青へ寄せた明るい灰で、
チェック、既定値から変わっている印、ドラッグ先の強調にだけ使う。
彩度を上げるとグレー基調が崩れる。

角丸は控えめ（枠 0、**タブ 0**、フレーム 2、ポップアップ 3）。
**階層は明度で作り、形では作らない。**

**タブは矩形にし、明度の 3 段（帯 < 非選択 < 選択）だけで状態を表す。**
帯を一番暗くすることで、タブが板として浮いて見える。
**フォーカスの有無では色を変えない**（`TabDimmed*` も同じ値にする）。
見たいのは「どのタブを開いているか」であって、枠がアクティブかどうかではない。
タブの帯は `TitleBg` / `TitleBgActive` なので、**この 2 つを同じ色にする。**
片方だけ明るいと、タブそのものの明度差が読み取りにくくなる。

## 5. 一覧（サムネイルのグリッド）

マテリアルとテクスチャの一覧は同じ形にする。**別々の見た目を増やさない。**

**マテリアル / テクスチャ / 天球の一覧はサムネイルだけを置く。**
（残りの高さいっぱいの `BeginChild` 1 つ）

- **設定を一覧に出さない。** 一覧は「どれを使うか選ぶ」場所で、中身の確認と
  値の調整はプレビューの窓でやる（サムネイルのダブルクリックで開く）。
- **操作のボタンの帯も置かない。** 追加 / 複製 / 削除 / 読み込み / 書き出しは
  **右クリックのメニュー**にする。常に見えている必要のない操作に、
  一覧の面積と目線を使わせない。
  - サムネイルの上（`BeginPopupContextItem`）は**そのサムネイルが対象**。
    開くときに選択もそちらへ移す（メニューの見出しに名前を出す）。
  - 余白の上（`BeginPopupContextWindow` + `NoOpenOverItems`）は対象が無いので、
    対象の要らない項目だけ（マテリアルなら追加と読み込み、テクスチャなら読み込み、
    天球なら追加）。
    **一覧が空のときの入口はここ**なので、空のときは何をすればよいかを
    `HintText` で書く。
  - キーの近道は残してよい（テクスチャの Del）。ただし**確認は同じ経路へ通す**。
  - **消させない項目は伏せる**（天球の最後の 1 つ）。押せてしまうと、
    効いていないように見える。

- 高さを決めた `BeginChild`（枠付き）の中に、パネルの幅に入るだけ横へ並べる。
  列数は `コンテンツ幅 / (サムネイル + ItemSpacing)`。
- サムネイルは正方形。マテリアルは `Scaled(84)`、テクスチャは `Scaled(72)`。
- **ドラッグ元にするサムネイルは `InvisibleButton` で ID を持たせ、画像は
  `ImDrawList::AddImage()` で描く。`ImGui::Image()` を使わない。**
  `ImGui::Image()` は ID を持たないアイテムなので、
  **`BeginDragDropSource()` が黙って `false` を返し、ドラッグが一切始まらない**
  （vcpkg の imgui は Release ビルドで `IM_ASSERT` が無効なため、警告も出ない）。
  `ImGuiDragDropFlags_SourceAllowNullID` でも動くが、あれはウィンドウ相対の位置から
  ID を捏造するもので、一覧のスクロールや折り返しで ID が変わる。
  `PushID(id)` の下に `InvisibleButton` を置けば安定した一意の ID が付く。
  クリック選択だけなら `ImGui::Image()` でも動いてしまうので、**気づきにくい。**
- **ダブルクリックは「開く」に使う**（`ui::Thumbnail::doubleClicked`）。
  マテリアルではプレビューの窓が開く。1 回目のクリックで選択も動くので、
  「選んでから開く」と同じ結果になる。ツールチップに何が起きるかを書いておく。
- 選択は**画像の上に重ねる枠**で示す（`ui::ThumbnailFrame()`）。**画像を描いた後に呼ぶ。**
  - 選択中はアクセント色（`ImGuiCol_CheckMark`）の 2px。
    枠は矩形の内側へ半分寄せる。境界にまたがって描くと、
    隣り合ったサムネイルの間で線の太さが揃わない。
  - ホバー中は 1px の弱い枠（`ImGuiCol_HeaderHovered`）。押せることが分かる程度に留める。
  - **背景に敷く方式は使わない。** サムネイルが不透明だと下の色が完全に隠れ、
    選択が一切見えなくなる（実際にそうなっていた）。
  - 枠の描画は `IsItemHovered` などと同じく**最後のアイテムを変えない**ので、
    この後に `BeginDragDropSource()` を置いてよい。
- **サムネイルの下に名前を添える**（`ui::GridCaption()`）。全体はホバーの
  ツールチップで読む。
  - **常に 2 行**で描く。名前の長さで行数が変わると升目の高さが揃わない。
  - 収まらないぶんは**中央を省略し、先頭と末尾の両方を残す**。
    `T_Rocky_Soil_..._D.EXR` と `..._N.EXR` のように、素材名は先頭、
    マップの種別は末尾に入るため、片側だけ残すと同じ表示になって見分けられない。
  - 文字は補助色（`TextDisabled`）、サイズは `kCaptionFontSize`。
  - **もとは「一覧に文字は置かない」としていた。** サムネイルだけでは
    同じ素材の別マップ（D / N / ORD）を見分けられず、
    毎回ホバーする必要があったため改めた。
- 一覧の下に `選択中` 節を置き、選択したものの詳細をプロパティ行で並べる。
- **テクスチャの `選択中` には拡大プレビューを置く。** サムネイル（72）では
  中身を確かめられないため。
  - 大きさは固定（`kTexturePreviewSize`）。プロパティ行はその横へ回す。
    **下に積むとスクロールが長くなり、何を選んでいるのかを見ながら値を確かめられない。**
  - **テクスチャパネルは区画に割らない。** 一覧を全幅で流し、詳細はその下
    （スクロールした先）に置く。**帯は縦に狭いので、割ると両方が窮屈になる。**
    詳細を横へ置くのも駄目で、一覧の幅がその分だけ削れ、
    帯が横に広くても枡が数列しか並ばない。
  - **チャンネルを分けて見られるようにする**（`RGB` / `R` / `G` / `B` / `A`）。
    Megascans の `_ORD` は 1 枚に AO / ラフネス / ハイトが詰まっており、
    RGB のまま見ても意味の読めない色の塊にしかならない。
  - 実現は **SRV の `Shader4ComponentMapping`**（`RRR1` のような並べ替え）。
    テクスチャの実体は増えず、増えるのはディスクリプタ 4 本だけ。
    シェーダも専用の焼き直しも要らない。
- **一覧の要素からドラッグできる**（テクスチャ → マップ欄）。
  ペイロードの種別は `TG_TEXTURE`。ドラッグ中はコンボを開けないので、
  受け側の `BeginDragDropTarget()` はコンボの直後で確実に本体を指す。
- **追加したものは選択して枠内へ送る**（`SetScrollHereY`）。
  一覧はスクロールするので、末尾に足しただけでは見えない位置に入る。
- **リニアなテクスチャ（EXR）はそのまま描かない。** ImGui は値をバックバッファへ
  そのまま書くので、リニアのまま出すと極端に暗い。読み込み時に sRGB へ焼いた
  表示用テクスチャを作り、一覧はそれを描く（`LibraryTexture::PreviewHandle()`）。

## 6. レイヤー一覧

- **上が最前面**（スタックの index が大きいほうが上）。一覧は逆順に描く。
- **行の並びは Quixel Mixer に合わせる。**
  「目のアイコン / マテリアルのサムネイル / マスクのサムネイル / 名前 / 削除アイコン」。
  サムネイルは `kLayerRowThumbnail`（40）の正方形で、行の高さもこれから決める。
  **目のアイコンは `kLayerRowEye`（20）で、サムネイルより小さくする。**
  同じ大きさだと切り替えのアイコンが素材と同じ重みで並び、目線が散る。
  **部品どうしと行の左右には `kLayerRowGap`（12）を空ける。**
  `ItemInnerSpacing`（6）では目・サムネイル・マスク・名前が詰まって
  1 つの塊に見える。どれも意味の違う情報なので、読み分けられる間隔を取る。
  削除アイコンも右端に貼り付けず、同じ間隔だけ内側へ寄せる。
- **行そのものを `Selectable` にし、部品はその上へ重ねる。**
  `ImGuiSelectableFlags_AllowOverlap` を付けて先に置き、`SetCursorScreenPos()` で
  部品を配置する。`SameLine` で横に並べる方式だと、
  **目のアイコンやサムネイルの上では行を選べなくなり、当たり判定に穴が空く。**
  - 部品を置く前に**次の行の位置を控え**、置き終わったらそこへカーソルを戻す。
  - ループの最後に `ImGui::Dummy()` を 1 つ置く。カーソルを動かしたまま
    アイテムを出さずに終わると、ImGui が「境界だけ広げた」と判断して警告を出す。
- 名前は削除アイコンの手前で `PushClipRect` して切る。
  隠しているレイヤー（目を閉じた行）は名前も `TextDisabled` に落とす。
- **マテリアルを割り当てていないレイヤーは、そのレイヤーの定数色を出す**
  （`ui::ColorSwatch()`）。枠だけ空けるより手がかりになる。
- **シェイプと水面のレイヤーは、サムネイルの場所に種類のアイコンを出す**
  （シェイプ = 山の稜線 `ui::MountainIcon()` / 水面 = 波 `ui::WavesIcon()`）。
  どちらもマテリアルを持たないので、スウォッチより種類が分かるほうが役に立つ。
  一覧を流し見るだけで、どの行が形や水なのかを読み分けられる。
- **マスクのサムネイルは合成のついでに焼く**（`MaterialEvaluator::MaskThumbnailHandle()`）。
  傾斜や窪みのような中間結果由来のマスクは、そのレイヤーを合成する直前の下地から
  しか作れないため、一覧側で後から作り直すことはできない。
- **並べ替えはドラッグ＆ドロップ。** ペイロードは `TG_LAYER`（スタックの index）。
  ドロップ結果はループの外で `MaterialStack::MoveTo()` に渡す。
  走査中に並びを変えない。
- `MoveTo` は入れ替えではなく「抜いて差し込む」。間のレイヤーの順序が保たれる。
- **削除もループの外で行う。** 走査中に要素を消すと、その後の行が壊れる。
  並べ替えと同じく、押された index を控えて `EndChild()` の後で処理する。
- **削除の入口は 1 つにする**（`Application::RemoveLayer()`）。
  ツールバーの `削除` と行のアイコンで別々に書くと、
  ペイントマスクの後始末のような手当てが片方に付き忘れる。
- **最後の 1 枚は消せない。** 下地が無くなると合成の起点が消えるため、
  `BeginDisabled` で落とし、理由をツールチップに出す。

### 記号を使うとき

**`×`（U+00D7）のように JIS の範囲にある字だけを使う。**
`✕`（U+2715）のような装飾的な記号は Yu Gothic に無く、`?` に化ける。
フォントは日本語が出せるシステムフォントを読むだけで、
アイコン用の字形は持っていない。

**字形が無い記号は `ImDrawList` で図形として描く。**
目のアイコン（`ui::EyeToggle()`）がその例で、上下 2 本の放物線で作った紡錘形と
瞳を描いている。レイヤー種類のアイコン（`ui::MountainIcon()` = 山の稜線 /
`ui::WavesIcon()` = 波 2 本）も同じ作法で、サムネイルと同じ枠のタイルに
線画を載せる。近い字で代用すると意味が伝わらないので、
アイコンが要るときはここに部品を足す。色はテーマから引く
（表示中は `ImGuiCol_Text`、非表示は `ImGuiCol_TextDisabled`）。

## 7. ビューポート

- `ImGui::Image` は入力を消費しない。**同じ矩形に `InvisibleButton` を重ねる**こと。
  忘れると画像上のドラッグがパネルの移動になる。
- ウィンドウには `NoScrollbar | NoScrollWithMouse` を付ける（ホイールはズームに使う）。
- 表示サイズはコンテンツ領域に合わせ、8 の倍数へ丸めてから作り直しを要求する。
  実サイズで描くとスクロールバーの出入りで要求サイズが振動する。
- ビューポートに重ねる描画（座標軸ギズモ、ブラシカーソル）は
  `GetWindowDrawList()` で描く。テーマ色ではなく、背景に埋もれない固定色を使う。

### ファイルを選ぶ

**パスの手入力欄は置かない。** `core/FileDialog.h` の
`ShowOpenFileDialog` / `ShowOpenFilesDialog` / `ShowSaveFileDialog` を使う。
COM を使うので `CoInitializeEx` 済みであること（`Application::Initialize` が済ませる）。

**エクスプローラからのドロップも受ける**（`Window::SetDropCallback`）。
拡張子で行き先を決める（画像 → テクスチャ / `.tgproj`（旧 `.mmproj` も可） → プロジェクト /
`.tgmat`（旧 `.mmmat` も可） → マテリアル / `.hdr` → 環境）。扱えない拡張子は警告を出す
（ステータスバーに出るので、黙って捨てない）。

読み込みは GPU 待機を伴うので、ダイアログで選んだパスはいったん保留し、
次のフレームの頭（フレームの外）で処理する。

### ビューポートに重ねる操作

**ビューポートの操作は、できるだけビューポートの中に置く。**
見ている場所から目を離さずに切り替えられ、いまの状態も常に見えるため。

- 置き場所は**左上**（`Scaled(10)` の余白）。画像と不可視ボタンの**あと**に submit し、
  不可視ボタンの前に `SetNextItemAllowOverlap()` を呼んで入力を譲る。
- 左端は表示モードの切り替えボタン。ボタンの文字が現在の表示を示し、
  既定（シェーディング）以外のときは警告色にする。
- その横に **「表示」ボタン**。ビューポートに重ねる情報の切り替え
  （FPS / 統計 / ハイトの範囲。どれも既定はオフ、`settings.json` に覚える）を
  ポップアップで出す。**重ねるものの切り替えはトップメニューに置かない。**
  対象が見えている場所で切り替えられるほうが迷わない。
- ライトギズモの数値は左端のボタンの下へ出す（重ねない）。
- **右上には FPS と描画の量を出す**（どちらも既定はオフ）。
  左上は切り替えボタンとライトの数値で埋まっているため。
  押すものではないのでボタンにせず、暗い下地に文字を描き込むだけにする。
  余白は左上と同じ `Scaled(10)`。
  - **箱は 1 つにまとめ、行を右へ揃える。** 別々の箱にすると片方だけ出したときに
    位置が揃わない。左揃えだと桁数が変わるたびに数字の頭が動いて目で追えない。
  - FPS は 1 桁台では小数まで出す（整数だけだと 0.8fps が「0 FPS」になり、
    止まっているのか極端に遅いのかが読めない）。
  - 数は 3 桁ごとに区切る。桁数の多い数はそのままだと読めない。
  - **テセレーション中は三角形の数を出さない。** 実際の数はドメインシェーダが
    決めるので CPU では分からない。投入したパッチ数と上限に差し替える。
    数えられないものを数えたふりをしない。

### ハイトの範囲

ビューポート左上の `表示 > ハイトの範囲`（既定はオフ、`settings.json` に覚える）。
合成した Height の **0 / 0.5 / 1 がワールドのどこに来るか**を、
平面メッシュの縁に沿ったワイヤーフレームの枠で重ねる。

- ディスプレイスメントは `(height - 0.5) × 変位量` なので、0.5 が元の面、
  0 / 1 がその上下 ±0.5 × 変位量。枠は変位量の変更に追従する。
- **平面のときだけ描く。** 球とキューブは法線方向への押し出しなので、
  直方体の枠では高さの範囲を表せない。
- 0.5 の枠だけ色を落とし、基準面だと分かるようにする。ラベル（0.0 / 0.5 / 1.0）は
  手前の角に添える。色は他のギズモと同じく固定（テーマから引かない）。
- **枠の線はレンダラが描く**（`PreviewRenderer::DrawHeightGuideOverlay`）。
  シーンの深度でテストしてメッシュの向こう側を隠すためで、ImGui の
  オーバーレイでは深度が使えない。トーンマップ後の表示用テクスチャへ、
  露出を通さない表示色のまま描く（画面上で一定の明るさに見えるべきもの）。
  ラベルの文字だけは ImGui で重ねる。線は `--screenshot` にも写る。

### 天球（環境）の置き場

**空そのものの設定は「天球」パネルに集め、「ライティング」には残さない。**
環境は「どう見えるか」ではなく**素材と並ぶアセット**で、マテリアルと同じく
名前・サムネイル・複製を持つため。

- 一覧は**マテリアルと同じ作法**（追加 / 複製 / 削除 + サムネイルの格子）。
  サムネイルは**裏返した球**（内側に環境が貼られた玉）で、
  マテリアルの球と大きさ・余白・輪郭のぼかしを揃える。
- **一覧で選んだものが、そのままビューポートの環境になる。**
  環境は同時に 1 つしか使えないので、「選ぶ」と「適用する」は分けない。
  分けても操作が 1 つ増えるだけで、選んだのに反映されない状態のほうが混乱する。
- **一覧は空にしない。** 空だと環境が決まらないので、最後の 1 つは消させない。
- 「ライティング」に残すのは、天球ではなく**見え方**に属するもの
  （背景の表示とぼかし、露出、トーンマップ）。適用中の天球の名前だけを表示で出す。

### 表示モード

ビューポート左上のボタンで、合成したチャンネルをそのまま覗ける
（シェーディング / ベースカラー / 法線（カメラ・ワールド）/ ラフネス /
メタルネス / AO / ハイト / ワイヤーフレーム / クレイ）。

- **値をそのまま見るための表示**なので、露出もトーンマップも掛けない。
  背景（スカイボックス）も描かない。実装は `renderer::DebugView`。
- ベースカラーだけは sRGB へ直して出す（リニアのままだと暗く見えるため）。
- **形を見る表示（ワイヤーフレーム / クレイ）は上の扱いから外れる。**
  - ワイヤーフレームはラスタライザの設定（`fillMode`）で、単色の線として描く。
  - **クレイはテクスチャを貼らないだけで、陰影は本物**（露出もトーンマップも
    背景も、シェーディングと同じ）。値を覗く表示ではないので素通しにしない。
    一覧の並びはワイヤーフレームの隣に置く。どちらも「形を見る」ためのもの
    （線で見るか、単色の陰影で見るか）。
- 法線は**同じ向き（法線マップを当てたあとの、陰影に実際に使う向き）を
  2 つの空間で**見せる。**カメラ**は画面に対する向き（正面が水色。
  視点を回すと色が変わる）、**ワールド**は世界に対する向き（視点を回しても
  変わらない）。どちらも `n * 0.5 + 0.5` で色にする。
  - カメラ空間は右手系（カメラは -Z を向く）なので、正面を向いた面が
    法線マップと同じ水色になり、同じ読み方ができる。
- **既定以外の表示になっていることはボタンの文字色（警告色）で示す。**
  見落とすと「マテリアルが壊れた」と勘違いするため。

### ライトギズモ

L + 左ドラッグの最中と、離してから 0.35 秒だけ重ねる。**常時は出さない。**

- 地面のリング（方位角の目安）、水平方向への投影、仰角の弧、光が来る向きの矢印、原点の丸。
- 左上に `方位角 xx 度  仰角 xx 度` を出す。掴んだまま数値を確かめられるようにするため。
- ワールド座標はカメラの `ビュー × 投影` で画面へ落とす（`ProjectToViewport`）。
  カメラの後ろに回った点は描かない。
- 色は座標軸ギズモと同じく**意味色**。光は暖色（`#FFBC4C`）、地面のリングは無彩色寄り。

### 座標軸ギズモ

左下に置く。ビューポートの左下から `Scaled(16)`、半径 `Scaled(30)`。

- 色は DCC 共通の意味色。**X = 赤 / Y = 緑 / Z = 青**。テーマからは引かない。
- 透視投影は掛けず、カメラの基底（`Camera::Basis()`）へ落とした向きだけを見せる。
- 奥を向いている軸はアルファを落とし、奥の軸から先に描く。
- **線と軸名だけで描く。先端に丸は置かない。** 向きを読むのに要らない飾りで、
  小さく描くほど密になって見づらくなる。
- **軸名は軸の色で描く。** 下に敷く丸が無いので、暗い色だと背景に沈む。
- **線は軸名の手前で止める。** 文字まで引くと字画と重なって読めなくなる。
- ビューポートが小さくて収まらないときは描かない。

### 操作

| 状態 | 左ドラッグ | 中ドラッグ | 右ドラッグ | ホイール |
| --- | --- | --- | --- | --- |
| **Alt を押しながら** | **視点の回転** | **注視点の移動** | **ズーム** | ズーム |
| 通常 | （空き） | （空き） | （空き） | ズーム |
| ペイントモード | 塗る | （空き） | 消す | ズーム |
| **L を押しながら** | **ライトの向き** | （空き） | （空き） | ズーム |

**視点操作は Alt を押している間だけ**。Maya と同じ割り当てにしてある。
モードによらず常に同じ操作で視点を動かせるので、
「いまペイント中かどうか」を意識せずに済む。

**Alt なしのドラッグは空けてある。** 選択や範囲選択を入れる場所として取っておく。
ペイントモードのときだけブラシが受け取る。

- Alt + 右ドラッグは**右へ引くと寄る**。縦の動きは見ない（斜めに引いたときに暴れるため）。
  ズームは距離に対する比で効かせる（`Camera::Dolly` がホイールと同じ経路へ流す）。
  そうしないと遠くにいるときだけ極端に速くなる。
- **L + 左ドラッグはブラシと視点より優先する。** 横で方位角、縦で仰角
  （0.25 度 / ピクセル）。**Alt は付けない**（Alt を押している間は視点操作になる）。

モードでビューポートの操作を変えるときは、この表を必ず更新する。

#### キー

| キー | 動作 |
| --- | --- |
| `F` | 注視点をメッシュの中心へ戻す。距離と角度は変えない |
| `A` | 注視点を戻したうえで、メッシュ全体が収まる距離まで引く |

DCC の「選択をフレーム / 全体をフレーム」に倣った割り当て。
このアプリはメッシュが 1 つで選択の概念が無いため、
**F は中心へ戻すだけ、A は距離も合わせる**という分け方にしてある。

- **修飾キーは付けない。** Ctrl は数値の直接入力、Alt は軌道で使っている。
- **カーソルがビューポートの上にあるときだけ効かせる。**
- **テキスト入力中は無視する**（`io.WantTextInput`）。
  レイヤー名を打っている最中に視点が飛ばないようにするため。

収める距離は `radius / sin(画角 / 2)` に余白 8% を掛けたもの。
**画角は縦横のうち狭い方**を使う。広い方に合わせると狭い側からはみ出す。
包む球の半径は `PreviewRenderer::BoundingRadius()` が形状ごとに返し、
ディスプレイスメントの押し出し分（`変位量 * 0.5`）を足してある。

## 7.5 通知トースト

画面右下へ積み上げて出す通知（`ui::ToastQueue`）。

- **使いどころは「結果をその場で知らせたいが、手を止めさせるほどではない」もの。**
  スクリーンショットの保存など。**エラーはステータスバーとログへ流す**（下の §8）。
  トーストは消えるので、後から追えないと困るものを載せない。
- 位置は右下から上へ積む。同時に出すのは 4 件まで。
- 約 6 秒で薄くなって消える。**マウスを乗せている間は消えない**（読み終わる前に消さない）。
- 保存先を渡した通知は、左クリックでエクスプローラを開いてそのファイルを選択する。
  右クリックは開かずに閉じる。開けることは本文へ明示する
  （「クリックで保存先を開く」）。書いていない機能は無いのと同じ。
- **枠にアクセント色を使わない。** 通常の `Border` にする（§4 のとおり、
  アクセントはチェック / 既定値から変わっている印 / ドラッグ先だけ）。
- **他のウィンドウより後に描く。** 先に描くと後から出したウィンドウの下に隠れる。
- **スクリーンショットを撮るフレームには描かない。** 直前の通知が写り込む。

## 8. 見た目の確認

**画面キャプチャに頼らない。** 他ウィンドウを掴んだり、DPI の違いで縮んだ絵になる。

```
terrain_graph.exe --screenshot-ui <path> --screenshot-frame 20
```

`--screenshot-ui` はバックバッファ（UI 込み）を PNG に書き出して終了する。
ビューポートの中身だけでよければ `--screenshot` を使う。

UI を変えたら、**必ずこれで 1 枚撮って目視する。** 撮っていない場合は報告にそう書く。

## 9. 新しい UI を足すときのチェックリスト

- [ ] 既存の `Property*` ヘルパーで表現できないか検討したか
- [ ] ウィジェット幅を明示し、親いっぱいに伸ばしていないか
- [ ] 幅は 2 章の表の値のどれかに一致しているか

- [ ] 色を直書きしていないか。必要ならテーマ側へ足したか
- [ ] パネルを追加したなら、`BuildDefaultLayout()` と 1 章の表に足し、ドックスペース ID の版を上げたか
- [ ] ビューポートの操作を変えたなら、7 章の表と README を更新したか

- [ ] `--screenshot-ui` で 1 枚撮って目視したか
