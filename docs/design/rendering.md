# rendering — PBR プレビューの設計

作成日時: 2026-08-31 12:09
更新日時: 2026-09-04 16:45

`src/renderer/` の設計方針。M2a（直接光）と M2b（IBL）で確定し、
M4b でマテリアル UV バッファを足した。

## 描画の流れ

```
シーンカラー(RGBA16F, 線形) + マテリアル UV(RGBA16F) + 深度(D32)
    ↓  メッシュ描画（GGX 直接光 + IBL。露出は掛けない。MRT で UV も書く）
    ↓  スカイボックス（深度書き込みなし、LESS_EQUAL で残った画素を埋める）
    ↓                （UV バッファには書かないので、シーンカラーだけ束ね直す）
シーンカラー
    ↓  トーンマップパス（コンピュート）: 露出 → トーンマップ → sRGB
表示用テクスチャ(RGBA8_UNORM)
    ↓
ImGui のビューポートパネルへ表示
```

**シェーディングは絶対放射輝度のまま出力し、露出はトーンマップパスでのみ掛ける。**
こうすることで、ライトの照度（lux）とカメラの露出設定を独立に扱える。

## マテリアル UV バッファ

メッシュ描画は 2 枚目のレンダーターゲットへ `frac(uv * materialUvScale)` と
被覆フラグを書き出す。ペイントのブラシが
「画面のこの画素はマテリアルのどこか」を引くために使う。

- **スカイボックスは 1 枚目だけに描く。** PSO のレンダーターゲット数が変わるため、
  メッシュのあとに `OMSetRenderTargets` でシーンカラーだけを束ね直す。
- **クリア値はリソース生成時の値と揃える。** UV バッファは被覆 0 でクリアするので、
  `TextureDesc::clearColor` のアルファも 0 にしてある。ずれるとデバッグレイヤーが警告する。
- 用途と精度の理由は [compositing.md](compositing.md) のペイントマスクの節にある。

## プレビューのジオメトリは平面だけ

**メッシュは平面 1 種類**（`MakePlane`）。地形をオーサリングするツールなので、
球やキューブに素材を貼って眺める用途は持たない。プレビュー設定の「形状」と
「UV スケール」も無くした（合成結果は平面 1 枚に**等倍で**貼る）。

- 合成結果を読むサンプラは**常にクランプ**。wrap だと UV 端（0 / 1）の
  バイリニア補間が反対側の端と混ざり、**地形の縁が反対側の高さへ引っ張られて
  壁が立つ**（グラデーションのハイトで顕著。実際に踏んだ）。
- 素材のタイリングはレイヤーの `UV スケール`（合成時）で行う。
  メッシュへ貼る側では並べない。

シェイプノードがハイトマップ**そのもの**を読むときのクランプ
（合成時。`CompositeLayer.hlsl`）とは別の話で、両方が要る。

## 接空間（タンジェント）

シェーダは従法線を `cross(normal, tangent) * tangent.w` で作る。
**w は「その面の V の向き（dP/dv）と合うか」で決める。**

- 平面: `T = +X`、`cross((0,1,0),(1,0,0)) = -Z` に対して `dP/dv = +Z`
  なので **`w = -1`**。+1 のままだと接空間法線の Y が世界の -Z へ載り、
  **Z 方向だけ陰影が反転する**（形は正しいのに、光が反対から来ているように見える）。
  実際に踏んだ。ランプ状のハイトを作り、光を +Z / -Z から当てて
  明るさを測ると一発で分かる。
- 球とキューブ（メッシュとしては廃止済み）は `w = +1` で dP/dv と一致していた。

合成が作る法線（`CompositeLayer.hlsl`）は **緑 = +V の向き（DirectX 規約）**。
素材の法線マップが OpenGL 規約（緑 = -V）だと V 方向（平面では世界の Z）の
陰影が逆になるので、**マテリアルごとに「緑を反転」**を持つ（既定は入 = OpenGL）。
Megascans など手元の素材がその規約のため。

**この食い違いは測って確かめられる。** 同じ地形・同じ光で
「素材の法線マップで陰影を付けた絵」と「同じ素材のハイトから法線を作った絵」を
撮り、`az0 − az180` の差分どうしの相関を取る。向きが合っていれば正、
逆なら負になる（実測: 直す前 Z = −0.77 / X = +0.77 → 直した後 Z = +0.77）。

シェイプノードがハイトマップ**そのもの**を読むときのクランプ
（合成時。`CompositeLayer.hlsl`）とは別の話で、両方が要る。
片方だけだと、合成結果の端にもう一度 wrap の混ざりが出る。

## 露出とトーンマップ

物理カメラベースで統一する。

```
EV100    = log2(N^2 / t) - log2(ISO / 100)
exposure = 1 / (1.2 * 2^EV100)
```

- マニュアル露出（絞り / シャッター / ISO、または EV 直接指定）。
- トーンマップは ACES（Stephen Hill のフィット）を既定とし、Reinhard となしを切り替えられる。
- 環境の輝度は絶対値（cd/m^2 相当）で持ち、露出と独立に扱う。

参考値。晴天の直射日光がおよそ 100000 lux、晴天の空が 4000〜15000 cd/m^2。
手続き的な空の既定値はこれに合わせてある。暗くしすぎると日中の露出で黒く潰れる。

### HDRI は較正してから使う

**HDRI ファイルは絶対輝度で較正されていない。** Radiance 形式は `EXPOSURE=` ヘッダで
較正値を持てるが、合成ツールが出すものはまず持たない（`stb_image` も読み飛ばす）。
実測すると、Poly Haven 系の屋外 HDRI は**空が 0.15〜0.2** 程度だった。

生の値のまま使うと、日中の露出（EV100 ≈ 16、露出係数 1.3e-5）で
`0.2 x 1.3e-5 = 0.0000026` となり**真っ黒になる**。3 桁以上ずれている。

そこで、**読み込み時に空の代表輝度を測り、指定した cd/m^2 に合わせる倍率**を掛ける。

- 分母は `MedianSkyLuminance()`（上側 40% の**中央値**）。
  平均だと太陽に引きずられる（実測で最大は空の 2000 倍以上あった）。
- 分子は天球アセットの `空の輝度`（既定 12000 cd/m^2 = 晴天）。
- **倍率そのものをユーザーに指定させない。** ファイルによって空の値が違うので、
  同じ倍率でも結果が変わってしまう。「空が何 cd/m^2 か」ならどのファイルでも同じ意味になる。
- **較正値は天球アセット（`renderer::SkyDefinition`）が持つ。**
  ファイルごとに違う値なので、レンダラに 1 つ持つと HDRI を差し替えたときに
  前のファイル用の値が残ってしまう。倍率の式は `SkyLuminanceScale()` に集約し、
  環境本体と天球のサムネイル（`SkyThumbnail.hlsl`）で同じものを使う。

**画像内の比は本物なので、定数倍しても物理的な関係は壊れない。**
足りないのは絶対値の基準だけで、それをここで与えている。

手続き的な空は `EnvSky.hlsl` が最初から cd/m^2 で書き込むため、較正は掛けない（倍率 1.0）。

### 被写界深度

**トーンマップの前、線形 HDR のシーンカラーに対して掛ける**（`DepthOfField.hlsl`）。
露出を掛けた後だと明るい点が飽和してから広がり、玉ボケの芯が白く潰れる。
HDR のまま混ぜれば明るいサンプルがそのまま強く出るので、
**ハイライト強調のような細工が要らない。**

**レンズの値を被写界深度のために増やさない。**
焦点距離はカメラの画角から（`FocalLengthFromFovY`）、F 値も**カメラの節**から取る
（実体は `ExposureSettings::aperture`。露出とボケは同じ 1 つの絞りで決まる）。
同じ意味の値をもう一組持つと、露出とレンズが食い違った絵になる。
EV を直接指定しているときは露出の節に絞りの行が出ないため、
被写界深度の節から同じ `aperture` を編集できるようにしてある。

錯乱円は現実の式そのまま。

```
CoC(直径) = A * f * (d - D) / (d * (D - f))     A = f / N（絞りの実口径）
半径(px)  = CoC / センサー高さ * 画像の高さ / 2
```

深度からカメラ前方距離を戻すのは `XMMatrixPerspectiveFovRH` の逆算で、
`near * far / (far - depth * (far - near))`。スカイボックスは深度を書かないので、
背景はクリア値の far として扱われ、いちばん強くぼける。

**ミニチュアの縮尺（`miniatureScale`）でシーンの距離を縮める。** 既定は 1（実物大）。

錯乱円は距離に反比例するので、**実寸のまま 2km の地形を撮るとほぼ全部が無限遠**に
なり、絞りを開けても 1 画素もボケない。既定（29mm・F16、ピント 2000m）で
1000m の所の錯乱円は **0.0006 画素**。F1.8 まで開けて誇張を上限の 16 倍にしても
0.08 画素で、1 画素に届かない。誇張の倍率では原理的に救えない。

縮尺は**シーンの距離だけ**に掛ける（`sceneScale = 1 / miniatureScale`）。
レンズの側（焦点距離・絞り・センサー）は現実のままなので、
UI の単位も現実のカメラのまま保てる。1:1000 なら「2km の地形を 2m の模型として撮る」
計算になり、素材（2m 角）を撮ったときと同じ効き方になる。
terrain-editor は 0.001 を決め打ちし、その上に 1〜50 倍の `Miniature Scale` を
掛けていた。こちらは 1 つの縮尺にまとめてある。

実測（2km の地形、カメラ距離 2534m、F2.8。隣接画素の差で細部の量を測ったもの）:

| 縮尺 | 奥（ピント付近） | 手前（ピント外） |
| --- | --- | --- |
| 切 | 10.25 | 6.55 |
| 1 : 1000 | 10.25 | 6.54 |
| 1 : 3000 | 10.24 | 5.58 |
| 1 : 10000 | 10.04 | **1.62** |

引きで見る地形では 3000〜10000 あたりが実用域。

**ボケの強さに誇張の倍率（`blurScale`）も持つ。** 既定は 1（現実どおり）。

**これはスケールの補正ではない。** 2m 角の地面を 3.2m の距離から広角で撮れば、
現実のカメラでも全域にピントが合う（29mm・F1.8 で錯乱円が 1 画素に届かない）。
物理的に正しくても素材の見せ方としては物足りないことがあるので、
物理の関係を保ったまま量だけ持ち上げる係数として掛ける。
倍率を使わずにボケを出したいなら、現実と同じく望遠へ寄せればよい
（100mm・F1.8 なら倍率 1 のまま半径 10 画素ほどになる）。

集め方は 1 パスの gather 近似。奥のボケは「自分の錯乱円のぶんだけ周りから集める」、
手前のボケは「相手の錯乱円がここまで届いているか」を上限半径まで探して集める。
**ピントが合っているサンプルの重みを落とす**ことで、
手前の輪郭が後ろのボケへ吸い込まれるのを抑えている。

未実装: 多段ブラー、ボケの分離（近景 / 遠景を別バッファで）、時間的な安定化。

**デバッグ表示のときは掛けない。** チャンネルの値そのものを見るための表示なので、
露出やトーンマップと同じ扱いにする。

### 背景のぼかし

`背景をぼかす` は**プリフィルタ済みキューブの粗いミップを引くだけ**で、追加のパスは無い。
IBL の寄与と陰影は変わらない（引くのは背景の描画だけ）。

**ミップ m はラフネス m / (段数 - 1) に対応する**（プリフィルタは 128px の 6 段）。
`kSkyboxBlurMip = 1.6` はおよそラフネス 0.32 で、空と地面の分かれ目や光の向きは
残るが、木立や建物の形は溶けて目に留まらなくなる。
**素材を見比べるときに背景が目移りの原因にならないこと**を優先している。

未実装: 自動露出（輝度ヒストグラムから EV を決めて時間補間）、AgX。

### 影（シャドウマップ）

ディレクショナルライトの影を落とす（`ライティング > 影`）。

- ライトから深度だけを 2048^2 の深度テクスチャへ描き、本描画で比較する。
  深度は `R32_TYPELESS` で作り、DSV は `D32_FLOAT`、SRV は `R32_FLOAT` を張る。
- 投影は**平行投影**。プレビューの被写体（半径 2.2 の範囲）だけを覆えばよい。
- **比較サンプラは使わない。** 普通の `Texture2D<float>` として読み、3x3 の
  ポイントサンプルを平均する。ルートシグネチャに比較サンプラを足さずに済む。
- 自己遮蔽（シャドウアクネ）対策は、傾きに応じて増やす下駄だけ。
  ライトに対して斜めなほど大きくする。
- **影は直接光にだけ掛ける。** 環境光（IBL）には掛けない。
- シャドウパスは本描画と**同じ頂点シェーダ・同じ分割**で描く。
  形が違うと自分の影が自分に落ちて縞になる。

### テセレーション

`プレビュー設定 > テセレーション`。**画面上の辺の長さ**で分割量を決める。

- ハルシェーダが各辺を画面へ投影し、1 辺がおよそ 10 ピクセルに収まるよう
  分割数を決める（上限は UI の `分割の上限`）。**細かいメッシュではそのまま 1 になり、
  寄って 1 辺が伸びたときだけ細かく割る。**
- ドメインシェーダで重心座標の補間と**ディスプレイスメント**を行う。
  式は頂点シェーダと共通の `ApplyDisplacement`（`MeshPbr.hlsl`）で、
  どちらも**ワールド空間**で適用する。別々に書くと、モデル行列を入れたときに
  テセレーションの ON / OFF で形が変わってしまう。
- **分割量はカメラから見た値で決め、シャドウパスでも同じ値を使う**
  （`tessellationViewProjection`）。パスごとに分割が変わると形がずれて影が破綻する。
- 出力トポロジは `triangle_cw`。右手系 + `FrontCounterClockwise = TRUE` の組み合わせでは
  こちらが表になる。`triangle_ccw` にすると裏面だけが見えて真っ黒になる。

### ディスプレイスメント

合成した Height を**頂点で押し出して形状に反映する**（`変位量` が 0 なら何もしない）。

- 頂点シェーダが Height を `SampleLevel` で読み、法線方向へ `(h - 0.5) * 変位量` 動かす。
  **0.5 を基準にする**のは、全体が膨らんだり縮んだりしないようにするため。
- 頂点シェーダには微分が無いので `SampleLevel`（ミップ 0）を使う。
- **押し出せる細かさは頂点の密度で決まる。** 平面の分割数はプレビュー設定
  （`メッシュ分割`。256 / 512 / 1024）で、地形の一辺 ÷ 分割数 が 1 マスの大きさ。
  2048m の地形なら 256 分割で 8m、1024 分割で 2m。
  **これより細かい形は出ない**（法線には出るが、シルエットは動かない）。
  作り直しは GPU 待機を伴うのでフレームの外で行う（合成解像度と同じ作法）。
- **テセレーションは「画面上で辺が伸びたとき」しか割らない。**
  1 辺がおよそ 10px（`kTessellationTargetPixels`）になるよう分割量を決め、
  上限でクランプする。**地形全体を画面に入れた画角では 1 マスが 5〜8px しかなく、
  分割量は 1（＝割らない）になる。** 引きの絵の細かさは基本メッシュで決まり、
  テセレーションは寄ったときのためのもの、と考えるのが正しい。
- 形の細かさの上限はもう一段あって、**合成テクスチャの解像度**
  （2048m を 2048^2 で 1m/テクセル）。メッシュをそれより細かくしても増えない。
- **法線は作り直していない。** 合成の Normal はハイトの勾配から作っており、
  しかも**変位量と同じ実寸（m）で**作るので、押し出した形と必ず同じ凹凸を表す
  （[compositing.md](compositing.md) の「法線」）。変位量を変えると法線も同じだけ動く。
- テセレーション（HS/DS）を使うと、分割後の点でも同じ式で押し出される
  （上の「テセレーション」を参照）。

### 表示モード

ビューポートには合成したチャンネルをそのまま出せる（`renderer::DebugView`）。

- メッシュのピクセルシェーダが、シェーディングの代わりにチャンネルの値を書く。
- **ハイト（ローカル）** は、その場の起伏だけを見る表示。周り（半径 6 テクセル）の
  平均を引いて 0.5 中心へ伸ばす（`kLocalHeightGain`）。地形の標高差 600m の
  傾きに埋もれて見えない素材の凹凸を、ハイトマップを貼ったような見た目で確かめる。
- `TonemapPass` は `passthrough != 0` のとき**露出・トーンマップ・sRGB 変換を通さない**。
  データを見るための表示なので、値をそのまま画面へ出す。
- 背景（スカイボックス）も描かない。
- **法線はカメラ空間とワールド空間の 2 つ**（`DebugView::NormalView` / `NormalWorld`）。
  どちらも法線マップを当てたあとの向きで、空間だけが違う。カメラ空間は
  ビュー行列の上 3x3 を掛けるだけ（回転と平行移動しか無いので、これで向きが移る）。
- **クレイ（`DebugView::Clay`）だけは陰影を付ける表示**なので、
  シェーディングと同じ扱いにする（背景も被写界深度も露出もトーンマップも通す。
  `IsShadedView()` が両者をまとめる）。
  - 合成の色 / 法線 / サーフェスを読まず、単色マテリアル（`MaterialSettings`）で塗る。
    **形（ディスプレイスメント）は据え置き**なので、メッシュの確認に使える。
  - **法線は画面微分（`ddx` / `ddy`）から面の向きを起こす。** 平面メッシュの頂点法線は
    押し出しても上を向いたままで、そのまま塗ると形が出ない。面から起こせば
    実際に描かれた三角形の向きになり、**分割の粗さがそのまま面として見える**。
    法線マップが形を補っていない、本当のポリゴンの形が分かる。
- C++ の `DebugView` と HLSL の `TG_VIEW_*` は並びを一致させること。

### マスクの飽和に斜線

マスクをプレビューしているとき、**0 か 1 に張り付いた所へ 1px 幅・4px 周期の
斜線**を中間の灰色で重ねる（プレビュー設定の `マスクの飽和に斜線`。既定は切）。
terrain-editor の GrayscaleHatched を移したもの。

- 濃淡が付いている所と、上限に当たって潰れた所は**絵では見分けが付かない**。
  「マスクを反転しても絵が変わらない」といった混乱の原因がこれで見える。
- マスクのプレビューは「0 の色」と「1 の色」の間を塗るだけなので、
  **ベースカラーから元のマスクへ戻せる**（`compositor::kMaskPreviewLow / High`）。
  塗る側と読む側が同じ定数を使うよう 1 か所にまとめてある。
- 画素の座標は **x と y を別々に切り捨ててから足す**。float のまま足して
  丸めると桁落ちで縞の位相が揺れ、太いバンドに見える。
- 描画側は「いまマスクを見ているか」を知らないので、
  `PreviewRenderer::MaskPreviewActive()` へ Application が毎フレーム写す。

### レンズ（画角）

**UI では画角を焦点距離 (mm) で指定する。** 露出を絞り / シャッター / ISO で
決めている以上、レンズだけラジアンで扱うと言葉が揃わない。

```
焦点距離 = (センサー高 / 2) / tan(縦画角 / 2)      センサー高 = 24mm（35mm フルサイズ）
```

- 内部（`Camera::FovY()`、プロジェクトファイル）は**ラジアンのまま**持つ。
  換算は `renderer::FocalLengthFromFovY` / `FovYFromFocalLength` で UI 側だけが行う。
- 縦画角を基準にする。ビューポートの縦横比は表示サイズで変わるため、
  横を基準にすると同じレンズでも画角が変わってしまう。
- 既定は 29mm（= 縦 45 度）。

## IBL

分割和近似。生成はすべてコンピュートで、`Device::ExecuteImmediate` により
環境の読み込み時に一度だけ走る。

```
equirect (RGBA32F)
    ↓  EnvEquirectToCube
キューブマップ 256^2 (RGBA16F, ミップ付き)
    ↓  EnvDownsample（ミップ連鎖）
    ├→ EnvIrradiance   → irradiance キューブ 32^2
    └→ EnvPrefilter    → プリフィルタ済みキューブ 128^2（ラフネス別に 6 ミップ）
EnvBrdfLut → 環境 BRDF の LUT 256^2 (RG16F)
```

- **irradiance マップには `E / pi`**（余弦重み付きの平均放射輝度）を格納する。
  シェーディング側は `diffuseColor` を掛けるだけでよい。pi を二重に割らないこと。
- プリフィルタはサンプルの立体角に応じたミップから引き、ファイアフライを抑える。
  そのためにキューブのミップ連鎖が要る。
- **手続き的な空に太陽は入れない。** 太陽はディレクショナルライトで扱う。
  環境マップに入れると二重計上になり、256^2 のキューブでは
  エイリアスとファイアフライの原因になる。

キューブマップの面の並びは D3D の規約に従う（0: +X, 1: -X, 2: +Y, 3: -Y, 4: +Z, 5: -Z）。

## ラフネスの下限

知覚ラフネスは全経路で **0.045 を下限**にクランプする
（`Brdf.hlsli` の `kMinPerceptualRoughness`）。

- 適用箇所: 直接光（`MeshPbr`）、サムネイル（`MaterialThumbnail`）、
  BRDF LUT の生成（`EnvBrdfLut`）。
- 理由は 2 つ。
  1. 0 に近づくと GGX の D 項が発散し、RGBA16F のシーンカラーに Inf が出る
     （half の上限 65504 を超える）。
  2. `alpha^2 = roughness^4` が fp16 で表現できる範囲を割って 0 に潰れる。
     0.045 は `0.045^4 ≒ 4.1e-6` で、fp16 の正規最小値（6.1e-5）は割るが
     非正規域で表現でき、演算が 32bit の限り安全に持ち上がる値として
     Filament / Frostbite が採用している。**独自の値を作らず、これに合わせる。**
- プリフィルタ済みキューブのミップ 0 だけは例外で、**roughness = 0 の鏡面**を
  そのまま焼く（`EnvPrefilter` の特別扱い）。シェーディング側は下限未満の
  ラフネスを参照しないため、ミップ 0 はミップ 0.36 付近からの三線形補間の
  一端としてしか使われない。

## フレームレートの上限

`ウィンドウ > 設定` で決める。実装は `core::FrameLimiter`。

**背面（非アクティブ）のときは別の上限を使う。** 既定は 10fps。
見えていない絵に GPU を回し続ける理由がない。**完全には止めない**のは、
シェーダのホットリロードや進行中の処理を生かしたまま、
外から様子を見られるようにするため。最小化のときだけは `WaitMessage` で完全に休む。

- **「長く眠る」のではなく「描くのを間引く」。** フレームの間ずっとブロックすると、
  その間メッセージを汲めず、**OS からは無反応なウィンドウに見える**
  （クリックしても固まったように感じ、しばらくして戻る）。
  フレームループの頭で `ShouldRender()` を呼び、偽なら描かずにメッセージ処理へ戻る。
- **1 回に眠るのは 2ms まで。** これがそのまま入力への反応の遅れになる。
  10fps に落としていても 1 秒に 500 回しか起きないので、CPU はほぼ使わない。
- **眠るのは `Sleep` ではなく高分解能の待機タイマー**
  （`CREATE_WAITABLE_TIMER_HIGH_RESOLUTION`）。既定の `Sleep` は 15ms 刻みで、
  2ms を頼んでも 15ms 眠ってしまう。
  `timeBeginPeriod` でプロセス全体の分解能を上げる方法は他のアプリにも影響するので採らない。
- **前面と背面が切り替わった時点で締め切りを捨てる。** 積み上げた締め切りが残っていると、
  戻った直後の 1 フレームだけ待たされる。
- 次のフレームの時刻は**前回の締め切りから積む**（平均のレートがずれない）。
  ただし大きく遅れたときは積み直す。読み込みで数秒止まった後に、
  取り返そうとして何フレームも待たずに走るのを防ぐ。
- **開発用オプション（`--screenshot` / `--export` など）が動いている間は落とさない。**
  起動直後はウィンドウが背面のことがあり、待つと書き出しが遅くなる。
- 待ち時間はスクリーンショットに写らないので、`tests/FrameLimiterTests.cpp` で押さえる。

## ワールドの単位

**ワールドの 1 単位を 1m とする。**

長らく単位を決める必要が無かった（平行光は lux、露出はカメラ側だけで、
距離に依存する物理が無かった）が、被写界深度が距離を実寸として扱うので確定させた。

根拠は**平面のプレビューメッシュ**。頂点データの一辺 `kPlaneMeshSize = 2.0` は
**Megascans のサーフェスが 2m 角で作られているものが多い**ことに合わせたもので、
実際の大きさは `PlaneSize()`（m）へモデル行列で広げる。
カメラの既定距離 3.2 は 3.2m。

### メートルなのはジオメトリだけ

**テクスチャは無次元のまま**にしてある。レイヤーの UV スケールは
「何回並べるか」で、`1 UV が何 m か`は決めない。素材のタイリングは実寸に
紐づけずに使いたいことが多く、決めてしまうと素材を差し替えるたびに換算が要る。

グラフが持つハイトも 0〜1 の正規化値で、メートルは持たない
（[node-graph.md](node-graph.md)）。**正規化ハイト + 高さレンジ**という
持ち方は、16bit ハイトマップの受け渡しでも使われている形。
実寸へ変換するのは表示のときで、変位量（m）がその役目を負う。

### 被写体の大きさに追従するもの

平面のサイズは 2m 固定ではなく `PreviewRenderer::PlaneSize()`（m）で変えられる。
素材のプレビュー（2m 角）から地形（2km 角）まで、これ 1 つで切り替える。
**グラフに Heightmap ノードがあるときは、その実寸（`graph::TerrainScale`）に従う**
（決める場所を 1 つにするため。[node-graph.md](node-graph.md)）。
メッシュは 2m（`kPlaneMeshSize`）で作ったまま、**モデル行列の拡大で実サイズにする**
（作り直しの GPU 待機を避けるため。Y は拡大しない。高さは変位量が世界空間で足す）。

これに合わせて、**被写体の大きさを前提にしていた固定値をすべて比例させた**。
固定のままだと 2km の地形では「100m までしか引けない」「200m 先が消える」
「4.4m 角の影の枠から完全にはみ出す」となって使えない。

| 値 | 基準（半径 1.41 = 2m 平面） | 決め方 |
| --- | --- | --- |
| 軌道の距離の下限 / 上限 | 0.1m / 100m | 半径に比例 |
| クリップ面（近 / 遠） | 0.02m / 200m | 半径に比例（比は一定なので深度の精度は変わらない） |
| 影の平行投影の範囲 / 光源の距離 | 2.2m / 6.0m | 半径に比例 |
| 変位量の上限 | 1.0m | 平面の辺の半分 |

**倍率は 1 を下回らせない。** 基準より小さい被写体で範囲まで狭めると、
既存のプロジェクトの見え方が変わってしまう（球や 2m 平面は従来と 1 ピクセルも変えない）。

カメラの `SetState` は**シーンの大きさで距離を丸めない**。平面のサイズを読む前に
カメラを復元することがあり、丸めると地形スケールの距離が素材スケールの上限へ潰れる。
歯止めは絶対値の範囲だけにして、丸めは次の Dolly / Frame に任せている。

## 座標系

**右手系 Y-up。** X が右、Y が上、Z が手前（画面から見て奥が -Z）。
terrain-editor と同じ規約に揃えてある。

- ビュー行列は `XMMatrixLookAtRH`、投影は `XMMatrixPerspectiveFovRH`。
  **LH 版を使うと画面が左右反転し、+X が画面左に出る。**
  対称なプリミティブでは気づきにくいので、規約側で固定しておく。
- 深度の範囲は RH 版でも `[0, 1]`（D3D の規約）。クリアは 1.0、比較は LESS_EQUAL。
- カメラの基底は `右 = 前 × 上`。`Camera::Basis()` がビュー行列と同じ基底を返す。
- ライトの方位角は 0 度が +Z、90 度が +X。仰角は +Y 方向。

**外向きの面は画面上で反時計回りに見える。** ラスタライザは
`FrontCounterClockwise = TRUE` で固定する。LH のままの設定
（`FALSE`）を残すと、すべての面が裏面判定になって消える。

ワールド空間そのものは手系に依らない。キューブマップのサンプルも
法線・タンジェントもワールド空間の向きで扱うので、ここは変わらない。

## 行列の規約

DirectXMath は行ベクトル規約、HLSL の定数バッファ内の行列は既定で列優先。
`XMMATRIX` をそのまま積むと HLSL 側では転置として解釈されるため、
`mul(matrix, vector)` が意図どおりに動く。**転置は入れない。**

法線行列だけは `(M^-1)^T` が必要なため、`XMMatrixTranspose(XMMatrixInverse(...))` を積む。

## メッシュ

球 / 平面 / キューブをコード生成する。頂点は position / normal / tangent / uv。

**球だけ添字の並べ方が逆になる。** 球は行方向が -Y、列方向が経度なので、
平面やキューブと同じ並べ方をすると外向き面が裏面判定になる。
誤ると遠側の内面が見え、暗く巨大な面が映る。
生成後はどれも「外向き = 反時計回り」に揃うので、カリングの設定は 1 つで足りる。

## 高 DPI

`ImGui_ImplWin32_EnableDpiAwareness()` はウィンドウ生成前に呼ぶ。
呼ばないと Windows にウィンドウごと拡大され、描画解像度が半分になってぼやける。
テクスチャを等倍で見たいツールとしては致命的。

- フォントサイズとスタイルを DPI スケールで拡大する。
- 初期ウィンドウサイズも DPI で拡大し、`Window::Create` で実際に載ったモニタの
  作業領域に収める。`SPI_GETWORKAREA` はプライマリモニタしか見ないので使わない。

## ImGui のビューポート

**`ImGui::Image` は入力を消費しない。** 画像の上でドラッグすると
「ウィンドウの余白のドラッグ」と解釈され、パネルごと動いてしまう。
同じ矩形に `InvisibleButton` を重ねてドラッグを受け止めること。
併せて `io.ConfigWindowsMoveFromTitleBarOnly = true` を入れてある。

画像はテクスチャの実サイズではなくコンテンツ領域に合わせて描く。
実サイズで描くとパネルからはみ出し、スクロールバーの出入りで要求サイズが振動する。
レンダーターゲットの作り直しは 1 フレーム遅れる。
