# プロジェクトルートと共有アセット

作成日時: 2026-09-13 20:32
更新日時: 2026-09-14 11:45

通常起動は新規シーンから開始する。`--project`で明示指定した場合のみ起動時にシーンを読み込む。ルートのみを開いた場合も新規シーンにする。既存のstartupSceneフィールドは互換性のため保持するが、自動読み込みには使わない。

## 所有関係

プロジェクトは実フォルダをルートに持つ。開発環境では`data/`（`TG_DATA_DIR`で変更可能）を初期値とし、`--root`または「ルートフォルダを開く」で変更する。ルート直下の`project.tgproj`は`terrain-graph.workspace`版1のJSONで、プロジェクトIDと開始シーンを保持する。既存の同名ファイルが別形式なら上書きせず開く操作を中止する。

シーンは`.tgscene`（`terrain-graph.scene`版1）としてルート内の任意の場所に保存する。保存ダイアログの初期値は`Scenes/`。グラフ、プレビュー設定、使用中の天球（1 つ。`skies` 配列は互換のため残し、先頭だけを使う）、ペイントマスクの参照をシーンに保持する。ペイントは引き続き`<シーン名>.assets/`に保存し、キャッシュとは区別する。

画像とFBXは元のファイルを使う。ルート内のファイルはコピーせず、外部から読み込むファイルは選択フォルダへコピーする。旧シーンの保存時に外部参照を取り込む場合は`Imported/`へコピーする。再配布できない素材をリポジトリの`assets/`へ入れない。

## アセット形式

| 拡張子 | format | 内容 |
| --- | --- | --- |
| `.tgmat` | `terrain-graph.material-asset` | 名前、PBRパラメータ、画像のID参照 |
| `.tgsky` | `terrain-graph.sky-asset` | 名前、大気散乱、HDRIのID参照、環境光倍率 |
| `.tgmodel` | `terrain-graph.model-asset` | 名前、FBXのID参照、マテリアルスロットのID参照 |
| 元ファイル名`.meta` | `terrain-graph.source` | 元画像・FBXの固定ID |

すべてUTF-8 JSON、版1。マテリアル・天球・モデル設定は編集内容の原本であり、再生成可能なキャッシュではない。フォルダ分類は強制しない。旧シーンから初めて分離するときだけ`Materials/`、`Skies/`、`Models/`を使う。

モデル設定はFBXのサイドカーへ埋め込まず、独立した`.tgmodel`にした。同一FBXに異なるマテリアル割り当てを持つ旧シーンがあるため、設定の異なるモデルを安全に分離するためである。

参照は`{"uid":"固定ID","path":"ルート相対パス"}`。ネイティブ形式は内部にIDを持ち、元画像・FBXは隣の`.meta`にIDを保存する。ルート走査でIDから現在のパスを解決し、IDが見つからない場合に同名の別アセットへ黙って付け替えない。重複IDもエラーにする。原本をエクスプローラで移動するときは`.meta`も一緒に移動する。ネイティブ形式をエクスプローラで単純コピーするとIDも重複するので注意する。

この分離は[Unityのアセットメタデータ](https://docs.unity.cn/Manual/AssetMetadata.html)および[GodotのUID](https://godotengine.org/article/uid-changes-coming-to-godot-4-4/)を参考にする。シーン内のグラフは既存の整数IDを保ち、シーン内の参照表を介して永続IDへ接続する。GPU用の実行時IDと永続IDを混同しない。

## 保存と読み込み

「保存」はシーンと読み込み済み共有アセットを保存する。まだファイルを持たないアセットは、同じ種類・同じ中身（名前を含み、IDを除く）のファイルが既にあればそれを使い、そのIDのまま上書きする。中身の同じアセットが保存のたびに「名前_1」「名前_2」と増えないようにするため。共有アセットだけを保存するボタンは置かない（シーン保存で必ず一緒に保存され、作成・読み込み直後は自動で保存されるため）。新規マテリアル・天球は選択フォルダへ作成する。共有アセットを編集すると、それを参照する他シーンは次回読み込み時に更新された内容を使う。シーン切り替え前には保存・破棄・キャンセルを選べる。

旧`.tgproj`・`.mmproj`は既存の読み込み器で開く。通常の保存は別名の`.tgscene`へ行うため、移行元は残る。既存の持ち出し用`.tgmat`と新しい共有アセットはformatで区別する。同名の異なる旧マテリアルを名前だけで自動統合しない。

新シーンはアセットのJSONと依存参照を展開・検証してからGPU資源と現在の文書を置き換える。共有アセット欠落時は読み込みを中止し、現在の文書を保持する。画像そのものが欠け、メタデータが残る場合は既存のリンク切れ表示を使う。保存はファイル単位の一時ファイルと置換で保護する。複数ファイル全体を一括で巻き戻すトランザクションではない。

## UIと残る範囲

アセット帯は単一パネル。左に実フォルダのツリー、右にサブフォルダとアセットの84px格子を表示する。`.meta`とドットで始まる内部フォルダは隠す。ダブルクリックで読み込み・編集、モデルは従来どおりシングルクリックでプレビューする。読み込み済み画像とマテリアルは従来のドラッグペイロードを使用する。

現段階では明示的な「更新」で外部のファイル変更を取り込む。未読み込みの画像・共有マテリアル・共有天球・共有モデル・FBXは、表示範囲から1件ずつサムネイルを生成する。シーンと分離した読み込み領域を使い、最大128件をメモリに保持する。画像は縦横比を保った128px、マテリアル・天球は既存の球、モデルは既存のメッシュ描画を使う。「更新」はサムネイルも破棄し、失敗項目を再試行する。ファイル監視、検索・種類フィルタ、ブラウザ内の移動・改名・削除は後続とする。フォルダ自体はエクスプローラで整理できる。

## 履歴とサムネイル

履歴は`%LOCALAPPDATA%/terrain-graph/recent.json`の版2へ保存する。roots配列にルートのpathとscenes配列を持つ。ルート・シーンとも新しい順で最大10件、大文字小文字とパス表記差を正規化して重複を除く。版1のprojectsは、所属ルートを開いたときに移行し、未移行分は保持する。履歴の削除は履歴だけを変更する。

未読み込みアセットのサムネイルは`.terrain-graph/thumbnails/`へPNGと検証用JSONを保存する。相対パスから保存先を決め、生成形式の版・入力ファイル・参照素材の更新日時とサイズで有効性を判定する。メモリには最大128件を保持する。フォルダを開き直すか「更新」すると入力の変更を再判定する。モデルの照明・露出はシーンから独立した固定条件。ディスクキャッシュは削除しても再生成できる。現状、ディスク容量の自動整理とファイル監視は未対応。

シーンのサムネイルはキャッシュとは分け、ルート内の`.terrain-graph/scene-thumbnails/`に保存する。シーン保存時にsceneUidを付け、IDからファイル名を決める。同一保存先はIDを維持し、名前を付けて保存では新規IDにする。既存のID付きシーンは改名・移動しても画像を引き継ぐ。IDのない旧シーンは相対パスを使って暫定管理し、次回保存でID付き画像を作る。外部でIDごとシーンを複製した場合は同じ画像を指すため、別シーンを作る操作は名前を付けて保存を使う。

旧`<シーン名>.assets/thumbnail.png`はルートを開いたときに移行する。移行先が既にある場合は上書きせず旧画像も残す。空になった.assetsは取り除くが、ペイント等が残るフォルダは維持する。表示中のビューポートを縦横比を保って最大256pxへ縮小する処理は従来どおり。失敗してもシーン本体の保存は成功扱いとする。

## アセットファイルの削除

ブラウザの削除はシーン内ライブラリから外す操作とは別で、ファイル自体をルート内の`.terrain-graph/trash/DeletedAsset.../`へ退避する。対象と付随する.metaだけを移動し、restore.jsonへ元の相対パスを記録する。復元はこの記録を使ってエクスプローラで元の場所へ戻す。自動のごみ箱整理・復元UI・フォルダ削除は未対応。

確認前にルート内のシーン・共有アセット・旧プロジェクトのJSONを走査し、ID参照およびパス参照による直接参照元と、対象が参照する素材を列挙する。シーン画像とペイントフォルダも関連項目として表示するが削除しない。ルート外の参照元は検査範囲外。読めない文書やリンク等で検査が不完全な場合は削除を拒否する。

現在のシーンに読み込まれたアセット、開いているシーンとそのペイントファイルは削除を止める。確認後にも対象・.metaの更新状態と参照関係を再検査し、変化があれば再確認する。退避途中で失敗した場合は移動済みファイルを戻す。共有素材の連鎖削除、参照元文書の自動書き換えは行わない。アプリ外のエクスプローラ操作へ警告を出すことはできない。
