# compositing — レイヤー合成の設計

作成日時: 2026-08-31 12:09
更新日時: 2026-09-03 12:00

`src/compositor/` と `shaders/Composite*.hlsl` の設計方針。
M3a（合成エンジン）と M3b（テクスチャレイヤー）で確定し、M4 でマスク生成を足した。
このプロジェクトの中核。

## チャンネル定義

合成の対象チャンネルは以下に固定する（将来 Emissive / Opacity を追加可能な形にはしておく）。

| チャンネル | 意味 | 評価中のフォーマット |
| --- | --- | --- |
| BaseColor | リニア色 | R11G11B10_FLOAT |
| Normal | タンジェント空間法線 | R16G16_FLOAT（xy のみ保持、z は再構成） |
| Surface | Roughness / Metallic / AO をパック | R8G8B8A8_UNORM |
| Height | 高さ（合成の駆動値かつ Displacement） | R16_FLOAT |

評価器は上記 4 枚の UAV を出力とする。エクスポート時にここから任意のパッキングへ変換する。

レイヤーごとに書き込むチャンネルを選べる。ただし**一番下のレイヤーは下地なので
必ず全チャンネルを埋める**。そうしないと未初期化のテクセルが残る。

## 評価の流れ

各スレッドは自分のテクセルしか触らないため、出力 4 枚を UAV として
その場で読み書きしてよい。レイヤーごとに 1 ディスパッチし、間を UAV バリアで区切る。

```
レイヤー 0（下地・全チャンネルを直接書く）
    ↓ UAV バリア
レイヤー 1（下地を読み、ハイトブレンドの重みで合成して書き戻す）
    ↓ UAV バリア
...
```

## ハイトベースブレンド

レイヤー合成の重みは、マスク値そのものではなく「マスクで持ち上げた高さ」の比較で決める。

```hlsl
float HeightBlendWeight(float baseHeight, float layerHeight, float mask, float range)
{
    // 高さだけで決めた重み（起伏が拮抗する所で 0.5）
    const float t = saturate(0.5f + (layerHeight - baseHeight) / (2.0f * max(range, 1e-4f)));
    // マスクは被覆率。t を上下にずらす
    return saturate(t + (mask * 2.0f - 1.0f));
}
```

**マスクは被覆率、高さは境界の形。** 役割を分けてある。

- マスク 1.0 → 高さに関係なく全面を覆う。
- マスク 0.0 → 下地がそのまま残る。
- マスク 0.5 → 高さの大小がそのまま勝敗になる。
  このとき上のレイヤーの基準高さが**「溜まる水位」**として振る舞う。
- 中間のマスクは**そのレイヤーの起伏の高い所から順に**出る。
  マスク 0.3 なら「自分の凹凸のうち高いほう 3 割」が顔を出す、という効き方になる。

`range` は境界の柔らかさ。0 に近づけると硬い置き換え、
大きくすると高さの影響が薄れてマスク主体の合成に近づく。

> **2026-09-03 に変えた点。** 以前はマスクを高さと同じ土俵で競合させていた
> （`a = 下地 + (1 - mask)` と `b = レイヤー + mask` を比べる）。
> マスク 0 と 1 の結果は今と同じだが、**中間は 0.5 付近の狭いしきい値**
> （下地に沿わせたレイヤーで概ね 0.43〜0.58）として振る舞い、
> 0〜0.4 しか持たないマスク（堆積の厚みなど）がまったく絵に出なかった。
> シェイプが `weight = mask` なのとも食い違っていた。

## レイヤーの種類（M6）

**高さの合成規則はレイヤーの種類で決まる**（`LayerKind`）。Quixel Mixer の
Surface / Noise / Liquid に相当し、スタックは 1 本のまま、順序の意味も変えない。
種類はシェーダへ `TG_FLAG_KIND_*` のフラグで渡す。

| 種類 | 高さの規則 | 書くチャンネル |
| --- | --- | --- |
| サーフェス | 競合（`HeightBlendWeight`） | 選択可（既定は全部） |
| シェイプ | 加算して 0〜1 へ切り詰め | Normal / Height 固定 |
| リキッド | 水位より低い所を置き換え | 全部 |

### シェイプ（加算）

```
h' = saturate(h + (src - 0.5) * 起伏の強さ * マスク)
```

サーフェスの競合は置き換え（lerp）なので、大きな起伏を勝たせると下のレイヤーの
細部が重みぶん消える。加算なら周波数の違う起伏が単純に重なり、
**地形スケールの形と細かい表面が共存する**。

- `heightBase` は「全体の持ち上げ」と読み替える（0.5 で変化なし）。
  式の `(src - 0.5)` は実装上 `layerHeight - 0.5` で、`heightBase - 0.5` の
  定数項が持ち上げとして効く。
- **加算後は必ず 0〜1 へ切り詰める。** 高さ競合・高さ由来マスク・水位・
  PNG 書き出しがすべて 0〜1 を前提にしている。起伏の実寸（ワールドでの振幅）は
  ディスプレイスメントの強さが担うので、データ側のレンジを広げる意味がない。
  上限に張り付くと台地状のクリップが見えるが、これは起伏の強さを下げれば直る
  予測可能な挙動で、黙ってレンジが漂流するより良い。
- 法線は**下地を平坦化せずに** RNM で重ねるだけ
  （`ReorientNormal(下地, FlattenNormal(自分の勾配法線, マスク))`）。
  下地の細部を消さないのが加算の意味。
- BaseColor / Surface は書かない（評価器がチャンネルマスクを強制する）。
  ただし一番下に置かれた場合は下地なので、全チャンネルを定数で埋める。
- **ハイトマップはレイヤー直結のスロット（`MaterialLayer::heightTexture`）から読む。**
  シェイプはマテリアルを持たないため、マスクの画像と同じ「テクスチャ + チャンネル」を
  レイヤー側に持つ。マテリアルを割り当てたレイヤー（サーフェス）では
  マテリアルのハイトマップが優先され、このスロットは参照しない。
- **シェイプのハイトマップはクランプで読む。** 地形のハイトマップは
  「タイルしない 1 枚絵」で作られるので、wrap のままだと境界のバイリニア補間が
  反対側の端と混ざり、縁に壁や段差が出る。マテリアルのハイトマップは
  タイル素材なので wrap のまま（`SampleLayerHeight` がシェイプのフラグで分岐）。

### サーフェスの「下地に沿わせる」（Wrap to Underlying）

サーフェスの規則は置き換えなので、シェイプの上に被せると勝った領域の
大きな形が自分の基準高さで均されてしまう（「山の上の雪」で山頂が削れる）。
Mixer の **Wrap to Underlying** に相当するトグルで、コーティングに切り替えられる。

```
layerHeight' = 下地の高さ + (layerHeight - 0.5)
```

- 自分の高さを「下地 + 相対的な起伏」へ読み替えてから、**通常の競合
  （`HeightBlendWeight`）へそのまま流す**。専用の重み計算は持たない。
  勝った所の高さも下地基準なので、大きな形が保たれる。
- 基準の高さの 0.5 からのずれは、そのまま**被せ物の厚み**になる。
- Height は書いた後に 0〜1 へ切り詰める（下地 + 厚みで 1 を超えうる）。
- Normal は下地を平坦化せず RNM で重ねるだけ（シェイプと同じ分岐）。
  下地の大きな法線が生きていないと、ジオメトリは山なのに陰影が平坦になる。
- 一番下のレイヤーでは無効（沿わせる相手がいない）。
- Mixer の `preserve details` / `blur underlying` に相当するものはまだ無い。
  どちらも近傍参照のパスが要るので、必要になったら別途入れる。

### リキッド（絶対値の水位）

```
weight = マスク * smoothstep(0, フェザー, 水位 - 下地の高さ)
```

- `heightBase` を水位（絶対値）、`blendRange` をフェザー幅と読み替える。
  ハイトのソースは定数に固定（`layerHeight` = 水位）。
- **`HeightBlendWeight` を通さない。** 競合の遷移帯（幅 ≒ range）では下地の
  Height / Normal が水平面へ lerp で引っ張られ、水位を動かすたびに汀線周辺の
  地形が変形して見える。水位と下地の差だけから重みを決めれば、
  水が勝たない場所は重みが厳密に 0 で、**水位を動かしても下地は 1 テクセルも動かない**。
- `水位 - 下地の高さ` はそのまま**深さ**なので、吸収（深いほど濃い色）や
  汀線の濡れ表現を将来入れる場合はこの延長に置く。
- 水の質感の推奨値: ベースカラーはリニア `(0.01, 0.03, 0.035)` 程度の暗い青緑
  （水の拡散反射はほぼゼロで、赤が最も吸収される）、ラフネス 0.05〜0.1、
  メタリック 0（誘電体。反射を強くしたくてもメタリックは上げない）。

## Normal の合成は RNM

Normal だけは lerp してはいけない。Reoriented Normal Mapping で合成する。

```hlsl
float3 ReorientNormal(float3 base, float3 detail)
{
    const float3 t = base + float3(0.0f, 0.0f, 1.0f);
    const float3 u = detail * float3(-1.0f, -1.0f, 1.0f);
    return normalize(t * (dot(t, u) / max(t.z, 1e-5f)) - u);
}
```

RNM は本来「下地に細部を載せる」演算で、重みによる選択の演算ではない。
重み `t` に対しては次のように使う。

1. 下地を `1 - t` で平坦へ寄せる
2. レイヤー側を `t` で弱める
3. RNM で合成する

RNM は平坦な入力を恒等的に扱う（平坦な base なら detail をそのまま返し、
平坦な detail なら base をそのまま返す）ため、
`t = 0` で下地、`t = 1` でレイヤーそのものになる。端点が正確に一致する。

## レイヤーの入力

ハイトとマスクのソースは定数 / ノイズ / テクスチャから選ぶ。

| ソース | ハイト | マスク |
| --- | --- | --- |
| 定数 | `heightBase` | `constant` |
| ノイズ | `heightBase + (fbm - 0.5) * heightGain` | `constant + (fbm - 0.5) * amount` |
| テクスチャ | `heightBase + (tex.r - 0.5) * heightGain` | `constant * tex.r` |

ハイトはノイズの `amount` を使わない。ソースが何であれ `heightGain` が寄与の量を担う。

### ハイトの基準面を 0.5 に固定する理由

ハイトの式が `(src - 0.5)` と基準面を挟むのは、**基準の高さと起伏の強さを直交させる**ため。
`src` の平均が 0.5 なら、`heightGain` を動かしても平均の高さは `heightBase` から動かない。

- **基準の高さ** = そのレイヤーが座る高さ。下地との勝敗だけを決める
- **起伏の強さ** = その周りの振れ幅。勝敗には影響しない

基準面をマップ自身の平均にする案もあった（最小ミップの 1 テクセルが平均なので実質無料）が、
**採らなかった**。ディスプレイスメントマップは「中間グレーが変位ゼロ」という慣習で
オーサリングされるので、マップの 0.5 には作者の意図が入っている。平均で取り直すと
それを上書きしてしまう。goals.md の「業界標準に合わせる」に従い 0.5 固定とした。

副次的な利点として、0.5 は CPU 側でも分かるので、旧形式のプロジェクトを
`base' = base + 0.5 * gain` で**厳密に**移行できる（平均だと GPU 側にしか無く不可能）。

0.5 中心でないマップに当たった場合は、基準の高さで下駄を履かせて調整する。

この 0.5 は、ディスプレイスメント（`MeshPbr.hlsl` の `(height - 0.5) * displacementScale`）、
マスクのノイズ、曲率の平坦値と同じ基準で、プロジェクト全体で一貫している。

法線は法線テクスチャがあればそれを使い、無ければハイトの勾配から作る。

**勾配は実寸（m）で取る。強さのつまみは持たない。** これは地形をオーサリングする
ツールであって、テクスチャを作るツールではない。傾きは「その地形が実際に何度か」で
決まるべきで、見た目を合わせるための無次元の係数を挟む余地はない。

ハイト 0〜1 の全幅が標高差（m）、出力 UV 0〜1 が地形の一辺（m）なので、

```
d(高さ m) / d(距離 m) = d(height)/d(uv) * uvScale * (標高差 / 一辺)
```

を法線の xy に入れる（`CompositeLayer.hlsl` の `ComputeLayerNormal`）。
実寸は `MaterialStack::SizeMeters()` / `HeightMeters()` から来る
（出どころはグラフの Heightmap ノード。無ければプレビュー設定のジオメトリの値）。
テクセル差ではなく UV 単位の微分を取るので、合成解像度を変えても見た目は変わらない。

**結果として、法線とディスプレイスメントは必ず同じ形を表す。**
強さで法線だけ弱められた時代にあった「形と陰影が別物になる」ずれが無くなった。

**代わりに、`起伏の強さ` は「標高差に対する割合」として効く。**
一辺 2048m / 標高差 604m の地形にディテール素材を並べるなら、
2cm の凹凸は `0.6 / 604 ≒ 0.001` に相当する。素材のハイトマップを
そのまま強さ 1.0 で載せると、604m の起伏を数十 m 間隔で作ることになり、
砂利の粒が岩山の大きさになる。素材側の値は実寸に合わせて下げること。

## ハイトのぼかし（Heightmap Blur）

合成の途中でハイトをならす加工。`CompositeBlur.hlsl` と
`MaterialEvaluator::ApplyHeightBlur()`。参考にしたのは terrain-editor の
Heightmap Blur（CPU 実装）で、アルゴリズムは同じ**分離型ガウス**。

```
反復 × { 水平パス: Height → 作業用 / 垂直パス: 作業用 → Height（強さで混ぜる） }
最後に 1 回: ぼかした Height → Normal を作り直す
```

- 2 次元ガウスを 1 次元 × 2 回に分解する。計算量は O(n^2 × R)。
  重みは `w(x) = exp(-0.5 (x/σ)^2)`、`σ = 半径 × 0.5`。
  **重みはシェーダ内で作り、合計で正規化する**（カーネル配列を渡さない）。
- 端は clamp-to-edge。
- **元の高さと混ぜるのは垂直パスだけ。** 両方で混ぜると強さが 2 回掛かる。
- 反復を増やすと 1 回では届かない範囲まで広がる（実効半径はおよそ
  `半径 × sqrt(反復)`）。半径を大きくする方が速いので、反復は
  「効きを積む」ためのつまみとして使う。
- **近傍を読むので、1 パスを全タイル終えてから次のパスへ進む。**
  タイル優先で回すと、まだ書かれていない隣のタイルを読んで継ぎ目が出る
  （中間結果由来マスクと同じ制約）。作業用テクスチャは
  `MaterialTextureSet::scratch` をマスク生成と共用する。
- **法線を作り直す。** 合成の法線はレイヤーが自分のハイトソースから作るので、
  Height だけをぼかすと形と陰影が食い違う。ぼかした Height の実寸の勾配から
  作り直して合わせる（そのぶん、それより下で載せた素材の法線ディテールは消える。
  素材はブラーより後ろに繋ぐ）。
- 半径 1 テクセル未満、または強さ 0 のときはパスごと省く。

## 堆積（Sediment）

**可動な土砂**を重力で再分配する加工。terrain-editor の Sediment を移植した。
`CompositeSediment.hlsl` と `MaterialEvaluator::ApplySediment()`。

```
setup →（反復ごとに）供給 → 滑らせ（掃引 1 / 掃引 2）を macro × 安定化 回
     → 差分を Height へ足し戻す → 法線を作り直す
```

- **安息角（talus）を超えた落差だけが動く。** 角度は `粘性^2 × 80 度`
  （0.2 で約 3 度 = ほぼ平らな堆積、0.5 で 20 度）。terrain-editor と同じ曲線。
- **1 回の滑らせは 2 掃引に分ける。** 掃引 1 で各セルが 4 近傍へ出す量を
  `outgoing`（RGBA = 東西南北）へ書き、掃引 2 で「自分の流出 − 近傍が自分へ
  向けて出した量」を差し引く。こうしないと同じセルへ同時に書き込む。
- 割る数は「流す先の数 + 1」。1 回の適用で傾きが安息角へ収まる。
- **計算グリッドは合成解像度と別**（既定 512）。反復回数がそのまま効くうえ、
  土砂の再分配は大きなスケールの現象なので粗くてよい。
- **足し戻すのは差分だけ**（`基盤 + 土砂 − 元の高さ`）。粗いグリッドの結果で
  Height を置き換えると、合成解像度で作った細部が消えてしまう。
- **ただし積もった所では細部を埋める。** 厚み d だけ積もったなら、
  合成解像度の細部（粗いグリッドとの差）を `sign × max(|細部| − d, 0)` へ縮める。
  - 出っ張りの**頂上は動かない**（周りが d 上がるので相対的に d 低くなるだけ）。
  - 窪みは埋まり、厚みが細部の振れ幅を超えたら完全に平ら（＝解析グリッドの面）になる。
  - 出っ張りは何ももらわず窪みが 2d もらう形なので、細部の分布が上下対称なら
    平均は d のまま。**体積の帳尻が合うのでパラメータを持たない。**
  - 効果の実測（`data/sample.tgproj`。法線マップの隣接画素の差で測った面のざらつき）:
    堆積した所 **55.4 → 31.1**、堆積していない所 35.0 → 33.8。
    埋めていなかった頃は、土砂の上に下地の礫がそのまま出ていた。
- パラメータは m で持ち、評価器が正規化ハイト（0〜1）へ直す
  （安息角は `tan(角度) × セルの大きさ / 標高差`、供給量は `m / 標高差`）。
- ブラーと同じく**下地になれない**（`IsHeightOperationKind`）。
- **積もった厚みは Mask としても出せる**（`MaskOpKind::Sediment`）。
  厚みは **`基盤 + 土砂 − 元の高さ`（削れた所は 0）**。土砂のテクスチャを
  そのまま読むと、`地形を土砂にする` が入のときに**地形の高さそのもの**になる
  （あの設定では土砂 = 動かせる地形のため）。
  **正規化は実寸**で、`基準の厚み`（m）で 1 になる。
  0 にすると「一番厚い所で 1」に戻るが、少数の分厚い点が基準になって
  残りが 0 付近へ潰れる（`data/sample.tgproj` の実測で、0.5 以上の面積が
  最大正規化では 0.29%、基準 0.5m では 48%）。そのあと締まり（コントラスト）を掛ける。
  焼くのは**その堆積レイヤーの直後**だけ（作業用テクスチャを使い回すため）。
- **マスクに効くのは Height だけで、法線マップは一切効かない。**
  堆積が読むのは合成の Height（`indices1.w`）だけで、法線を読む所は無い。
  素材の法線マップを全部外して焼き比べても**マスクは 1 ビットも変わらない**（確認済み）。
  細かい模様が乗って見えるのは、**下地サーフェスのハイトマップの起伏**が
  合成 Height に入っているから（下地の `起伏の強さ` を 0 にすると
  マスクの隣接画素の差が 1.78 → 0.56 まで落ちる）。
- **注意: レイヤーの加工にはキャッシュが無い。** マスクの op と違い、
  スタックが変わるたびに走る（既定値で 300 回ほどのディスパッチ）。

## 崩落（Crumbling）

`shaders/CompositeCrumbling.hlsl`。terrain-editor の Crumbling を移したもの。
発生源から岩片を生み、地形の低い方へ歩かせ、止まった位置に岩片の形を積む。

- **合成解像度でそのまま回す。** 岩片は m 単位の小さな形なので、
  堆積のように粗いグリッドで回すと形にならない。
- **1 スレッド = 1 粒子**で「生む → 歩く → 描く」まで通す。
  terrain-editor は CPU で 3 段階に分けているが、GPU では粒子ごとに独立させたほうが速い。
- 試行回数は `256 + 量 × 12000` に**地形の面積（km²）を掛けた**数。
  受け入れるかどうかは発生源マスクの明るさで決まる。
- 歩行は勾配の逆向きへ。`重力` が低いほど向きが揺らぎ、`散らばり` が高いほど横へ逸れる。
  ほとんど下らなくなったら止める（落差は m で見る）。
- **積む先は 1 枚の R32_UINT にパックする。**
  上位 20 bit が岩屑の高さ（岩片の最大の高さで割った 0〜1）、下位 12 bit がその
  岩片ごとの乱数。非負の値どうしなら uint の大小が高さの大小と一致するので、
  `InterlockedMax` 1 回で「一番高い岩片が勝ち、その乱数も一緒に残る」が成り立つ。
  高さと付随データを別々に書くと、勝者が入れ替わる競合を避けられない。
- 出力は 3 つ。Height への加算、`Mask`（厚み）、`Unique`（岩片ごとの乱数）。
  マスクは**パックしたテクスチャから取り出すだけ**なので、専用の作業用テクスチャは要らない。
- **未対応: 粒子どうしの分離。** terrain-editor は止まった後に近すぎる岩片を
  押し分けるが、全粒子を見渡す処理なので 1 スレッド 1 粒子とは相性が悪い。
  歩行中の横ぶれ（`散らばり`）だけで散らしている。
- 堆積と同じく**キャッシュが無い**。スタックが変わるたびに走る。

## マスクの op（ノードグラフの評価）

グラフのマスクは `compositor::MaskProgram`（op の列）へ落ちてくる。
評価器は op ごとに 1 枚のテクスチャへ焼き、レイヤーは添字で参照する
（`LayerMask::maskOp`、`MaskSource::Node`）。

- 画像 / 傾斜 / レベル / 合成は `CompositeMaskOps.hlsl` の 1 ディスパッチ。
  川筋だけは反復が要るので `CompositeFluvial.hlsl`。
- **タイルには分けない。** マスクは全面で 1 枚として焼く。
- 解像度は合成解像度に合わせる（川筋だけは自前のグリッド）。
  下流の op は UV で引くので、解像度が混ざっていてもよい。
- **焼き直しは入力ハッシュで決める。** 「op のパラメータ + 入力 op のハッシュ +
  そこまでのレイヤーの Height に効く値 + 地形の実寸」を混ぜたハッシュが
  前回と同じなら、そのまま前回のテクスチャを使う。
  色やラフネスを動かしても川筋（1024 ディスパッチ）は走らない。
- **傾斜（Slope）は角度で切る。** 勾配を実寸（標高差 / 一辺）に直して
  `atan` で角度にするので、「30 度より急な所」と指定できる。
  `最大ディテール` は**勾配を測る距離**で、離れた 2 点の差を見ることで
  小さな凹凸を無視する（terrain-editor はぼかしてから勾配を取る）。

## 川筋マスク（Mask Fluvial）

下地の Height から**どこへ水が集まるか**（フロー累積）を求め、その量をマスクにする。
terrain-editor の Mask Fluvial を移植したもので、
`CompositeFluvial.hlsl` と `MaterialEvaluator::ApplyFluvialMask()`。

**MFD（Multiple Flow Direction）**: 各セルは下り勾配のある 8 近傍すべてへ、
`勾配^集中度` を正規化した重みで流量を配る。1 方向だけへ流す D8 と違い、
尾根から谷へ面的に広がってから 1 本に集まるので、樹枝状の川筋になる。

```
Height → 解析用グリッドへ落とす → ローパス（最大ディテール）
      → 窪み埋め（8 回）→ 8 方向の配分重み
      → ヤコビ反復ゲザー（2 × 解像度 回）→ 出力カーブ → マスク
```

- **逐次処理を反復で置き換えている。** CPU 版（terrain-editor）は標高の降順に
  ソートして上流から順に足す**本質的に逐次**の手順で、GPU へは直接移せない。
  代わりに毎回すべてのセルが上流を集め直す**ヤコビ反復**を使う。情報は
  1 反復につき 1 セルずつ下流へ進むので、収束に要る回数はおおよそ最長流路長。
  安全側で 2 × 解像度 回まわす。絵は CPU 版と同等になるが、値は一致しない。
- **計算グリッドは合成解像度と別**（既定 512）。反復回数が解像度に比例して
  効くうえ、川筋の形は粗いグリッドでも決まる。合成パスは UV で引くので、
  解像度が違っても継ぎ目は出ない。
- **タイルには分けない。** グリッド全体を何度も舐めるパイプラインなので、
  出力タイルとは無関係に全面で走る。
- **どの時点の Height から作るかはコンパイルが決める**
  （`LayerMask::fluvialSourceIndex`。Mask Fluvial ノードの Base 入力）。
  評価器は合成ループの中で「その位置まで終えた時点」に川筋を作り、
  上のレイヤーがそれを読む。出力マスクだけは川筋 1 本につき 1 枚持つ
  （作る時点と使う時点が離れるため）。作業用テクスチャは 1 組を使い回す。
- **窪み埋めが要る。** 局所的な窪みを残すとそこで流れが止まり、川筋が途切れる。
  8 近傍すべてが自分以上のセルを `min(近傍) + ε` へ持ち上げるヤコビ反復
  （固定 8 回）。端のセルは出口として動かさない。
- 出力カーブは 3 つ。**対数**（流量は下流で桁違いに大きくなるので、対数で
  圧縮すると細い支流から主流までが 1 枚に収まる）、**しきい値**（川とみなす
  所だけを二値寄りに抜く）、**線形**（主流が強く出る）。
  正規化に使う最大値は `InterlockedMax`（非負 float はビット列の大小が
  uint と同じ順序になる）で集める。
- **コスト**は反復回数がそのまま効く。512 グリッドなら 1024 回のディスパッチで、
  スタックが変わるたびに走る。パラメータを動かすときの重さはここから来る。
  作業リソース（8 枚）は**川筋を使うレイヤーがあるときだけ**確保する。

`強調`（`derivedScale`）は効かない。川筋は自前のパラメータ一式を持つ。

## 河川（River）

`CompositeRiver.hlsl` と `MaterialEvaluator::ApplyRiver()`。川筋から河床を掘り、
下流へ単調に下がる水面を張る加工。設計の経緯は
[reference/river-node.md](../reference/river-node.md)、実装の要点は
[design/node-graph.md の「河川（加工）」](node-graph.md)。

- **水面 = Planchon–Darboux 法の窪み埋め**（最小勾配 ε 付き）。埋めた面が
  そのまま水面高で、盆地は出口の高さまで埋まって湖になる。
- 流量は川筋マスクと同じ MFD + ヤコビ反復。ただし**埋めた面の上で**回すので、
  湖の下流へも流量が続く。
- 幅は `max(最小幅, 主流の幅 × (Q / Qmax)^幅の伸び)`。中心線からの距離場は JFA。
- 掘りは堆積と同じく差分で足し戻し、水は `max(地形, 水面高)` で置き換える。
  水面の被覆 / 水深は合成解像度で焼き、水面の法線は R32 の水面高から作る
  （合成の Height は R16 で、緩い水面は階段になる）。
- 川筋 / 堆積 / 積雪と同じく**下地になれず、キャッシュも無い**。
  512 グリッドで約 2100 回のディスパッチ（いまのノードで一番重い）。

## マスクのソース

| ソース | 値 |
| --- | --- |
| 定数 | `constant` |
| ノイズ | `constant + (noise - 0.5) * amount` |
| テクスチャ | `constant * tex.r` |
| 下地の高さ / 傾斜 / 曲率 / 窪み | `constant * derived` |
| ペイント | `constant * paint` |

ノイズは fBm / 尾根状 / セル状（Worley）から選べる。

### ノイズはタイルする

合成の全経路がタイリング前提（wrap サンプラ、書き出した素材もタイルして使う）なので、
**ノイズも UV の 0 / 1 の境界で継ぎ目なく巻ける必要がある。**
格子の座標を周期で巻いてからハッシュすることで周期化している
（`Common.hlsli` の `WrapCell`。fBm / 尾根状 / Worley とも、オクターブごとに周期を倍にする）。

- **周期は整数のときだけ厳密にタイルする**ため、周波数はシェーダ側で整数へ丸めて
  評価する（`SampleNoise`）。UI のスライダーも刻み 1 の整数にして、表示と実際を揃える。
- **UV スケールが整数でないレイヤーではタイルしない。** これはテクスチャの
  タイリングと同じ制約で、ノイズだけの話ではない。
- 周期化する前は、ハイトの境界が反対側の端の高さと混ざって
  （wrap のバイリニア補間）継ぎ目に段差が出ていた。振幅の小さいサーフェスでは
  目立たなかったが、シェイプの地形スケールの起伏で顕在化した。

得られた値に **カーブ**（`contrast`。1 で線形、大きいほど S 字が強く境界がはっきりする）と
**レベル調整**（下限・上限）、**反転**を掛けたものが最終的なマスクになる。

### 中間結果由来のマスク

「下地」とは、そのレイヤーより下を合成した結果のこと。Height チャンネルから作る。

| 種類 | 意味 | 用途の例 |
| --- | --- | --- |
| 高さ | 下地の高さそのもの | 高いところだけ雪を積もらせる |
| 傾斜 | 勾配の大きさ（0 = 平坦） | 急斜面にだけ岩を出す |
| 曲率 | ラプラシアン（0.5 = 平坦、> 0.5 で凸） | 稜線を強調する |
| 窪み | 周囲の平均との差（簡易 AO） | 窪みにだけ苔を生やす |

**近傍を参照するため、合成パスとは別のパスで計算する。**
合成パスは Height を UAV として書き換えるので、同じディスパッチで近傍を読むと競合する。
`CompositeMask.hlsl` が Height を SRV として読み、専用のスクラッチテクスチャへ書き出す。

**評価のループはレイヤー優先。** 1 レイヤーぶんを全タイルで終えてから次へ進む。
タイル優先で回すと、まだ評価されていない隣のタイルを読んで境界に継ぎ目が出る。

窪みの計算はリング状に 8 方向 × 2 半径（8 / 16 テクセル）をサンプルする。
半径が小さすぎるとノイズの最高周波数の穴ばかり拾ってしまう。

### ペイントマスク

ブラシで描いたマスク。`PaintMaskStore` が R8_UNORM のテクスチャを ID で管理し、
レイヤーは `LayerMask::paint` でその ID を持つ。

**ペイントマスクは出力そのものの座標で引く。** レイヤーの `uvScale` は掛けない。
ブラシは「メッシュ上で見えている位置」に描くものなので、
合成結果のテクセルと 1 対 1 で対応していないと、描いた場所と出る場所がずれる。

#### カーソル位置からマテリアル UV を求める

メッシュ描画の 2 枚目のレンダーターゲットへ `frac(uv * materialUvScale)` と
被覆フラグを書き出す（`MeshPbr.hlsl` の `SV_Target1`）。
ブラシパスはこの UV バッファをそのまま読むため、CPU への読み戻しが要らない。

- レイキャストではなく UV バッファにしたのは、メッシュが増えても地形になっても
  同じ仕組みで済むため。
- 読むのは 1 フレーム前の内容になるが、ブラシの描き味に出るほどの差はない。
- UV はタイル 1 枚ぶんに畳んであるので、R16G16B16A16_FLOAT の精度で足りる。

#### ブラシ

`PaintBrush.hlsl` が前フレームのカーソル位置から今フレームの位置までを
線分として受け取り、線分上を最大 64 点で標本化して重みの最大値を取る。
標本化はグループ内の 64 スレッドで行い、`groupshared` で共有する。

**ブラシの半径は画面ピクセルで指定する。** マテリアル UV での半径は、
UV バッファの隣接テクセルとの差分（= 画面 1 ピクセルあたりの UV 幅）から求める。
視点の距離や UV スケールが変わっても、画面上で見える大きさが変わらない。
差分は UV の継ぎ目やメッシュの輪郭で跳ねるため、
0.05 を超える差分は捨てて残りの近傍から取る。

マスクはメッシュ上でタイリングするため、**UV の距離は 0 / 1 の境界をまたぐ**。
`min(d, 1 - d)` で巻き戻して測る。継ぎ目の向こう側にも同じストロークが乗る。

#### アンドゥ

ストロークの開始時にペイントマスクを履歴用テクスチャへ `CopyResource` で退避する。
アンドゥは書き戻すだけ。CPU へ読み戻さないので、履歴の出し入れに GPU 同期が要らない。
1024 の R8 で 1 段 1 MB、上限 24 段。

アンドゥの単位は「1 ストローク」。押しっぱなしで塗り重ねても 1 段に収まる。

#### 要求はいったん積む

描画・塗りつぶし・アンドゥはすべて要求として積んでおき、
フレーム内の 1 か所（合成の評価より前）でまとめてコマンドリストへ記録する。
UI から直接コマンドを積まないことで、フレームの内と外で呼べる操作が混ざらない。

## タイル評価

編集中の即応性とエクスポート時の解像度を両立するため、評価器は
「出力タイル矩形と解像度を引数に取る」形で固定する。

- 編集中: プレビュー解像度（既定 1K、512 / 1024 / 2048 から選択）。
- エクスポート: フル解像度（4K / 8K）をタイル分割し、順次評価して読み戻す（M5）。
- 8K × 4 チャンネルは VRAM を強く圧迫するため、フル解像度を常駐させる設計にはしない。

**タイル評価は常用する。** プレビューでも 512 のタイルに分割して評価し、
エクスポート時と同じ経路を通す。使わない経路は壊れたままになるため。
一括評価との結果一致は画素単位で確認済み（中間結果由来のマスクを含む）。

**ループはレイヤー優先**（外側がレイヤー、内側がタイル）。
中間結果由来のマスクが近傍を参照するため、この順序でないと境界に継ぎ目が出る。

この順序では、レイヤーを跨いで 4 枚のチャンネルが全解像度で常駐している必要がある。
「フル解像度を常駐させない」という当初の狙いとは矛盾するが、
近傍参照を伴うマスクを入れた時点で避けられない。
エクスポート時にガードバンド付きのタイルへ切り替えるかは M5 で判断する。

## マテリアル

**レイヤーはマテリアルを 1 つ参照する。** マテリアルは PBR のマップ一式に名前を付けたもので、
`MaterialLibrary` が持つ。マップを個別に差し替えるのではなく、
マテリアルを差し替えることで見た目を変える（Quixel Mixer と同じ形）。

| マテリアルが持つもの | 内容 |
| --- | --- |
| マップ（RGB） | ベースカラー / 法線 |
| マップ（スカラー） | ラフネス / メタルネス / AO / ハイト。**テクスチャ + チャンネル**で指定 |
| 定数 | ベースカラー、ラフネス、メタルネス、AO（マップが無いスロットに使う） |
| サムネイル | 一覧に出す 128x128 の球 |

- **色はすべてリニアで持つ。** テクスチャは sRGB の SRV 経由でハードウェアが
  リニア化するので、定数も同じ空間で持たないと、同じ「0.5」がテクスチャ由来か
  定数由来かで倍以上ずれる。UI へ出すときだけ sRGB へ直す
  （[design-guide.md](design-guide.md) の「色空間」）。
- **ベースカラーの既定は 18% グレー（リニア 0.18）。**
  写真と CG で共通の中間グレー基準で、画面上では sRGB 0.46 に見える。
  地面素材のアルベド（0.1〜0.3）にも収まる。
  リニアで 0.5 を置くと sRGB 0.735 相当、つまりコンクリート（0.5）より明るくなり、
  この分野の素材としては行き過ぎになる。単色マテリアル
  （`renderer::MaterialSettings`）も同じ 0.18 で、ルックデブのグレーボールに揃える。
- **ベースカラーの定数は「マップに掛ける色」（tint）で、既定は 1.0。**
  シェーダは `layerBaseColor *= テクスチャ` と乗算するので、
  **乗算の中立値である 1.0 以外を既定にすると、外から持ち込んだ素材の
  アルベドが黙って変わる。** 実際、既定が 0.5 だった頃は Megascans の
  ベースカラーが一律で半分に暗くなっていた。
  マップが無いスロットでは、この値がそのままベースカラーになる。
- **マテリアルを割り当てたら、レイヤー側の色とサーフェスの値は使わない。**
  同じ意味の値が 2 か所にあると、どちらが効いているのか分からなくなる。
  レイヤー側の値はマテリアル未割り当てのときだけ効く。
- **マスク用テクスチャはマテリアルに入れない。** マスクはレイヤー固有で、
  「どこに出すか」を決めるもの。マテリアルの「何を出すか」とは役割が違う。
- ハイトはマテリアルが持つが、効かせるかどうかはレイヤーの
  「ハイトのソース」がテクスチャかどうかで決まる。

### チャンネルパック

スカラーのマップは「どのテクスチャの、どのチャンネルを読むか」で指定する。
**Megascans の `_ORD` のように 1 枚へ複数のマップを詰めたテクスチャがあるため。**

| 並び | 意味 |
| --- | --- |
| O (R) | Occlusion（AO） |
| R (G) | Roughness |
| D (B) | Displacement（ハイト） |

マテリアルパネルの `ORD` 行から、この並びでまとめて割り当てられる。
個別に選び直すこともできる（UE の ORM のように並びが違う素材にも対応するため）。

チャンネル指定は **4bit ずつ 1 つの uint へ詰めて**シェーダへ渡す。
ルート定数の枠を節約するため。並びは `TG_CHANNEL_SLOT_*` と C++ 側の
`PackChannel` の第 2 引数で揃える。

マスク用テクスチャも同じ形で指定する（レイヤー側で持つ点は変わらない）。

### サムネイル

`MaterialThumbnail.hlsl` が正面を向いた球を解析的に解いて描く。メッシュは使わない。
マップは円板の UV でそのまま引く。見比べるためのものなので、
プレビュー本体と厳密に一致させる必要はない。

サムネイルは**マップかパラメータを変えたときだけ**作り直す（`thumbnailDirty`）。
生成は `Device::ExecuteImmediate` を使うためフレームの外で行う。

**円の外はアルファ 0 で抜き、背景色を焼き込まない。** サムネイルは
レイヤーパネル（`#1E1E1E`）とマテリアル一覧（`#232323`）の両方に出るので、
背景を塗ると必ずどちらかで四角い色違いの板に見える。`R8G8B8A8_UNORM` で
アルファを持たせ、`ImGui::Image` の通常のアルファ合成に任せる。

**2 方向から照らす。** キー（左上手前・暖色）とフィル（右奥・寒色）の 2 灯。

- フィルは**カメラより奥**（`z` が負）に置く。右の輪郭が光ってシルエットが背景から分離する。
- 1 灯だと陰側がのっぺりして、素材の凹凸が半分しか読めない。
  サムネイルは**見比べるためのもの**なので、形と粗さが一目で分かることを優先する。
- 露出は掛けず、正規化した強さで直接シェーディングする（一覧の中で明るさを揃えるため）。
  プレビュー本体のような物理量では扱わない。
- **強さは素材の暗さを見込んで決める**（キー 4.5 / フィル 3.0）。
  地面素材はアルベドが 0.1〜0.3 と暗いので、控えめに当てると
  2 灯にしても差が模様のノイズに埋もれる。白い素材でも飽和しないことを実測で確かめる。

**輪郭は縁を暗く落とさない。** 以前は縁を背景色へ寄せて球らしく見せていたが、
素材の色によっては**濃いグレーの輪郭**として見えてしまった。
球らしさは斜めを向いた法線のシェーディングだけで足りる。
ジャギーは 3 テクセル幅のアルファのグラデーションで消す
（`disc` は `size` テクセルで `[-1, 1]` を張るので 1 テクセル = `2 / size`）。

## テクスチャの扱い

- 8bit の画像（PNG / TGA / JPG）はリソースを `R8G8B8A8_TYPELESS` で作り、
  **UNORM と UNORM_SRGB の 2 つの SRV** を張る。
  同じ画像をベースカラー（sRGB）にもラフネス（リニア）にも使えるようにするため。
  評価器はベースカラーだけ sRGB 側のインデックスを渡す。
- **EXR は `R16G16B16A16_FLOAT` のまま持つ。** 8bit へ落とすとハイトに階段が出る。
  中身はすでにリニアなので SRV は 1 つで、sRGB 側にも同じインデックスを返す。
  そのぶん、破棄のときに sRGB の SRV を二重解放しないよう `isFloat` で分けている。
- 読み込み時にミップを生成する（`TextureMips.hlsl`）。
  合成解像度より大きいテクスチャを縮小して使う場面が普通にあるため。
- **コンピュートシェーダでは暗黙の LOD が使えない。**
  `Sample` ではなく `SampleLevel` を使い、
  出力テクセル 1 つが張る UV 幅からミップレベルを計算する。
  これを怠ると縮小時にひどくエイリアスする。

テクスチャは画像 1 枚ぶんの単位で、マテリアルのスロットとレイヤーのマスクから参照する。
未指定のスロットは定数値を使う。
