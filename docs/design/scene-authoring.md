# scene-authoring — ハイトマップからシーンを仕上げる手順

作成日時: 2026-09-28 14:08
更新日時: 2026-10-05 19:07

ユーザーがハイトマップ（と、あれば GeoJSON・参考写真）だけを用意し、残り（地形の加工、岩・土・草の塗り分け、
植生、雪、雲と空、道、確認）を LLM が仕上げるときの手順と決まりごと。空木岳・天狗岳・赤岳・西伊豆・白馬岳・
アルブラ峠の 6 シーンで行った作業（`docs/plan/progress.md` の各節）から、繰り返し使う手順と落とし穴をまとめた。

- 植生モデルの作り方は [vegetation-assets.md](vegetation-assets.md)。ここでは「どの樹種をどこに置くか」までを扱う。
- ノードの仕様は [../reference/nodes.md](../reference/nodes.md)、道の仕様は [path.md](path.md)。
- 補助スクリプトは `tools/scene/`（Python 3。numpy と Pillow を使う）。どれも data/ の中でも外でも動く。

| スクリプト | 用途 |
|---|---|
| `tools/scene/dump_graph.py` | 地形グラフをノードごとに 1〜2 行で書き出す（メモ・入力の出どころ・主な設定。標高マスクは実際の標高も併記） |
| `tools/scene/qa_cameras.py` | 確認用カメラのシーンを作る（元のシーンの複製でカメラだけ変える） |
| `tools/scene/shoot.py` | アプリを非表示で起動して撮影・保存し直し・インポスターの焼き直しを行い、ログの警告を拾う |
| `tools/scene/mask_debug.py` | 切り分け用の複製を作る（マスクを赤く塗る / 繋ぎを 1 本外す） |
| `tools/scene/routes_from_geojson.py` | GeoJSON の位置の確認、登山道の Path、自動車道路の Road Path |
| `tools/scene/tgscene.py` | 上の共通部品（グラフの ID・繋ぎ替え、緯度経度 ⇔ UV、標高の読み出し） |
| `tools/blender/render_preview.py` | 生成した植生モデルの LOD を Blender で並べて描く |

## 1. 全体の流れ

1. ユーザーに用意してもらうもの・聞くことを揃える（2 章）。
2. バックアップを取り、確認用のフォルダを決める（3 章）。
3. 気候の近い既存シーンのグラフを複製し、ハイトマップと実寸を差し替える（4 章）。
4. 標高帯と植生を、その土地の実際の標高で組み直す。足りない樹種は作る（5 章）。
5. 岩・土・砂礫・草のマテリアルを、その土地の色にする（6 章）。
6. 雪・雲・空を季節に合わせる（7 章）。
7. GeoJSON があれば登山道と道路を引く（8 章）。
8. 撮影して、参考写真と並べて直す（9 章）。おかしければ切り分ける（10 章）。
9. Debug で開いて保存し直し、警告が無いことを確かめ、記録する（11 章）。

## 2. ユーザーに用意してもらうもの・聞くこと

| もの | 置き場所・形式 | 無いとき |
|---|---|---|
| ハイトマップ | `data/Scenes/<名前>/` に 16 bit グレースケール PNG。**上端が北**、右端が東 | 必須 |
| 一辺の長さ（m）・最低標高・最高標高 | Heightmap ノードの `scale`（`size` / `baseElevation` / `height` = 標高差） | 必須。ハイトマップの書き出し元（location-viewer など）の値を聞く |
| 中心の緯度・経度 | Heightmap ノードの `scale.location` | GeoJSON があれば 8 章の `check` で確かめる。無ければ聞く |
| GeoJSON（道） | `data/Scenes/<名前>/*.geojson`。LineString、座標は `[経度, 緯度, 標高]`、`properties` に `category`（trail / foot / road）・`name`・`osmId` | 道は引かない（Path を空にしておく） |
| 参考写真 | `docs/references/<名前>/`（Git には入れない） | その土地の一般的な姿で作り、後で写真をもらう |
| 季節・時刻 | 写真から読む。写真が無ければ聞く | 夏の日中 |
| 道路の方針 | 自動車道路は Road Path（分岐を持てない）。どれを 1 本にするか | 主要な 1 本（峠道・幹線）だけ |

- **写真の季節に合わせる。** アルブラでは空の日付（9 月）から晩夏で作ったが、写真は初夏（雪渓が点在、鮮やかな草）で、作り直した。写真があれば日付より写真を優先する。
- 最低標高を取り違えると標高帯が全部ずれる（天狗岳で確認用シーンの値が紛れ込んでいた）。ノードのメモに「一番低い所・山頂」を書き、最低標高 + 標高差 = 山頂 になることを確かめる。

## 3. 準備

- 作業の前に `docs/plan/goals.md` / `plan.md` / `progress.md` を読む（CLAUDE.md の決まり）。
- **バックアップ**: シーンのフォルダを丸ごと `data/Test/<名前>-backup-YYYYMMDD.zip` に取る（同じ日に 2 回目なら `-v2`）。
  `python -c "import shutil; shutil.make_archive('Test/<名前>-backup-20260928','zip','Scenes','<名前>')"`（data/ で）
- **確認用のフォルダ**: `data/Test/<名前>-qa/`。確認用のシーン・撮影・ログはここに置く（`data/` は Git に入らない）。
- シーン（`.tgscene`）の部品のパス（`components[].asset.path`、`atmosphere.path`）がファイル名と合っているか見る。
  新規作成の直後は「新規シーン_*」のままのことがある（ID で解決されるので開けるが、直しておく）。

- 複製元の「土で地形を覆う」（Snow ノード）の量は、山の質で変える。赤岳の値（量 1.6、細かさ 32）は岩が多く出るので、
  土と砂礫に覆われた稜線（中央アルプスの花崗岩）では空木岳の値（量 2.34、細かさ 8、動く勾配 30°）にする（木曽駒ヶ岳で、稜線一面がごつごつした岩になった）。

## 4. 基準のグラフを複製する

### 4.1 どのシーンから複製するか

地形グラフ（`.tgterrain`）は、空木岳（`utsugidake6`）から天狗岳 → 赤岳 / 西伊豆 / 白馬岳 → アルブラと複製して育ててきた。
同じ骨組みなので、**気候の一番近いシーン**を選ぶ（標高帯・樹種・色の手直しが少ない）。

| シーン | 場所 | 一辺 | 標高 | 特徴 |
|---|---|---|---|---|
| `shiroumadake` | 北アルプス（白馬岳） | 7,830 m | 1,051〜2,920 m | 多雪。ブナ → オオシラビソ → ダケカンバ → ハイマツ、残雪期の雪、灰色の岩 |
| `tengudake` | 北八ヶ岳（天狗岳） | 7,910 m | 1,247〜2,646 m | シラビソ主体（立ち枯れ）、麓にカラマツの植林、赤茶の砂礫 |
| `akadake` | 南八ヶ岳（赤岳） | 5,900 m | 1,628〜2,875 m | 天狗岳の複製。スコリア、森林限界 約 2,450 m |
| `kiso-komagatake` | 中央アルプス（木曽駒ヶ岳） | 3,960 m | 1,665〜2,941 m | 赤岳の複製。白い花崗岩、森林限界 約 2,520 m、カールの草原、雪なし（初秋） |
| `nishiizu` | 伊豆（西天城高原） | 4,010 m | 148〜888 m | 森林限界なし。スギ・ブナ、ササ原（ハコネダケ）・ススキの草原 |
| `julia-pass` | スイス（ユリア峠） | 5,050 m | 1,975〜3,135 m | アルブラの複製。木の無い峠、羊背岩のこぶと低木、細い流れ、6 月の朝 7 時の光 |
| `albura` | スイス（アルブラ峠） | 6,720 m | 1,797〜3,327 m | ドイツトウヒ → アロラマツ・ヨーロッパカラマツ → 草原。峠道の Road Path |
| `utsugidake6` | 中央アルプス（空木岳） | 3,970 m | 1,690〜2,850 m | 最初の骨組み。花崗岩の白いザレ |

### 4.2 複製のしかた

- アプリのアセット欄の `.tgscene` の右クリック「シーンを複製…」は、**同じシーンの部品ごと**複製する。
  ユーザーが新しいシーン（ハイトマップだけの地形）を作ってあるときは、**グラフだけ**を移す:
  1. 移し先の地形の `uid`・`textures`（ハイトマップ）と、Heightmap ノードの `scale` を控える。
  2. 複製元の `.tgterrain` を読み、`graph`・`materials`・`models` を持ってくる。`uid`・`name`・`textures` は移し先のもの。
  3. Heightmap ノードの `scale` を移し先の値にし、`layer.height.texture.texture` がハイトマップの `textures[].id` を指すことを確かめる。
  4. `geometry.planeSize` / `displacementScale` を一辺・標高差に合わせる（解像度 `materialResolution` 4096・`meshSubdivisions` 1024 は複製元のまま）。
  5. シーンの `preview` の `planeSize` / `displacementScale` も合わせる。露出・影の段数などは複製元に揃えてよい。
- **複製元に固有のものを消す**:
  - Path の点（複製元の登山道）。空にするか、8 章で引き直す。
  - 雪渓の範囲の Mask Area など、特定の谷を囲った形。
  - ノードのメモ。場所・標高・樹種を書き直す（メモは次の作業者への説明になる。標高は「標高 約 2,250 m（相対 453 m）」のように実際と相対を併記する）。

### 4.3 骨組み（本流の層の並び）

`dump_graph.py` で読める。出力から入力 0 をたどった本流は次のとおり（ノード ID は複製で変わりうるので、メモで探す）。

```
Heightmap → Blur → Fluvial Erosion → Height Levels
  → Surface「Rock」（全体を岩で覆う）
  → Snow「土で地形を覆う」（露出した所が岩になる）→ Surface「Mud」（土）
  → Sediment（崩れた砂礫）→ Surface「Gravel」（砂礫）
  → Snow Cover（季節の雪。植生より上流に置き、Cover で植生を除く）
  → Surface「Grass」（植生の範囲 = 草）→ 乾いた草 → 湿った草 → 林床・低木の地面（ササ / 矮性低木）
  → River → Surface「Trees」（低木の地面）→ Surface「Road」（Path のマスクで土を塗る）
  → Surface「River」→ Surface「Snow」（Snow Cover の Cover を最後に塗る）→ Blur → Output
```

- **植生の範囲の大元**は「境界のコントラストを引き締める」Levels（土の被覆から作る）。その先で
  「森林限界より下 × 崖ではない × 沢ではない」を max で足し（**森林限界より下の岩の露出を崖だけに絞る**。赤岳で追加）、
  山頂部の砂礫地を引き、川と登山道を除いて「植生を置ける範囲」になる。
- 樹種ごとの分布は「標高帯（Mask Height）× 地形（沢・尾根の Curvature、崖の Slope）× 斑（Noise → Levels）」を掛け、
  上位の樹種の所を Subtract で譲る。Scatter（点）→ Model Scatter（モデル）→ Model Merge → Model Output。
- 背の高い木と低い植生で、雪（Snow Cover の Cover）の除き方を分けている（低い植生は縁まで、背の高い木は芯だけ）。

## 5. 標高帯と植生

### 5.1 標高帯の値

- **Mask Height の値は「地形の底（最低標高）からの高さ」**。実際の標高 − 最低標高 で入れる（`tgscene.Geo.relative`）。
  別のシーンから複製すると底が違うので、全部ずれる（天狗岳 → 赤岳で 497 m ずれ、森林限界が山頂を越えた）。
  値は「底の差だけずらす」のではなく、**その土地の実際の標高から決め直す**。
- 標高帯の境目は 100〜150 m でぼかし（feather）、さらに地形（沢で上へ伸ばす、尾根で下へ降ろす）で入り組ませる。
- 森林限界は土地で大きく違う。実績:

| シーン | 森林限界 | 帯（標高） |
|---|---|---|
| 白馬岳（多雪） | 約 2,350 m | ブナ 〜1,500、オオシラビソ 1,450〜2,300、ダケカンバ 1,550〜2,400（沢 〜2,500）、ミヤマハンノキ 1,750〜、ハイマツ 2,350〜（尾根 2,200〜）、山頂部の砂礫 2,650〜 |
| 天狗岳 | 約 2,450 m | 針葉樹林（シラビソ）〜2,400、麓にカラマツの植林 |
| 赤岳 | 約 2,450〜2,500 m | 針葉樹林 〜2,500、ハイマツ 2,480〜（尾根 2,400〜）、ダケカンバ 2,100〜2,550（沢 〜2,650）、ミヤマハンノキ 2,450〜、スコリア 2,480〜、カラマツ 〜2,000、ササ 〜2,050 |
| 木曽駒ヶ岳 | 約 2,520 m | 麓の針葉樹林（コメツガ・トウヒ）〜2,050、針葉樹林 〜2,520、ダケカンバ 2,150〜2,580（沢 〜2,680）、ミヤマハンノキ 2,450〜、ハイマツ 2,520〜（尾根 2,430〜）、ササ 〜2,200、草 〜2,780、白い砂礫 2,650〜 |
| 西伊豆 | なし（最高 888 m） | スギ 〜670、ブナ 600〜（沢 550〜）、草原 620〜（尾根 530〜） |
| ユリア峠 | 峠の周りは木なし | 林 〜1,990、カラマツ 〜2,040、ミドリハンノキ 2,000〜2,200、低木の塊 2,150〜2,650、矮性低木 2,150〜2,700、草地 〜2,750、崖錐 2,800〜 |
| アルブラ峠 | 約 2,150〜2,250 m | ドイツトウヒ 〜1,950、アロラマツ・カラマツ林 〜2,150、カラマツの疎林 1,900〜2,200（沢 〜2,250）、ミドリハンノキ 1,950〜2,250、ハイマツ（小さな低木の塊）2,200〜2,450、草地 〜2,600、崖錐 2,700〜 |

- 写真があれば、写真で木が無い所には木を置かない（アルブラの峠は森林限界の資料より低い所まで木が無かった）。

### 5.2 樹種の割り当て

- 既存のモデル（`data/Models/`）: ハイマツ、ダケカンバ、オオシラビソ、シラビソ（と立ち枯れ）、カラマツ、ミヤマハンノキ、ササ、ハコネダケ、ススキ、スギ、ブナ、アロラマツ（Arve）、ドイツトウヒ（Fichte）、ヨーロッパカラマツ（Laerche）。
- 同じ属・同じ姿の木は代用してよい（ノードのメモに「〜で代用」と書く）。実績: ヨーロッパハイマツ（Legföhre）→ ハイマツ、ミドリハンノキ（Grünerle）→ ミヤマハンノキ、コメツガ → オオシラビソ、アセビ・マメザクラ → ミヤマハンノキ。
- 足りなければ作る（[vegetation-assets.md](vegetation-assets.md)）。姿の近い既存のスクリプトを元にする（トウヒ ← シラビソ、五葉松 ← シラビソの骨格 + ハイマツの針葉、ヨーロッパカラマツ ← カラマツ）。
  作ったら `render_preview.py` で**既存の樹種と並べて**描き、葉の平均の明るさ（生成時に表示する）を既存と揃え、インポスターを焼く（`shoot.py --bake`）。
- Model Scatter の models に重みを付けて混ぜられる（アロラマツ 1 : カラマツ 0.45 など）。ただし**種類ごとに全点をカリングし直す**ので、1 つの Model Scatter の種類は 4〜6 に抑える。
- Model Scatter の「スケール」は全モデル共通。背丈の違う樹種を混ぜるときは、中間の倍率にするか、Scatter を分ける。

### 5.3 配置の制限

- **Scatter の間隔には下限がある**: 地形の一辺 ÷ 約 2,046（一辺 7,830 m で 3.83 m、6,720 m で 3.29 m）。細かくすると評価が止まり、**地形が真っ黒**になる（白馬岳）。下限に当たるときは間隔を 4 m にして株を大きくする。
- 標高や傾斜のマスクを、そのマスクを使う層より下流の層で測ると**接続が循環する**。上流の層（Fluvial Erosion の直後の岩の層、Sediment など）で測る。
- 描画が重いときは、群落（ササなど）の描画距離を詰める（西伊豆で 800 m）。

## 6. 地面のマテリアル

- 既存のマテリアル（`data/Materials/`）を**複製して色だけ変える**。テクスチャは流用する。名前は `MI_<種類>_<シーン名>`（`MI_Rock_albula` など）。
  複製するときは `uid` を新しくし、共有のマテリアル（`MI_Moss` など）そのものは変えない（ほかのシーンの色が変わる）。
- 調整する値は `brightness`・`saturation`・`hueShift`（度）・`baseColorTint`。
- 実績:
  - 岩: 灰色の堆積岩（白馬岳）は Icelandic Rock Cliff を明るく・彩度を落とす。暗い青灰色（アルブラ）は明るさ 0.72・彩度 0.3・青寄りの色味。
  - 砂礫: Gravel Ground（xdusfjy）を彩度 0.15〜0.25 で灰色に。赤茶（八ヶ岳）は少し暗く赤寄り。
  - 草: Wild Mossy Grass。初夏の鮮やかな黄緑は明るさ 1.15・彩度 1.25・色相 +6。晩夏は色相 −8・彩度 0.75。
  - **明るくしすぎない。** 写真に合わせて明るくすると、同じ光の下でほかより浮く（西伊豆のササ原が蛍光色に見えた）。
- 地面を塗る層（Grass など）が一帯を暗い色で覆っていないか、低い視点で確かめる（アルブラで矮性低木の地面が峠一帯を暗い茶緑にしていた）。

## 7. 雪・雲・空

- **Snow Cover の降雪線（`snowLineHeight`）は、Height 0.5 の基準面が 0 m**（最低標高 + 標高差 / 2）。実際の標高から `tgscene.Geo.snow_line` で換算する。
  降雪線を入れないと、谷に吹き溜まった雪が帯状に残る。季節で決める（アルブラ初夏: 降雪線 約 2,450 m・融雪 0.9 で窪みと北面に雪渓）。
- 雲は既存シーンの雲のグラフ（`.tgcloud` の `graph`）をコピーしてよい。**Weather Layer の雲底（`bottomHeight`）も基準面からの相対**なので、
  地形に対して同じ高さ（山の中腹）に浮く。峠や稜線を見下ろしたいなら雲底を上げる。
- 空（`.tgatmosphere`）: 見た目（大気の濃さ・Mie・天空光・夜空）と太陽の向きは既存シーンからコピーしてよい。
  位置の欄は `longitude` / `starLatitude`（ラジアン）と `utcOffset` をその土地に、日付を季節に合わせる。`celestialMode` が `manual` なら太陽は `azimuth` / `elevation` の値で決まる。
- **太陽の向きは手動で入れる。** ライトは `azimuth` 0 が +z（南）、+x が東。地理の方位 A（北 0°、東 90°）の太陽は `azimuth = 180° − A`（ラジアン）。時刻から A と高度を求めるには NOAA の簡易式でよい（ユリア峠 6 月 21 日 7:00 夏時間で高度 13°・方位 70°）。
- **注意（未対応）**: 北が上の DEM を読み込むと、太陽の方位から見て南北が反転した地形になる（`progress.md` の「Heightmap の位置」）。天体モードで太陽を合わせるときは気を付ける。
- シーンの `preview`（露出・解像度・影の段・ゴッドレイ）は既存シーンに揃えると、見た目を比べやすい。

## 8. 道（GeoJSON）

1. **位置の確認**: `routes_from_geojson.py check <シーン> <geojson>`。GeoJSON の標高とハイトマップの差の中央値が数 m なら合っている
   （実績 1.0〜4.7 m。上下が逆だと 160 m、位置が古いと数百 m ずれる）。種類・名前ごとの本数と長さも出るので、道路の名前をここで拾う。
2. **登山道**: `routes_from_geojson.py trails <シーン> <geojson> [--road-names "名前,名前"]`。
   trail / foot の線を地形の端で切り、分岐でつなぎ、形を保って 4 m で間引き、幅 2 m・フェザー 4 m の Path にする（既存の Path の点を置き換える）。
   `--road-names` を付けると、自動車道路の中心線も幅 9 m で入れる（Road Path は Mask Path に繋げないので、道沿いの土の塗りと、道の上の植生の除外はこの Path で行う）。
3. **自動車道路**: `routes_from_geojson.py road <シーン> <geojson> --names "名前,名前" --start west`。
   **Road Path は分岐を持てない**ので、主要な 1 本（峠道・幹線）だけにする。指定した線を端点で繋ぎ（分岐ではまっすぐ続く方）、12 m ごとに打ち直し、
   Road Path → Road Mesh（幅 6 m、片側 1 車線）→ Lane Marking（中央の破線）→ Shoulder（砂利の路肩 1 m）→ Mesh Output を作り直す。
   区画線・車線・路肩は写真に合わせて引数で変える。
- 点の無い Path のマスクは 0（足跡が無い）。以前は「未接続」扱いで、道の層が地形全体を土で塗った（2026-09-28 に修正）。
4. **地形を道路に合わせる（Road Grading）**: 道路を作っただけでは、路面が所々で地形に埋もれる（中心線を CPU 側のハイト 512² から引くため）。
   Road Path の Base になっている層（アルブラでは Surface「Grass」）の直後へ Road Grading を挿し、Base にその層、Mesh に Shoulder（無ければ Road Mesh）を繋ぐ。
   その層を読んでいた下流（本流の次の層、マスク、Scatter、Path）は Road Grading の Result へ付け替える。**Road Path の Base だけは元の層のまま**（付け替えると循環する）。
   既定値（路面下の余裕 0.15 m、平らな幅 1 m、切土 1 : 1、盛土 1 : 1.5）で、アルブラ・ユリア・西伊豆とも見た範囲の全区間で路面が出た。
- **既知**: 法面は元の素材が引き伸ばされて縞に見える。法面の塗り分けや植生の除外には Road Grading の Road / Cut / Fill のマスクを使う（アルブラ・ユリアでは未設定）。

## 9. 確認（撮影）

1. Release をビルドする（`cmake --build --preset x64-release`）。
2. 確認用カメラのシーンを作る:
   `qa_cameras.py <シーン> --out Test/<名前>-qa far=0.5,0.55,9000,0,22 top=0.5,0.5,11000,0,85 low=@緯度,経度,500,270,8 ...`
   - 各カメラは「注視点（u,v か @緯度,経度）, 距離 m, 見る方位（0 = 北を見る、90 = 東）, 俯角（0 = 水平、90 = 真下）」。
   - カメラの向きの式（`Camera.cpp`）: 目 = 注視点 + 距離 ×（cos 俯角 · sin ヨー, sin 俯角, cos 俯角 · cos ヨー）、ワールドの +x が東、**+z が南**。
     見る方位 a のときヨー = −a。スクリプトが換算する。
   - 目が地形に埋まると真っ暗や裏返しの絵になる。スクリプトが警告するので、俯角を上げるか方位を変える。
   - 雲の動きは止める（撮り直しで絵を比べるため）。
   - 揃えておくとよい構図: 遠景（地形全体）、真上、主な谷・峠の中景、**写真と同じくらいの低い視点**（ドローンの高さ、距離 500 m・俯角 8° 程度）、森林帯の近く。
3. 撮る: `shoot.py Test/<名前>-qa/far.tgscene ... --prefix v1`。画像は `v1_far.png`、ログは `.err`。
   - アプリはウィンドウを出さずに起動する（最小化では描画が止まる）。撮影はグラフの評価が止まるまで待つ。
   - 撮影は 1 枚数秒〜十数秒。変更のたびに `v1`、`v2`… と頭を変えて残し、前後を並べて比べる。
4. **参考写真と並べる**。写真は 4K なので縮小して見る。違いを具体的に書き出してから直す（例: 木が多い、岩が明るすぎる、雪原が大きい）。

## 10. 切り分け

結果がおかしいとき（土一色、植生が出ない、藪が多すぎる）は、推測で値を変えず、原因のノードを突き止める。

- **マスクを見る**: `mask_debug.py paint <確認用シーン> <ノード>[.<出力>] ... --out Test/<名前>-qa`。
  最後に「そのマスクで赤く塗る」層を足した複製を作る。赤い所がマスク = 1。上流から順に見て、どこで 0 になるかを探す。
- **どの配置が置いているか**: `mask_debug.py drop <確認用シーン> <Model Merge のノード>:<入力> --out ...`。
  1 本ずつ外して撮り、消えたものが犯人（アルブラで、峠の暗い藪がハイマツではなくミドリハンノキだと分かった）。
- 撮影が早すぎる疑いは `shoot.py --frame 600` で確かめる（評価の終了を待つので、普通は同じ絵になる）。
- **Surface のマスクの入力を `drop` で外すと、その Surface は定数マスクで全面を塗る**ので、Surface の切り分けには `paint` を使う（`drop` は Model Merge など用）。
- 見終わったら `dbg_*` を消す。
- 実例:
  - 土一色 → 空の Path の道の層が全面を塗っていた（修正済み）。
  - 地形が真っ黒 → Scatter の間隔が下限より細かかった（5.3）。
  - 峠の谷底に帯状の雪原 → 降雪線が低い / 入れていない（7 章）。
  - 森林帯の尾根に点々と岩 → 森林限界より下の岩の露出を絞っていない（4.3）。

## 12. 落とし穴のまとめ

| 症状 | 原因 | 対処 |
|---|---|---|
| 森林限界が山頂を越える / 麓に高山の植物 | Mask Height を別のシーンの底のまま使った | 実際の標高 − 最低標高で入れ直す（5.1） |
| 地形が真っ黒 | Scatter の間隔が一辺 ÷ 約 2,046 より細かい | 間隔を広げて株を大きく（5.3） |
| 接続の循環の警告 | マスクを下流の層で測った | 上流の層で測る（5.3） |
| 谷底に雪の帯 | 降雪線が無い / 低い（基準は Height 0.5） | 降雪線を実際の標高から換算（7 章） |
| 雲の中に峠が埋まる | 雲底は基準面からの相対 | 雲底を上げる（7 章） |
| GeoJSON の標高と数百 m ずれる | Heightmap の位置が古い / 上下が逆 | `check` で確かめ、位置を聞き直す（8 章） |
| 道路が分岐しない | Road Path は分岐を持てない | 主要な 1 本にし、残りは Path（マスク）で（8 章） |
| 平らな谷底に幅の広い淡い水面 | 窪み埋めで谷底が浅い水面になる（川の幅・しきい値では変わらない） | 細い流れの Mask Fluvial と水面を掛けて塗る（ユリア峠） |
| 湖の周りが帯状に砂礫になり、植生が抜ける | River の Water 出力が、平らな湖面と湖岸を丸ごと水面とみなす | Water に「湖の周りではない」マスクと細い流れの Mask Fluvial を掛ける（ルンゲルン） |
| ハイトマップの湖が平らで水が張れない | 窪みが無い | 湖面の標高の帯 × 平らな所をマスクにし、Lake の「範囲を湖面にする」の Water Mask に繋ぐ。水位は自動で決まる（ルンゲルン） |
| 斜面に砂礫の筋が多すぎる / 少なすぎる | 谷筋の曲率マスクの感度（m。小さいほど多く拾う） | 感度を上げると減る |
| 確認用の絵が真っ暗・裏返し | カメラの目が地形に埋まった | 俯角・方位を変える（9 章） |
| 樹冠が Blender で薄く見える | 確認レンダリングでアルファ抜きのカードが薄く写る | 既存の樹種と並べて比べ、アプリで確かめる |
| 草原・樹木が浮いて見える | アルベドを写真に合わせて上げすぎ | ほかの植生と並べて決める（vegetation-assets.md） |
