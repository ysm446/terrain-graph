# path — パスと経路探索の設計

作成日時: 2026-09-04 15:00
更新日時: 2026-09-04 15:40

Path ノード（地形の上に引く向き付きの線）と、その鎖ごとの経路探索についてまとめる。
ノードの使い方（パラメータ表と操作表）は [reference/nodes.md の Path](../reference/nodes.md#path)、
グラフ全体の設計は [node-graph.md](node-graph.md)。ここは**なぜそうなっているか**と
**実装の骨組み**を置く場所。

実装:

| 役割 | 場所 |
| --- | --- |
| データと編集操作（純粋関数） | `src/graph/Path.h` / `Path.cpp` |
| 経路探索（純粋関数） | `src/graph/PathRoute.h` / `PathRoute.cpp` |
| ビューポートの編集、描画、プロパティ、地形の焼き直し | `src/app/ApplicationPathEdit.cpp` |
| 評価（Mask Path） | `NodeGraph::EmitMaskOps` → `MaskOpKind::Path` → `shaders/CompositeMaskPath.hlsl` |
| 保存 | `src/io/ProjectIo.cpp`（`WritePath` / `ReadPath`） |

## 目的

道路・川・氷河の**ガイド線**を地形の上に引き、それを下流のノード（Mask Path → Surface の
Mask、River の Seed、将来の「パスに沿って掘る / 均す」）が読む。線は手で置くのが基本で、
経路探索は「勾配や流れを守った線を、置いた点の間に自動で通す」補助。

## データ

### 点とエッジ

- **点は地形平面の正規化 UV（0〜1）だけを持ち、高さは持たない。** 高さは読む側
  （表示、Mask Path、将来のノード）が入力の地形から毎回導く。道路・川・氷河はどれも
  地形の上に乗るもので、高さは地形が決める。3D で保存すると、上流の侵食を触った瞬間に
  点が地面に埋まったり浮いたりして、ノードグラフの利点を自分で壊す。例外（橋 / 堤防）は
  点ごとの `高さのずれ`（m）で足す。
- 点は幅 / フェザー / 強さ / 高さのずれを持ち、エッジ上では両端から補間する。
  **エッジは幅の上書き**（`overrideValues` + 幅 / フェザー / 強さ）を持てる。入っていれば
  そのエッジの上では点の値を補間せず、エッジの値で一定になる（鎖を選んでまとめて決める。
  点の値は捨てないので切れば戻る）。ノードの `幅（初期値）` などは新しく置く点の初期値で、
  既にある点には効かない。
- **エッジは from → to の向き**を持つ。Mask Path は使わないが、川 / 氷河の流れの向きと、
  経路探索の `流れ` が使う。分岐は自由（1 つの点に何本でも）。
- ID は点とエッジで共通の空間（`nextId`）。パスの中でだけ一意。

### 鎖（導出）

**鎖（`PathStrand`）は「分岐から分岐まで」のエッジの並び**で、エッジが 2 本だけ付いた点を
通り、それ以外の点（端 / 分岐）で止まる。分岐の無い輪は 1 本の閉じた鎖。
`BuildPathStrands` で毎回導出し、保存しない。

- 「A の途中に B が乗る」という形は無く、支流を繋いだ時点で本流の鎖はそこで割れる。
  支流と本流の判定をツールがしない規則にした。
- **鎖の性質（曲線の種類 / 丸め / クロソイド比 / 経路探索）はエッジに持ち**、鎖を選んだときに
  まとめて読み書きする。鎖は導出したものなので、性質の置き場はエッジしかない。
  点を挿入して割ったエッジは元の値を引き継ぐ。混在は UI が注記する。

### 制御点

曲線と評価が読む「制御点列」は **置いた点 + 経路探索の内部点**。
`PathEdgeControlPoints(path, edge)` がエッジ 1 本ぶん（from、内部点…、to）を返し、
内部点の値（幅など）は両端を道のりで補間したもの。`SamplePathStrand` は鎖の向きに沿って
これを繋ぐ。**経路が古いエッジは内部点を飛ばして両端だけ**になる（後述）。

## ビューポートの編集

軸は「**クリックは選ぶ、Ctrl を押している間だけ伸ばす、ドラッグして重ねれば繋がる**」。

- **ふつうのクリックはデータを変えない**（選ぶだけ）。増やす / 繋ぐは Ctrl、動かすは
  ドラッグ、消す / 分ける / 反転はキーとメニュー。線のそばに点を置きたかったのに
  挿入されてしまう、という誤操作を無くすため。点の挿入も Ctrl + エッジのクリック。
- **「末尾」という状態は持たない。** 伸ばす起点は選択した点で、仮のエッジは Ctrl を押して
  いる間だけ出す（常に出ていると急かされる感じになる）。
- 選択は「点の集合」か「鎖 1 本」のどちらか（混ぜると Delete の意味が曖昧になる）。
  **エッジ 1 本の選択は無い。** 曲線も向きも経路探索も鎖の性質で、1 本だけ変えると
  鎖の中で食い違う。1 本だけ消す / 切り離すは右クリックのメニュー。
- 点を消すとき、**鎖の途中の点（エッジが 2 本）なら両隣を繋ぎ直す**（残すほうのエッジを
  伸ばすので、ID と鎖の性質が続く）。端と分岐はエッジも一緒に消える。
- 吸着は点が優先、無ければエッジ（そこに点を挿入して結合）。Shift で切る。
- 操作の案内はプロパティではなく**ビューポートの右下**に、いまの状態に合わせて出す。

### 座標とハイト

- 表示位置とクリック位置の投影は **CPU 側のハイト**（`MaterialEvaluator::Heightfield()`。
  評価器が評価の末尾で Height を 512² へ縮小して読み戻したもの）から引く。
  クリック位置は箱の中をレイマーチして地面に潜った区間を二分法で詰める。
- ハイトは**プレビューしているもの**なので、Path ノードをダブルクリックして Base の地形を
  プレビューに出してから編集する（`PreviewTop` が Base の上流を返す）。

### 描画

- ImGui の draw list（深度テストなし。丘の向こう側の線も見える）。
- 直線の鎖のエッジは画面上の長さで細かく割り、各点を地形の高さで描く（地形に沿う）。
- **曲線の鎖のエッジはガイド（制御の骨組み）なので、地形に沿わせず点と点を 3D の直線で結ぶ。**
  結果である曲線のほうが地形に沿うので、役割の違いが一目で分かる。
- 経路探索の内部点は小さな点で出す（選べない）。ガイドは内部点を通る。

### アンドゥ

パネルは変更を見つけると文書の変更を記録するだけで、フレームの末尾で 1 段にまとめる。
点の追加は 1 クリック 1 段、ドラッグは離した時点で 1 段（掴んでいるウィジェットの ID が
同じ間は畳まれる）。**離した時点で走る経路の計算し直しは `m_documentJoinsEdit` で
直前のドラッグと同じ段に畳む**（別の段だと Ctrl+Z で先に経路だけが消える）。

## 鎖と曲線

**曲線は点を通らない。** 置いた点は制御点で、折れ線（ガイド）の内側を回る。

| 種類 | 中身 |
| --- | --- |
| 直線 | 制御点そのもの |
| 2 次ベジェ | 途中の点ごとに、両隣の線分上の「丸め × 半分」の位置を 2 次ベジェで結ぶ。両端の点だけ通る（C1） |
| 3 次 B スプライン | 両端を 3 重にした一様 B スプライン（C2）。丸めは折れ線との混ぜ具合 |
| クロソイド | 角ごとに「クロソイド → 円弧 → クロソイド」。交角のうち `クロソイド比` を緩和曲線 2 本が受け持つ。単位曲線をローカルで組み、接線長が「丸め × 半分」に来るように拡大。曲率の数値積分で点列にする |

制御点の区間ごとに 12 分割して直線にし、**表示と Mask Path の両方が同じ標本を使う**
（`SamplePathStrand`。シェーダは線分のまま）。分岐点は鎖の端なので、そこで曲線は折れてよい。

## 経路探索

### 何をするか

鎖ごとに切り替え、有効なら**エッジごとに両端の点の間の経路を地形から探して、内部点として
エッジに持つ**（`PathEdge::waypoints`）。置いた点は動かさない。曲線は「置いた点 + 内部点」で引く。

| モード | コスト |
| --- | --- |
| 道路 | 長さ × (1 + k × 超過²)、超過 = max(0, \|勾配\| − 許容) / 許容。上りも下りも同じ扱い |
| 流れ | 長さ × (1 + k1 × (上り勾配 / 5%)² + k2 × 相対高さ)。向き（from → to）に下り、上りを嫌い、箱の中で低い所（谷底）を好む。川 / 氷河用 |

どちらも**ペナルティであって制約ではない**。制約にすると「経路なし」が起きるが、
ペナルティなら必ず何かは返る（許容勾配を少し超えることがあるのはこのため）。

### 設計判断

1. **内部点はエッジに持って保存する。「高さは保存しない」原則の例外。**
   地形は評価しないと分からず、評価は GPU で非同期。しかも「上流を触っても勝手に
   追従させない（指示するまで変えない）」のが希望なので、導出結果を持つしかない。
   古さは「計算したときの両端の位置」（`routedFrom / To`）と今の両端を比べて判定する
   （`IsPathEdgeRouteCurrent`）。古い間は内部点を無視して両端を直線で結ぶ。
2. **地形は Path の Base に繋いだチェーン。** プレビューの CPU ハイトは使わない。
   プレビューは別の地形を見ているかもしれず、Base が無いときの出力チェーンは
   Path 自身の結果（Mask Path → Surface の削り）を含んで循環する。Base が無ければ計算しない。
3. **地形が変わっても経路は作り直さない。** 再計算のきっかけは編集操作とボタンだけ。
   古さの検出だけでは発動させない（アンドゥで古い状態へ戻った直後に勝手に計算して、
   アンドゥが効かなくなる）。

### 地形の焼き方（`BakePathRouteTerrain`）

- Base のチェーンを `CompileLayersTo(pathNode)` でレイヤー列へ落とし、**専用の同期評価器**
  （512²、1 タイル）で `ExecuteImmediate` → `MaterialEvaluator::ReadbackHeight` で CPU へ。
  GPU 待機を伴うので**フレームの外**（`ProcessPendingPathRoutes`、`ProcessPendingFileWork` の直後）。
- 実寸はチェーンの根の Heightmap（`FindChainScale`）。無ければプレビュー設定の値。
- 焼いた地形は `HashStackHeightState`（レイヤーの Height に効く状態 + マスクの op のハッシュ）で
  使い回す。Path ノードを編集している間だけ、グラフの改版ごとに 1 回確かめる
  （パスの編集でも改版は進むが、ハッシュが同じなら焼かない）。
- 512² は 1 km の地形で 1 セル 2 m。プレビューの CPU ハイトと同じ粗さ。

### 再計算の規則（`RecomputePathRoutes`）

| きっかけ | 対象 |
| --- | --- |
| 点のドラッグを離した | 古いエッジ（両端が動いたもの） |
| 挿入 / 合体 / 分離 / 切り離し / 削除の繋ぎ直し / 反転（流れ） | 古いエッジ |
| 鎖の `経路探索` / `許容勾配` を変えた | その鎖のエッジ（未計算に戻してから） |
| `この鎖を再計算` | その鎖のエッジ全部（古くなくても） |
| `経路をすべて再計算` | 経路探索が有効なエッジ全部（古くなくても） |

- ドラッグ中は計算しない（毎フレーム探索しない）。古いので直線で見える。
- 地形の写しがまだ無ければ（起動直後、Base を繋いだ直後）要求を先送りにし、
  次のフレームの前に焼いてから計算する（`m_pathRouteRequest`）。
- `route` が `なし` のエッジに内部点が残っていれば捨てる。

### 編集操作との相互作用

- **挿入**（Ctrl + エッジのクリック）: t は制御点の折れ線の道のり。内部点はそこで前後に分け、
  両側とも計算済みのまま（両端の記録も更新する）。経路が古かったなら両側とも未計算。
- **反転**: 道路の経路は向きに依らないので内部点を逆順にして使い回す。
  流れは「下る向き」が変わるので未計算に戻す（次の編集 / ボタンで作り直される）。
- **合体 / 切り離し / 削除の繋ぎ直し**: 両端が変わるので古くなり、そのフレームで作り直す。
- 経路探索の設定は、点を挿入して割ったエッジが引き継ぐ。新しく伸ばしたエッジは `なし`。

### 探索の中身（`FindPathRoute`）

- 格子はハイトの解像度そのまま（512²）。両端の外接矩形に、両端の距離の 3/4（最低 40 セル）の
  余白を足した**箱**の中だけを探す（全面を見ると無意味な大回りをするし、遅い）。
- **36 方向**（3 セル以内の既約な向き）。8 方向だと 45° 刻みの階段になって、斜面を斜めに
  登る線形が作れない。(3, 1) なら勾配は直登の 1/√10。
- **曲がりのペナルティ**（(1 − cos θ) × 定数 m）。これが無いと、勾配を守るために 1 歩ごとに
  左右へ振る細かいジグザグになり、間引くと直登と同じ線に戻る。前の 1 歩の向きだけを見る
  近似（向きを状態に持たない。持つとセルごとの状態が 36 倍になる）。
- A*（ヒューリスティックは直線距離。コストは常に長さ以上なので許容的）。
- 結果は Douglas–Peucker で間引く。許容差は幅の 1/4（最低でもセル 1.5 個）。
  両端はセルの中心ではなく点の位置そのもの。

内部定数（`PathRoute.cpp`。欲しくなったらプロパティに出す）:

| 定数 | 値 | 意味 |
| --- | --- | --- |
| `kRoadExcessWeight` | 8 | 道路: 超過² に掛ける |
| `kFlowUphillWeight` / `kFlowUphillScale` | 4 / 5% | 流れ: (上り勾配 / 5%)² に掛ける |
| `kFlowValleyWeight` | 2 | 流れ: 箱の中の相対高さ（0〜1）に掛ける |
| `kRoadTurnMeters` / `kFlowTurnMeters` | 30 m / 10 m | 曲がりのペナルティ |
| `kBoxMarginRatio` / `kBoxMarginMinCells` | 0.75 / 40 | 探索の箱の余白 |

一様 19.5% の斜面で、許容 10% → つづら折れ 713 m（最大 12.3%）、5% → 1291 m の大回り、
30% → 直線。谷では谷底へ降りてから下る。1 本 15〜70 ms（Release）。

### 既知の制約

- 曲がりのペナルティが近似なので**つづら折れの脚が短め**。ペナルティを強めると
  （60〜100 m）勾配の守りが崩れた（16〜18%）ので 30 m にしている。長い脚が欲しければ
  向きを状態に持つ探索が要る（重い）。
- 許容勾配は少し超えることがある（ペナルティであって制約ではない）。
- Debug ビルドでは 1 本あたり数百 ms かかることがある。
- 上流を変えた後の「古いかも」は表示しない（両端が動いていなければ古いと判定しない）。
  地形を変えたら再計算のボタンを押す、が運用。

## 評価（Mask Path）

`EmitMaskOps` が Path 入力の上流から `BuildPathSegments`（鎖 → 制御点 → 12 分割の線分列、
孤立点 → 長さ 0 の線分）を op へ写す。線分は 256 本ずつ定数バッファで流し、2 回目以降は
前の結果と max を取る。ハッシュには線分列の中身を混ぜる（内部点が変わっても焼き直す）。
Mask Path は向きと高さを使わず、幅 / フェザー / 強さだけを読む。

## ファイル形式

`path` の `edges[]` は `{ id, from, to, curve, rounding, clothoidRatio, route, maxGrade,
routedFrom, routedTo, waypoints }`。`route` が `none` なら経路探索のキーは書かない。
`routedFrom` / `routedTo` が揃っていなければ未計算として読む（内部点は捨てる）。
詳細は [reference/file-format.md](../reference/file-format.md)。版は上げていない。
