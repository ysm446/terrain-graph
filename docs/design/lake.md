# Lake — 湖の生成

作成日時: 2026-09-10 17:46
更新日時: 2026-10-04 22:42

## 入出力と設定

`CompositeLake.hlsl` / `MaterialEvaluator::ApplyLake()` で、
地形の窪みに水を溜めて湖を生成する。

| ピン | 内容 |
| --- | --- |
| Base | 入力地形。未接続なら既存の加工ノードと同じ中立平面 |
| Water Mask | 任意の給水マスク。未接続なら全面に給水。水の移動範囲は制限しない |
| Result | 元の地形を湖の水面まで持ち上げたマテリアル |
| Lake | 水深が 0.001 m を超える場所を 1 とするマスク |
| Depth | 0.001 m を引いて 0 以上にした水深（m） |
| Water Level | 湖の水位を周囲へ延長したフィールド。既存 Height と同じ正規化基準 |

水量は既定 5 m、最適化段数は 3、境界からの流出は無効、基準スケールは 1 m。
Water Mask の接続で給水範囲を指定し、独立した 3 本の出力から湖の範囲・水深・水位を取得する。

色・粗さは Lake 自身では変更しない。Result の後ろの Surface に Lake マスクを接続し、
BaseColor / Surface チャンネルを指定すれば、水面へマテリアルを割り当てられる。
Depth は 1 を超え得るため、被覆として使うときは Mask Levels などで調整する。

## 計算

1. セル幅と基準スケールから 2 の累乗の縮小率を求める。
   `shift = floor(log2(reference / cellWidth)) + optimizationSteps`。
   `shift` を 0〜`floor(log2(resolution))` に制限し、元解像度以上への拡大を避ける。
2. 地形を点サンプルで縮小し、給水深を独立した状態として置く。
   8 近傍の高さ差、斜めの `1.4142`、移動係数 `0.17`、
   水深による移動量の制限、境界からの流出を計算する。反復回数は低解像度の 2 倍。
   初期の輸送用高さには給水深を足さない。
3. 給水後の深さを線形補間で元解像度へ戻し、元地形へ加える。
4. 粗い間隔と細かい間隔で近傍最小値を伝播する。
   地形以下には下げない。粗い間隔で低解像度の 2 倍、1 セル間隔で縮小倍率分反復する。
5. 軸ごとの距離伝播で水位を周囲へ延長する。
   近傍の水位も前段のバッファから読み、並行書き込みによる順序依存を避ける。
   未到達の距離には十分大きな値を使い、
   伝播間隔が地形解像度に達した時点で終了する。
6. 0.001 m を差し引いて湖の境界を決め、Height と法線を更新する。

計算は SM 6.6 の GPU compute。状態は ping-pong の RGBA32F、最終出力も RGBA32F。
パス間は明示的な UAV バリアを置き、Height の SRV / UAV 遷移を行う。
リソースの作り直しと終了時の破棄は `Device::DeferRelease()` を使う。
反復中の定数バッファは 2 状態で再利用し、フレームリングの消費を抑える。

## 範囲を湖面にする（2026-10-04）

実測のハイトマップ（DEM）の湖は、水面の高さの平面として入っている。窪みが無いので、水を溜める計算では
湖にならない。先に Shape で掘ってから溜めても、溜めた水は「一番低い水面」へ平らになるので、川が掘った
河床の高さまで水位が下がり、岸が数 m の崖になる（ルンゲルン湖で確認）。

`範囲を湖面にする`（`LakeSettings::areaMode`）を入れると、輸送と平坦化をせず、次の 3 段で湖を置く。

1. `CsAreaSum`: Water Mask が 0.001 を超える画素に（地面の高さ m, 1）を置く。
2. `CsAreaReduce`: 2×2 を足して半分の大きさへ。1 画素になるまで繰り返す（4096 で 12 回）。
   1 画素に残った「高さの合計 / 画素数」が水位。
3. `CsAreaApply`: `湖底 = min(地面, 水位 − マスク × 最大水深)`、`水深 = max(0, 水位 − 湖底)`。
   マスクが 0 の所には水を張らない。範囲の中でも水位より高い地面は陸のまま残る。

その後の水位の延長（`CsLevelInit` 〜 `CsFinish`）と 3 つの Mask 出力は共通。`CsResolve` は、
水のある所の Height を「地面 + 水深」ではなく水位そのものへ置き換える（湖底を掘っているため）。

- 水位を平均にした理由: 侵食・土・堆積の層を経た湖面は数 m 波打つ。最小にすると岸が崖になり、
  最大にすると岸の外へあふれようとして範囲の縁に段ができる。平均なら岸の高さとほぼ揃う。
- Water Mask は「範囲」と「深さの割合」を兼ねる。汀線を正確にしたいときは、範囲のマスク（汀線で切る）と
  深さのマスク（ぼかしから作る）を乗算して繋ぐ。ぼかしだけから作ると、入り江で汀線が陸へはみ出す。
- 合成解像度は 2 の累乗を前提にしている（2×2 の畳み込みが割り切れること）。
- 湖が複数あるとき、水位は全部の範囲の平均 1 つになる。高さの違う湖は Lake を分ける。

検証: Debug / Release ビルド（警告 0）、CTest 6 件（Lake の接続テストに設定の受け渡しを追加）、起動時の DXC。
ルンゲルン湖のシーン（`data/Scenes/lungern`）で、水面が岸の高さに揃うこと、範囲の外（湖より低い北の谷）に
水が出ないことを撮影で確認（`data/Test/lungern-qa/k3_shore.png`、`k4_*.png`）。水を溜める既存の Lake
（`data/Test/sea/river_lake.tgscene`）が今までどおり描かれることも確認。プロパティの見た目
（`--screenshot-ui`）は未確認。

## キャッシュと保存

保存名は `lake`。既存の enum 値を変えず末尾へ追加する。
4 設定を保存し、入力地形・給水マスク・各設定の変更で再評価する。
各マスクは該当 Lake の評価直後に焼き、後段の別 Lake と共有作業テクスチャを混同しない。
ノードを無効にした場合は地形を通過させ、3 種類のマスクは 0 にする。

## 検証と制限

Debug / Release ビルド、既存テストと Lake の接続・出力テスト、9 エントリポイントの DXC コンパイルを実施。
Debug の GPU 検証を有効にした起動と Release の `--screenshot-ui` で描画・プロパティを確認。
検証データと画像は `data/lake-port/`、更新した Release は `build/lake/Release/`。

2048×2048 の EXR 書き出しを計算式の CPU 参照実装と比較し、
最大高さ誤差は約 0.000018 m。水量 0・黒の給水マスク・無効化は元地形と画素一致した。
流出ありでは残水量が減り、水量 5→10 m では被覆が増えることを確認。
設定・全ピンの保存、および保存後の再読み込みで Height が画素一致することも確認した。

輸送と平坦化は有限回の反復であり、厳密な体積保存や完全な水平面を保証するソルバーではない。
最適化段数・基準スケールは結果にも影響する。高解像度で縮小しない設定は計算量が大きくなる。
