# goals — プロジェクトの目的と完成形

作成日時: 2026-08-31 05:46
更新日時: 2026-09-02 12:11

## 目的

ハイトマップとマスクを**ノードグラフ**で生成・加工し、PBR テクスチャと組み合わせて
マテリアルと地形をオーサリングするデスクトップアプリケーションを自作する。

material-mixer（Quixel Mixer 相当のレイヤー合成ツール）からのフォーク。
レイヤースタック方式を廃止し、合成の組み立てをノードグラフへ置き換える。
ノードグラフの仕組みは既存プロジェクト terrain-editor（`D:/GitHub/terrain-editor`）から移植する。

## 完成形

1. ノードグラフ方式の合成
   - ハイトマップとマスクを中心のデータとして扱い、
     生成（ノイズ / パターン / 画像）→ 加工（フィルタ / 演算）→ 合成の流れを
     ノードの接続で組み立てる。
   - マテリアル出力は PBR チャンネルセット
     （BaseColor / Normal / Roughness / Metalness / Height / AO）。
   - 単純なアルファ合成ではなく、**ハイトベースブレンド**を中核に据える
     （岩の隙間に砂が溜まるような、高さ関係に基づく自然な境界）。
   - マスクはプロシージャル生成（ノイズ / 傾斜 / 高度 / 曲率 / AO）とペイントの両方に対応する。

2. リアルタイム PBR プレビュー
   - Cook-Torrance GGX + IBL（irradiance + prefiltered specular + BRDF LUT）。
   - 物理カメラベースの露出（EV100）に対応し、マニュアルと自動露出を切り替えられる。
   - トーンマップを通した、他 DCC / ゲームエンジンと比較可能な見た目。

3. 地形オーサリング
   - ハイトマップのインポートと LOD 付き地形描画。
   - 作成したマテリアルを地形にスプラット適用する。
   - 地形の高度 / 傾斜 / 曲率を、そのままグラフのマスク入力として使えるようにする。

4. 実用的な出力
   - フル解像度でのテクスチャセット書き出し（チャンネルパッキング設定を含む）。
   - 他のエンジンに持ち込んで同じ見た目が再現できること。

## 重視する価値

- **リアルタイム性**: グラフの評価は GPU compute で行い、編集操作に対して即座にプレビューが更新される。
- **物理的な正しさ**: 露出と IBL を物理量ベースで扱い、見た目の基準をぶれさせない。
- **業界標準に合わせる**: できるだけ既存の DCC / レンダラ / ゲームエンジンで通っている
  慣習に従い、独自の解釈を持ち込まない。詳細は下の「業界標準に合わせる」を参照。
- **非破壊編集**: グラフとパラメータは常に編集可能で、評価は毎回そこから再生成される。
- **段階的に動くもの**: 各マイルストーンの終わりに必ず起動して触れる状態を保つ。

## 業界標準に合わせる

外から持ち込んだ素材がそのまま噛み合い、書き出したものが他のツールでそのまま使えることを
優先する。「自分たちにとって自然か」より「**外の世界でそう決まっているか**」を先に調べる。

対象になるのは、たとえば次のようなもの。

- 数値の基準値（ディスプレイスメントの基準面、法線の中立値など）
- マップの向きと符号（タンジェント空間法線の Y の向きなど）
- 色空間の扱い（どのマップを sRGB として読むか）
- チャンネルパックの並び（Megascans の ORD など）
- ファイル形式と拡張子、UI の用語

判断のしかた。

1. まず、その領域で広く通っている慣習を調べる。素材の供給元（Megascans など）が
   どの前提で作っているかを最優先で見る。
2. 標準が割れている場合は、**このプロジェクトが実際に扱う素材の側**に合わせる。
3. 標準に従うと明確に使いにくくなる場合は従わなくてよい。ただし、
   **従わなかった理由を該当する設計文書に必ず書き残す**。黙って独自仕様にしない。
4. 採用した具体的な値や向きは、`docs/design/` の該当文書に根拠付きで記録する。

内部の実装都合で標準から外したくなったときは、たいてい実装の側を直すのが正しい。

## 現在の到達点

material-mixer として M6（レイヤーの種類）まで完了した状態からフォークした。
レイヤー合成とハイトベースブレンド、PBR プレビュー（直接光 + IBL）、
物理カメラの露出、フル解像度エクスポートまでが動いている。
これからレイヤースタックをノードグラフへ置き換える。詳細は [progress.md](progress.md) を参照。

## 当面の非目標

以下は最初から作らない。必要になった時点で改めて検討する。

- メッシュのスカルプト、UV 展開、リトポロジー。
- 高精度なメッシュベイク（ハイポリからのノーマル / AO ベイク）。
- Windows / DirectX 12 以外のプラットフォームおよび API への対応。
- アセットライブラリのオンライン連携、共同編集、クラウド機能。
